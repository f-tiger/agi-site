# 网站视觉风格设计

设计是主观的，直接替用户选风格的成功率很低。这个技能的核心是**把选择权还给用户，但不让用户做描述题**——用户看图选比用文字描述准确得多，也快得多。

## 两步法

### 第一步：视觉化选型（不要跳过）

**不要问"你想要什么风格"**，用户通常答不上来，或答了"简洁大气"这类无法执行的词。

正确做法：用**站点的真实内容**生成 3–4 套完整预览页，每套是一个自包含 HTML 文件，用户点开就能看到实际效果，然后指一个。

要点：
- **必须用真实内容**，不能用 Lorem ipsum 或占位方块——风格好不好看，在真实文字密度下才判断得出来。
- **各套预览的 HTML 结构保持一致，只换样式**，这样对比的才是风格本身，而不是布局差异。
- 每套预览顶部标注风格名与一句话定位（"像什么"），帮用户建立参照。
- 预览要覆盖页面的关键构件：标题区、主操作、卡片、标签、页脚——只做一个 hero 判断不出整站效果。
- 部署出去给链接，别只截图——交互和滚动手感也是风格的一部分。

### 第二步：规范先行，再写代码

用户选定后，先写 `DESIGN.md`，再改代码。跳过这步会导致后续每次改动都在破坏一致性。

`DESIGN.md` 包含九段：

1. **视觉基调** — 一句话定位、信息密度、给谁看
2. **色彩与角色** — 4–6 个具名 token（含 hex）+ 各自用途；语义色（成功/警告/危险）与品牌强调色分开
3. **字体规则** — 至少两种角色（标题 / 正文 / 数据），字号阶梯，字重与字距
4. **组件样式** — 按钮、输入框、卡片、标签、导航的常态与交互态
5. **布局原则** — 间距阶梯、栅格、留白节奏
6. **深度层次** — 阴影 token 与表面层级
7. **禁忌清单** — 明确写下不许做什么，这比正面规定更能防止走样
8. **响应式** — 断点与各断点下的形态变化
9. **动效** — 用在哪、时长、以及 `prefers-reduced-motion` 的降级

## 落地时必须守住的底线

- **深浅色都要设计**。用 `:root` 定义 token，在 `@media (prefers-color-scheme: dark)` 里只重定义 token，组件一律通过 token 取色。深色不是把浅色反相就完事。
- **中性色要挑，不能用纯灰**。带一点强调色色相的灰读起来是"选过的"，纯 `#888` 读起来是"没选"。
- **别用 CDN 字体**：国内访问不稳定，静默回退比不加载更糟。用系统字体栈，中文优先 `PingFang SC / Microsoft YaHei`，需要个性时用宋体做标题。
- **数字用 `font-variant-numeric: tabular-nums`**，凡是成列的数字都要对齐。
- **一处大胆，其余克制**。把视觉重量押在一个地方（一个强调色、一个特殊构件），周围全部安静下来。四处都想出彩等于四处平庸。

## 要避开的「AI 感」

以下组合已经被生成式工具用滥，看到就会觉得"这是 AI 做的"，除非用户明确要求，否则不要用：

- 米白背景（#F4F1EA 一类）配衬线标题配陶土色强调
- 近黑背景上一抹荧光绿 / 朱红
- 紫到蓝的渐变 hero 配纯白底
- Inter / Space Grotesk 当作"安全牌"
- emoji 当章节标记、全局 `border-radius: 12px`、卡片左侧一条彩色竖条
- 内容全部居中

风格要从**主题自身的世界**里找：做票券生意的站可以用票根和印章，做终端工具的站可以用等宽字体和命令行，做学术的站可以用论文排版。从主题里长出来的设计不会撞脸。
