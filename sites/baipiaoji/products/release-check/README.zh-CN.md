# BPJ ReleaseCheck：发布验收执行工具包 0.1.0

[产品与试点入口](https://baipiaoji.com/studio/release-check) · [English](README.md)

为维护收费应用的小型开发工作室提供可复现的 HTTP 检查与证据报告。
免费 MIT 本地执行器；拟议 **$299／单应用验收服务**当前仅接受申请。
已有编程助手可帮助准备测试、分析失败原因；本工具不调用模型，不是托管的自动 Agent。

## 立即复现一个缺陷

需要 Node.js 22 或更新版本。下载并审阅 `release-check.mjs`，在下载目录执行：

```sh
node release-check.mjs demo --broken --out ./broken-evidence
node release-check.mjs demo --out ./fixed-evidence
```

第一条预期退出码为 1：7 项通过、1 项失败，到期账户仍能使用付费功能。
第二条预期退出码为 0：修复测试应用后，同样的 8 项检查通过。
每次都真实请求本机回环地址上的合成测试应用，生成 `report.json` 和 `report.md`。
没有依赖安装、真实扣款、模型调用或自动上传。这是合成演示，不能当作客户应用测试结果。

覆盖：未登录、未付款、已付款、已经到期的测试账户、跨租户访问、无签名回调、带签名
合成事件、重复回调。最后两项要求重放相同事件，效果计数保持不变。
HTTP 状态和 JSON 断言都符合才通过；漏测标为不完整，网络错误会阻断结论。
这八项不等于真实结账、账期时钟、退款、套餐变更和生产环境已完成验收。

## 接到自己的应用

先由开发者和业务负责人确认授权的隔离测试环境、合成账户、业务规则与固定版本，
再修改 `example-manifest.json`。里面的路由、权限字段和最小事件都是演示协议，
不能直接当作通用 Stripe 适配器。真实测试应使用服务所需的支付测试模式事件结构。

```sh
node release-check.mjs run --manifest ./private-test.json \
  --allow-origin https://your-isolated-test-host \
  --authorized --allow-mutations --out ./private-evidence
```

这条命令只允许明确指定的同一源；远程必须 HTTPS，本机可用回环 HTTP。
`--authorized` 表示操作者有权测试该环境；`--allow-mutations` 允许清单内的 POST。
这些标志不能自动识别生产环境。操作者须确认数据完全隔离、不会触发真实扣款。
不要对生产环境执行。工具不会准备账户、自动清库、过期订阅、操作浏览器或发送消息。

凭据由 `headersEnv` 引用 `RELEASECHECK_*` 环境变量，私下在测试运行环境配置。
不要将实际值放进配置、聊天、代码仓或报告。签名辅助器只实现 Stripe 风格的
HMAC-SHA256 封套，不是完整支付模拟器。每次复测前复原合成数据库，或按确认方案
同时更新原始与重复两项的测试事件 ID。详细配置见英文说明和代码。

报告保留版本、时间、断言指针、状态码、配置和响应指纹，不保存凭据及响应正文。
项目名、指纹仍可能关联项目，分享前检查。私有配置与报告不要放进公共仓库。
已有报告不会被静默覆盖；请为每次运行选新目录。单次最多 12 项顺序请求，
单项 8 秒超时、响应上限 1 MiB，不跟随重定向，不执行任意脚本。

## 给现有编程助手的任务

读取项目规则和授权范围 → 确认付款与权益规则 → 准备合成测试数据 → 适配配置 →
人工核对期望 → 执行 → 根据源码解释失败 → 固定版本复测 → 交付证据与剩余缺口。
不得为了让测试通过而改弱期望；缺失规则必须提问或阻断，不能虚构。
助手本身的模型费用和数据条款按原提供方计算，本工具不代理模型调用。

## 付费交付边界

拟议试点包含确认规则、适配用例、证据、可复现问题与一次固定版本复测；不含修复、
生产操作和持续监控。既有报价范围还包括 Chromium 和支付测试模式的客户特定验收，
本 HTTP 工具包只覆盖其中一层。在真实环境演练、范围、工时、条款和退款安排确认前
不收款。测试通过不能证明没有漏洞，也不能证明能为客户节省多少时间。

退出码：0＝所列必需检查通过；1＝失败、错误或覆盖不完整；2＝输入、权限、凭据或
文件输出有问题。原创实现，未复制第三方项目代码。许可证见 `LICENSE`。
