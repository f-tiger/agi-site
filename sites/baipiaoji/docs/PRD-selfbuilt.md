# PRD：自研能力线——从「算别人的数」到「替用户做事」

调研日期：2026-08-14｜起因：用户指出站上的工具偏向中转第三方，要求探索部分自研

---

## 一、先把现状说准（不美化也不自贬）

「全是中转」这个判断，一半对一半不对。现有 12 个工具其实是两层：

| 层 | 是什么 | 自研程度 |
|---|---|---|
| 判定层 | 订阅体检的六档判定、能不能发的五态商用判定、API 计算器的除法、五个对照板的归一化 | **确实是自研的**——逻辑、口径、拒绝规则全是我们写的，别人没有这批结构化数据也跑不出来 |
| 出口层 | 每个结论最后落到 `/go/<slug>` 出站 | **确实是纯中转**——用户真正要做的事，发生在别人家 |

所以问题不在「有没有自研」，在**自研的部分只产生判断，不产生结果**：
我们能告诉你 ElevenLabs 免费档约 10 分钟、且不可商用，但你要合成语音，
还是得离开这里。**站点在用户的工作流里只出现在决策的那一秒，之后就消失了。**

这才是「中转感」的真实来源，也是要修的东西。

## 二、约束：为什么以前没做

`PRD-own-tools` 第二节写死过一条判断，今天仍然成立：

> 通用 AI 玩具（聊天框/改写器）= 零护城河：任何人接一个 API 就能抄，
> 且本站没有付费 LLM key，跑不起推理。

两个约束里，**第二个今天被打破了**（见下），但**第一个永远不会被打破**。
所以自研的判据不是「有没有用到模型」，而是：

> ### 自研 = 我们的引擎 × 我们的数据。第三方模型只能是零件，不能是产品。

## 三、本轮核实到的三件事（都可执行）

### 1. Workers AI 能绑到 Pages Functions，且有每天 10,000 Neurons 免费额度

- Cloudflare 官方文档明写 Pages Functions 支持 AI binding，代码里就是 `context.env.AI.run(...)`
  （developers.cloudflare.com/pages/functions/bindings/）。
- 免费额度 **10,000 Neurons/天，UTC 00:00 重置**，Workers 免费版与付费版都含
  （developers.cloudflare.com/workers-ai/platform/pricing/）。

**意义**：我们不需要任何第三方 API key 就能跑推理——因为我们本来就跑在 Cloudflare 上。
「没有付费 key」这个挡了三个月的约束，实际上不存在。

**但必须先说风险，且这条比机会更重要**：
- 10,000 Neurons 是**全账号共享池**，不是每模型一份；大模型烧得极快。
- 池子挂在 owner 的账号上。一个公开页面被刷，要么当天所有 AI 功能一起死，要么产生费用。
- 部分模型（如 kimi-k2.6、glm-5.2）**必须绑付费方式**才能调。

→ 所以任何 Workers AI 功能上线前必须先有**额度守门**：D1 计数 + 每 IP 限流 +
超额优雅降级（降级成纯确定性结果，而不是报错）。
说来讽刺：我们要先给自己做一个「免费额度撞墙保护」——这正是全站在讲的事。

### 2. 浏览器里跑真分词器是可行的，且能修掉我们自己的一个诚信瑕疵

**瑕疵在这**：`/llm-api-calculator.html` 现在要用户填「单次平均多少 tokens（输入+输出）」，
默认值 2000。**这是全站唯一一处让用户猜数字的地方**——一个把「不许猜数字」
写进每一页的站，自己的旗舰计算器却建在一个猜出来的输入上。

**可行性已实测**（npm 可达，MIT 许可，可自托管）：

| 词表 | 原始 | gzip 后 |
|---|---|---|
| cl100k_base | 1,058,707 B | **427,437 B** |
| o200k_base | 2,223,080 B | **993,438 B** |

懒加载、只在这一页用，可接受。BPE 合并算法本身几十行，**我们自己写**；
词表是公开常量（像字符编码表），不是服务。全程在用户设备上算，**不中转任何人**。

**必须同时说清的边界**：cl100k/o200k 是 OpenAI 系的分词器。
Claude、Gemini、通义用的是各自不同的分词器，**同一段文本的 token 数并不相同**。
所以这个工具只能报「按 X 分词器算是多少」，并逐模型标注 exact / indicative——
不能拿一个数去冒充所有厂商的口径。这条如果做不到，宁可不做：
在一个以「数字有出处」立身的站上引入一个未标注的近似值，破坏力大于工具的价值。

### 3. 完全不需要模型的自研能力，其实还有一块没做：AI 内容标识

我们已有 `labeling.json`（中国大陆 AI 内容标识义务的结构化数据），但**只讲义务、不帮人履行**。
显式标识（文案）与隐式标识（文件元数据）都可以**完全在浏览器里做**，文件不上传。
全网做中文合规向的极少，而这正好是「我们的数据 × 我们的引擎」。

## 四、结论与排序

| # | 自研能力 | 用不用模型 | 护城河 | 风险 | 建议 |
|---|---|---|---|---|---|
| 1 | **真分词器**：粘贴真实 prompt，算出真实 token 数，再喂给 API 计算器 | 否，纯本地计算 | 修掉我们自己的「唯一一处让用户猜」，且与已核实限额直接咬合 | 分词器口径差异必须逐模型标注 | **先做这个** |
| 2 | **AI 内容标识生成器**：显式标注文案 + 隐式元数据写入，全本地 | 否 | labeling.json × 浏览器能力，中文合规向几乎无人做 | 元数据规范要逐条核实，不能想当然 | 次之 |
| 3 | **额度条款解读器**：粘贴任一厂商条款，抽出「额度/重置/商用」三元组并与我们的记录比对 | 是（Workers AI） | 把我们的核实流水线本身开放出去——这是别人没有的工作流 | 必须先有额度守门；**模型抽取的结果绝不可写进数据集**（机器写事实是禁止的），只能当用户即时结果与我们的核实线索 | 守门做完再做 |
| — | 通用聊天框 / 改写器 / 翻译 | 是 | **零** | 烧 Neurons | **不做** |

## 五、硬规则（写进本 PRD，后续不豁免）

1. **模型产出永不进入数据集**。Workers AI 的任何输出只能是给用户的即时结果，
   或给我们人工核实的线索队列。`limits` 仍然只能由人对着官方页面写入，走 `limits-edit.mjs`。
2. **任何近似值必须标注为近似，并说明它对哪些模型精确、对哪些只是参考**。
3. **Workers AI 功能上线前必须有额度守门与优雅降级**；额度耗尽时页面退回纯确定性能力，
   不得报错、更不得在无声中给出质量更差的答案。
4. **自研不等于自造事实**：分词器算的是「这段文本按 X 分词器有多少 token」，
   这是一个可复现的计算结果，不是对厂商的断言——两者不能混。

## 六、MVP（下一轮执行）

`/tokenizer.html`（中英双语，进 PRD-own-tools 路线图 #12）：
- 粘贴文本 → 实时给出 cl100k / o200k 两套 token 数与字符数
- 逐模型标注：对 GPT 系精确，对 Claude/Gemini/通义**仅供参考**并说明原因
- 一键把结果带进 `/llm-api-calculator.html`，替换掉那个猜出来的 2000
- 验收：词表懒加载不阻塞首屏；离线可用（无任何外部请求）；
  与 `llm-api-calculator` 的联动不引入任何未标注的近似

## 七、2026-08-15 复查：第 2、3 号候选的需求侧核实结果——**都不做**

用户问「是否要再自研一些工具」。把排序表里剩下两个候选的需求侧查了一遍，结论是否定的，
理由如下（比结论更重要）：

### 标识生成器（原排序 #2）：需求被三方吃掉了，判为不做

核实到的三件事：
1. **官方配套平台已存在**：强制性国标《网络安全技术 人工智能生成合成内容标识方法》
   发布时即配套上线了 GCmark 平台（浙大网络空间安全研究中心），提供显式/隐式标识的
   **校验与合规检测**，覆盖文本/图片/音频/视频（icsr.zju.edu.cn 公告）。
2. **义务主体主要是平台不是个人**：《标识办法》的责任结构里，传播平台须核验元数据
   隐式标识并自动补充显著标识（新华网 2025-09-09：「平台将自动检测并补充标注」）——
   个人创作者在抖音/公众号发内容时，平台替他打标。个人自备「元数据写入工具」的
   需求面因此很窄。
3. **检测侧是红海**：AIGC 检测/查重工具已挤满（文察、PaperYY、checkaigc、AIGCTrace 等，
   多数免费）。我们若做生成侧，等于在官方平台 + 平台自动化 + 免费检测工具的夹缝里
   找一个没有付费证据的位置——上一轮对抗调研已核实「标注工具个人不付费、
   中国侧被云厂商吸收成附属功能」，本轮补的证据把「个人自备生成工具」这条也堵上了。

**保留的**：labeling.json 规则数据、get_china_ai_rules MCP 工具、publish-check 页的
义务解释——「讲清义务」仍是我们的差异化；「代为履行」不是。

### 条款解读器（原排序 #3）：维持「守门做完再说」，且加一条前置

Workers AI 额度守门未建（PRD 第五节硬规则 3），此项不动。新增前置：
**先让 watch 与 tokenizer 出现真实使用数据**——当下 calc 事件历史为零、watch 注册为零，
瓶颈明确在分发不在功能。在两个刚上线的自研工具得到需求验证之前继续造第三个，
违反本 PRD 自己的门控规则（deep-research 教训：没有需求侧证据不设计功能）。

### 本轮结论

**不新增自研工具。** 下一个自研动作的触发条件（满足其一）：
- watch 注册数 ≥ 10（转型北极星）→ 做历史时间序列导出（Pro 能力，已有付费证据支撑）
  - **2026-08-16 修正：该条暂时失效，不得据此判断需求。** 度量显示 `/watch.html`
    自上线起真人访问为 **0**（4 次全是爬虫），注册为 0 的原因是**没有人到达过这个页面**，
    不是没有需求。恢复该触发条件的前提：`/watch.html` 先拿到真实到达量
    （建议门槛：真人浏览累计 ≥ 100 且来源域非空）。在此之前它只是一个未曝光的页面。
- tokenizer 的 calc 事件周均 ≥ 50 → 做 PRD 第六节的计算器深度联动
- publish-check 的 CN 标识勾选出现规律性使用 → 重新评估标识生成器（届时以使用数据推翻本节）
