# PRD：游戏赛道 —— 「用 AI 做的游戏，能不能上架」

> 结论先行：**有条件做**，但不做用户最初设想的那个形态。
> 不做「AI 游戏资产目录」（同质化 + 社区敌意），做**发行合规层**：
> 你用的这个 AI 工具，产出能不能进商业游戏、上架要不要声明、怎么声明。
> 这是获客动作，不是变现动作——用户「游戏更容易变现」的前提在本站的
> 商业模型下**不成立**，理由见第四节，必须先纠正再谈路线。

调研日期：2026-08-12｜方法：WebSearch 查真实搜索语与社区原声（英文源为主）+ 站内已核实数据自检

---

## 一、需求侧证据（只列可核实的）

**1. 平台侧已经把「声明」变成硬性流程，而且是结构化的**（对抗性复核后改写：
原稿引的是第三方博客，违反本站「纯第三方口径一律拒绝」的规矩，已回官方页重核）

- **Steam**——出处：Steamworks 合作伙伴文档 Content Survey 页
  （partner.steamgames.com/doc/gettingstarted/contentsurvey，经搜索索引引文核实）。
  官方原文定义两类：**Pre-Generated** 是「随游戏发布、被玩家消费、开发期借助 AI
  工具创建的任何内容」；**Live-Generated** 是「游戏运行时借助 AI 工具创建的内容」。
  披露范围按官方口径覆盖游戏内美术/音效/叙事/本地化，**以及站外营销素材与商店页**。
  官方明确的豁免同样重要：用 AI 写代码、头脑风暴、优化流程，只要产出没有直接进入
  游戏文件，**不需要披露**。执行依据是 Steam 分发协议，发布前审核中 Valve 对 AI
  产出与非 AI 产出**同标准**评估。
  ⚠️ 原稿写的「约 20% 的 Steam 游戏带此声明」出自第三方站点，官方页未见此数——**已删**。
  「2026-01 重写规则」出自行业媒体（gamedeveloper.com），属可信转述但非官方公告，
  写入时须标注来源层级。

- **itch.io**——出处：itch.io 官方 Developer Updates 帖与创作者质量指引
  （itch.io/t/4309690，经搜索索引引文核实）。字段名为 **Generative AI disclosure**：
  勾「是」需进一步选 **Graphics / Sound / Text & Dialog / Code** 四类，页面自动获得
  **AI Generated** 标签；勾「否」得 **No AI** 标签（玩家可反向筛选）。
  官方理由原文：「因生成式 AI 内容的权利归属存在法律模糊，对**所有游戏素材页**
  强制执行披露」。
  **原稿写漏了最硬的一条后果**：含生成式 AI 的素材**即使后期修改过**，未打标签
  将**不再进入浏览页索引**——那是直接断流量，比「要声明」重得多。
  精度更正：素材页是阻断式强制（后台弹窗拦截 + 不索引），游戏页同样有该字段。

- 两家的字段结构（预生成 vs 运行时、按素材类型细分）**天然是结构化数据的形状**。

**2. 免费档做的素材，四成以上不能商用——而这条没人系统地告诉他们**
（对抗性复核后下修：原稿用「全部产出型工具 39 个」当分母算出 49%，
其中 HeyGen / D-ID 是数字人口播、OpusClip 是短视频剪辑、Framer 是建站——
这些产出不进游戏包体。剔除后重算如下，**结论变弱但更准**。）

站内已核实、且确实会被拿来做游戏素材的 **35** 个工具（美术 / 音乐音效配音 /
过场视频 / UI 设计）授权判定分布：

| 判定 | 数量 | 代表 |
|---|---|---|
| 明确可商用 | **8** | Runway、Ideogram、Figma、Canva、Bing 图像创作、Pixlr、TTSMaker、Udio |
| **明确不可商用** | **15（43%）** | Suno、ElevenLabs、Leonardo、Recraft、Pika、Luma、可灵、Vidu、PixVerse、Krea、Playground、Fish Audio、Haiper、remove.bg、稿定 |
| 有条件 / 取决于所用模型 | 5 | |
| 官方未说明 | 6 | |
| 已停服 | 1 | |

**比 43% 这个比例更要命的是构成**：被禁的这批恰恰是开发者最先想到的默认选择——
做音乐想到 Suno、做配音想到 ElevenLabs、做美术想到 Leonardo 和 Recraft、
做过场想到 Pika 和 Luma。**踩中的概率远高于 43%，因为选择不是均匀分布的。**

**表述更正（重要）**：不是「不能上架」，而是「**免费档产出不能商用**」——
付费档通常是给商用权的。所以正确的行动是二选一：**升到给商用权的那一档，
或者换一个免费档就给权的工具**。原稿把这话说过头了，已改。

**3. 成本压力真实存在，所以他们不会不用 AI**
社区口径：委托画师约 **$100–300/张**，一款游戏的美术开销可达 **$2 万–6 万**；
发免费游戏的多为单人开发者，没有这个预算。**需求不会因为争议而消失，只会转入水下。**

**4. 但社区对「AI 美术」有强烈反弹（这条决定我们怎么站位）**
itch.io 社区有「Ban AI generated game assets」的公开诉求；主流批评是
「AI 美术对多数消费者是劝退项」「贬低画师劳动」。
→ 因此**不能**做「AI 出图工厂」式的推荐站，那是站到火线上去。
→ 而做**核实与合规层**恰好两边都服务：用 AI 的人需要知道能不能发，
反对的人需要能筛掉——itch.io 的 No AI 标签正是后者的产物。

## 二、用户洞察

**谁**：英文侧独立/单人游戏开发者与小团队（与本站已证实的 94% 英文流量、
coding 页集中的人群高度重叠，不是另起炉灶换一批人）。

**在什么场景**：不是「逛工具」，是**准备上架的那一刻**——填 Steam Content Survey、
打 itch.io 标签、被商店打回、或者上架后被玩家质疑。这是有钱押在上面的时刻。

**卡在哪**：三个问题连在一起，而现有供给把它们拆散了——
1. 我用的这个工具，免费档产出**能不能进商业游戏**？（授权）
2. 上架**要不要声明**、按哪一类声明？（平台义务）
3. 如果不能用，**换哪个能用**？（替代）

**现有供给为什么没解决**：
- 法律博客答第 2 题，但不告诉你手上那个具体工具的条款；
- 工具榜单答第 3 题，但从不查授权，只写「好用」；
- 厂商自己的条款分散在十几个页面，且**改了不发公告**；
- 没有任何一方把「工具 × 授权 × 平台义务」这三层拼在一起——
  而这三层拼起来才是一个可执行的答案。

**能赢的细分赛道**：**「AI 做的游戏上架合规」**——不是游戏工具目录，
是发行前的最后一道检查。本站的三块既有资产恰好拼成它：
`licence.json`（39 条逐条核实的厂商条款判定）+ 中国大陆标识义务那套
「平台义务是与厂商条款相互独立的第二道门」的方法论 + 每日巡检的变更日志。

## 二·五、已有供给与自我攻击（对抗性检查产出）

### 我们不是第一个——这条必须先认

搜索显示已有一批内容在打同一个问题，且质量不低：
- **terms.law** 有逐厂商的「AI 输出权利」页（如 ElevenLabs Commercial Rights &
  Voice Output Ownership）
- **licenseorg.com**：《AI Music Licensing in 2026: Can You Actually Sell What
  Suno and ElevenLabs Create?》
- **promise.legal**：《AI-Generated Game Assets: Copyright & Ownership Risks》
——多为律所/法律服务方的内容营销（终点是「找我们咨询」）。

**它们强在**：法律深度、权威背书、能谈诉讼与判例。
**它们弱在**（也正是我们的位置）：
1. 逐篇散文，**不可比较**——读者无法一眼看出「我这五个工具里哪几个有问题」；
2. **不带核实日期**，而厂商改条款不发公告，法律博客不会每天回去看；
3. 只答「能不能」，**不答「不能的话换谁」**——而换谁才是开发者当下要的动作；
4. 与**平台披露义务**脱节（授权是一道门，Steam/itch.io 的声明是另一道门）；
5. **不可被 agent 调用**——我们有 MCP 与结构化数据，这一层它们完全空白。

**反过来说，这批供给的存在本身就是需求的证据**：没人会为零搜索量的问题
持续产出 SEO 内容。这一条部分回答了「需求是不是真的」——我手上没有关键词
工具查不到搜索量，但供给密度是可观察的代理指标。

### 自我攻击：这是不是 publish-check 换了张游戏皮？

**诚实回答：大约六成是。** 「这个工具的产出能不能商用」这一问，
现有的 /publish-check.html 已经在答，且答的是同一批 39 条判定。

真正新增的只有三样，**MVP 应当只押这三样**：
1. **平台披露义务**（Steam Content Survey 的两分类、itch.io 的四类标签与不索引后果）
   ——这是 publish-check 完全没有的一层，且与中国大陆标识义务同构，方法论可直接搬。
2. **发行时刻的问题顺序**：能不能用 → 要不要声明 → 不能用换谁。
   publish-check 是「查一个工具」，这里是「过一遍我的整条素材链」。
3. **3D / 游戏专用工具收录为零**——这是内容缺口，不是形态缺口。

**结论**：不新建一个「游戏板块」，而是**在既有数据上做一层薄合成**。
如果做完发现它只是 publish-check 的另一个入口，那就说明前两样没做出差异，
应当合并回去而不是硬撑一个页面。这条写进验收。

## 三、复用率与缺口

**可直接复用（不用新建）**
- 39 条产出型工具的商用判定（含 scope / condition / 核实日期）——**今天就能答第 1 题**
- publish-check 页的判定五态模型与「两道门」叙事框架
- china-labeling 的数据形状（法规 → 义务条目 → 平台落地）可原样套用到 Steam / itch.io
- MCP 的 `check_commercial_use` / `find_free_alternatives` / `get_china_ai_rules` 三个工具
- 变更日志：厂商改授权同样不发公告，这条通道已经建好

**必须新建**
- `data/platform-rules.json`：Steam / itch.io（+ 后续 Epic / App Store / Google Play）
  的 AI 披露要求，按已有 china-labeling 的字段结构写，逐条附官方出处与核实日期
- 产出型工具授权覆盖率从 **56%（39/70）** 补到 90%+——尤其音频与 3D
- **3D / 游戏专用工具目前收录为零**（Meshy / Tripo / Rodin / Scenario / Layer 等一个没有），
  这是硬缺口，按每日扩容配额补

## 四、对「游戏更容易变现」这个前提的纠正（必须先说清）

用户的判断在**做游戏**这件事上成立（内购、广告、买断），
但在**「做一个讲游戏工具的站」**上**不成立**，甚至相反：

| | 游戏向联盟 | 开发者/SaaS 工具联盟 |
|---|---|---|
| 典型佣金 | 极低（Roblox 约 **$0.50/单**） | **20–50% 且多为周期分成** |
| 收入形态 | 一次性 | 12–24 个月甚至终身分成 |
| 复利 | 无 | 一个 $99/月 的工具按 30% 周期分成，24 个月约 $713 |

而游戏开发者真正会付费的那些 AI 工具（出图、配音、3D）**本身就是 SaaS**，
和我们现在列的是同一批经济模型——**所以走游戏方向不会改善变现单价**。

**它改善的是获客，不是变现。** 说得再直白些：本站三级变现门槛
（赞助位←真实流量、计算器 Pro←calc 周均>50、数据授权←真实 agent 流量）
**一项都还没达标，卡点在流量而不在赛道**。游戏方向值得做，是因为它
带来一个高意图、可搜索、英文为主的人群入口，而不是因为它更好卖。
指望换赛道直接换来收入，会再一次跳过证据门槛。

## 五、MVP 范围（对抗性检查后收窄：只押三个真正新增的点）

**一份数据 + 一页薄合成 + 一个 MCP 工具**，全部建立在既有 39 条判定之上，
不新建任何数据管线。

1. **`data/platform-rules.json`**——真正新增的第一样。
   Steam 与 itch.io 两家起步，字段沿用 china-labeling 的结构
   （规则名 / 发布方 / 生效或更新时间 / 义务条目 / **不遵守的后果** / 出处 / 核实日期），
   中英双语。硬要求：**只写官方页写明的**——Steam 取 Steamworks Content Survey 页，
   itch.io 取官方 Developer Updates 帖与创作者质量指引；行业媒体转述可作为
   「变更提示」但不作为字段值，来源层级必须在数据里可分辨。

2. **`/ship-your-game.html`（+ `/en/`）**——真正新增的第二样：**发行时刻的问题顺序**。
   不做成又一张工具对照表（那样就真成了 publish-check 换皮），做成**过一遍素材链**：
   输入「我用了哪几个工具」→ 逐个给出 ①免费档产出能否商用（判定 + 范围 + 出处 +
   核实日期）②若不能，是升档还是换工具（同类里免费档即给商用权的）
   ③按 Steam / itch.io 分别该怎么声明（预生成还是运行时；四类素材勾哪几个）。
   交互复用既有对照板机制，不新造轮子。

3. **MCP 工具 `check_game_shipping`**——把上面三层一次给全。
   符合既定规则（新数据集 = 新问题形状），且是现有 13 个工具里没有的形状：
   其余工具答单点，这个答「我这一整条素材链能不能发」。

**第三样（3D / 游戏专用工具收录）不进 MVP**——那是内容缺口，
走每日扩容配额补（Meshy / Tripo / Rodin / Scenario / Layer 等），
不阻塞本 MVP 上线。

## 六、明确不做

- ❌ 不做「AI 游戏素材推荐榜」——同质化，且直接站到社区争议的火线上
- ❌ 不做「AI 生成游戏」「用 AI 一键做游戏」类内容——无可核实事实，纯流量投机
- ❌ **不追踪诉讼与法律风险**（如 Suno 相关诉讼）——那是律所的活，且每周都在变；
  我们只转述厂商条款与平台规则的**当期文本**，越界就成了法律意见
- ❌ 不碰法律意见——措辞沿用现有免责口径
- ❌ 不为进这个赛道而降低标准：新工具照样只写可确信事实，数字照样必须有官方出处
- ❌ 不因为「游戏更好变现」的假设而上收费——变现仍走三级证据门槛

## 七、验收

- `platform-rules.json` 两家平台逐条附官方出处与核实日期，七道门全零
- `/ship-your-game.html` 中英同权、EN 零中文、真机验证过滤器
- 页面能对**任意一个已收录产出型工具**给出「能不能进商业游戏」的可追溯答案；
  查不到官方条款的如实标注「未核实」，绝不因为要填满表格而猜
- MCP `check_game_shipping` 上线并进 CI 断言；server.json 版本 bump 走 OIDC 重发布
- 上线后按三线度量观察：`/ship-your-game` 的真人出站与订阅、以及该页被 AI 爬虫抓取的频次
- **自我否决条款**：若上线后该页除了「工具能否商用」之外没有产生新的使用
  （即平台声明部分与素材链顺序都没人用），说明它确实只是 publish-check 换皮，
  **合并回 publish-check 并下线该 URL**，不为了保住一个页面而留着它
