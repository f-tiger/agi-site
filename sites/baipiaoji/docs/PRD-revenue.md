# PRD：营收路径 —— 先修分母，再谈收钱

> **一句话结论**：现在所有变现方式的分母都是流量或调用量，而我们**唯一在指数增长的
> 是 AI 爬虫线**（190→690 次/天），它本身不产生一分钱。所以「如何创造营收」的
> 真答案不是选一种收费模式，而是**先把「被抓取」转化成「被访问或被调用」**。
> 在此之前接支付，收到的会是零——不是模式不对，是分母不够。

调研日期：2026-08-12｜本轮不写实现代码

---

## 一、现状（作为约束，不是背景）

| 指标 | 当前值 | 对变现的含义 |
|---|---|---|
| 真人手势事件 | 约 10 次/天（含出站点击 go） | 联盟与赞助的分母 |
| 订阅数 | **0**（subs 表仅 CI 自测行） | 新闻信赞助不成立 |
| 非 curl agent 调用 | **2 次/天** | 数据服务不成立 |
| AI 爬虫抓取 | **约 690 次/天且在涨** | 唯一在增长的，但**零收入** |
| Google 点击 | 21→5→6→1（下滑） | 搜索这条腿在变弱 |
| 三级变现门槛 | **一项未达标** | 按既定规矩不得上收费 |

站内已建好、但一直没启用的资产：
- **`outLink()` 的联盟机制早已就位**（优先使用 `tool.affiliate`），
  但 **0/218 个工具填了这个字段**——基础设施在，钥匙没插。
- `go` 出站点击事件已在计量，即收入的分母已可观测。
- MCP 已上线 13 工具 / 9 资源，且调用会落 D1（可计量 = 可计费的前提）。

## 二、外部调研（可核实的）

**1. 同类站的真实变现结构**（Futurepedia 公开的收益披露与第三方分析）
联盟佣金 + **付费推荐位** + 新闻信赞助（其订阅规模 5 万+）+ 展示广告 + 按注册计费。
关键观察：该站「日益转向 pay-to-be-featured，免费收录会被埋没在数千条之下」。
→ **这正是我们必须拒绝的那条路**，理由见第四节。

**2. 开发者/SaaS 联盟的经济性明显优于游戏等品类**（上一轮调研已确认）
SaaS 与开发者工具联盟普遍 **20–50% 且多为周期分成**（12–24 个月甚至终身），
而游戏向联盟极低（Roblox 约 $0.50/单）。我们列的正是前者。

**3. 付费 MCP 市场：真实存在，但极小**
- Claude Code 市场约 **318 个 MCP 服务器，绝大多数免费**；
  收费的集中在 **$19/月 – $149/月（企业档）**，$5–15 的「休闲付费档」几乎空白。
- 按次付费的 **x402**（未付费调用返回 HTTP 402 + 付款 URI，agent 用 USDC 结算后
  带凭据重试，往返 <2 秒、手续费 <$0.001）基础设施已可用，
  但 2026 年初全网**日成交仅约 $2.8 万、单笔约 $0.20**。
- 主流模式：免费引流层 + 订阅层 + 昂贵工具按次计费的混合结构。
→ 结论：这条路**天花板最高但市场未成熟**，现在建管道、不现在收钱。

**4. 一个我们自己造成的约束：数据已按 CC BY 4.0 开放（含商用）**
任何人可以带署名商用我们的数据。**所以「卖数据」这条路已经被我们自己关上了**，
而且不应该反悔——朝令夕改会摧毁比收入重要得多的东西。
可行的是**开源核心那套打法：数据免费，卖围绕数据的服务**——
新鲜度、SLA、更高频次、自定义订阅源、变更推送。

## 三、洞察：真正的瓶颈不在收费方式

三线度量里，**AI 爬虫线是唯一在指数增长的**，而它 referral 为零——
这正是零点击的预期形态：AI 读了我们的数字，在对话里答完了，人不过来。

所以问题变成：**零点击时代，「被引用」如何变成可计量的东西？**
只有一个形态成立——**agent 主动调用 MCP**。抓取不可计量、不可计费；
调用可计量、可鉴权、可计费。这就是为什么 MCP 不是「又一个分发渠道」，
而是**零点击时代唯一的收入接口**。

因此排序如下：
1. **把爬取转化为调用**（当前唯一在增长的东西 → 唯一可计费的形态）
2. **把点击转化为佣金**（分母虽小，但机制已建好、边际成本为零）
3. **把访问转化为订阅**（订阅是赞助与新闻信的前提，且是唯一自有的触达通道）

## 四、必须拒绝的路径（写进硬规则）

以下每一条都能换来更快的收入，也都会摧毁本站唯一的护城河——
**「每个数字都有官方出处、且不受任何人付费影响」**：

- ❌ **付费收录 / 付费加急核实**：收录与否只由「是否确有免费额度」决定
- ❌ **付费推荐位 / 付费排序**（Futurepedia 正在走的路）：
  排序能买，核实就一文不值
- ❌ **付费徽章**：厂商掏钱换「已核实」标记 = 把核实变成生意，最恶劣的一种
- ❌ **联盟关系影响判定或排序**：判定只随官方条款走，与是否有佣金无关
- ❌ **隐藏联盟关系**：任何带佣金的出站链接必须在页面显著位置披露
- ❌ **在三级门槛未达标时上收费**：既定规矩，不因为想赚钱而绕过自己的证据门槛

**护栏建议（可落到门禁）**：`affiliate` 字段的存在**不得**进入任何排序、
推荐、判定逻辑；构建时可加一道断言——带联盟链接的工具在各榜单中的位置分布
与不带的无系统性差异。

## 五、实现方案（三阶段，按触发条件推进）

### 阶段 0：现在就能做，且边际成本为零

**0.1 启用联盟机制（需 owner 注册账号，我方负责其余全部）**
- 我方可做：整理站内已收录工具中**公开提供联盟计划**的名单（按类目排优先级：
  API / coding / video 三类点击最多）、给出注册入口、接好 `affiliate` 字段、
  加统一披露文案（中英）与门禁断言。
- **owner 必须做**：用自己的身份注册联盟账号并把链接给我（我不能代注册）。
- **诚实的量级预期**：以当前约 10 次/天出站点击计，即便按行业常见的分成结构，
  月收入**量级在个位数美元**。做它的理由不是钱，是：机制零成本、佣金随流量线性增长、
  且**现在接好，将来流量涨了不用回头改**。

**0.2 把「分母」当成本轮真正的营收工作**
出站点击 = 联盟收入的分母，MCP 调用 = 数据服务的分母。
所以本阶段最有价值的动作其实是**提高这两个分母**：
- 让 AI 引用时更容易带出可点击的落点（llms.txt / MCP 描述里的 attribution 要求已就位）
- 把 MCP 的存在推到 agent 生态的每个发现入口（Registry 已收录；
  社区目录待 owner 提交——**这是目前投入产出比最高的一步**）

**0.3 零冲突的小额通道（owner 动作）**
GitHub Sponsors / 赞助链接挂在镜像仓库与开发者页。量小，但与独立性零冲突。

### 阶段 1：订阅通道打通后（当前最大卡点）

**触发条件**：邮件服务商密钥就位（Resend / SES / Mailgun 任一，**owner 动作**）。
这是目前唯一「确定有人要、我们却给不出」的东西——已有真人点过「关注额度变化」。

打通后可做：
- 额度变更提醒邮件（唯一自有触达通道，也是回访机制）
- 订阅规模达到可谈的量级后，**明确标注的**新闻信赞助
  （赞助只买位置与文案，不买判定、不买排序）

### 阶段 2：agent 调用达标后（天花板最高）

**触发条件**：非 curl 的真实 agent 调用达到可持续的日均量级（现为 2 次/天）。

形态（数据仍 CC BY 4.0 免费，卖的是服务）：
- **免费层**：现状不变——这是分发，不能动
- **付费层**候选：更高频次配额、变更 webhook 推送、自定义订阅源
  （按类目/按工具的定制切片）、SLA 与技术支持
- **按次付费**：x402 已具备可用基础设施，但全网日成交仅约 $2.8 万——
  **列为可选实验，不作为主路径**
- 定价参照：市场收费档集中在 $19–149/月，$5–15 档几乎空白

## 六、验收与度量

- 阶段 0 验收：联盟名单产出、披露文案上线、门禁断言就位；
  **`go` 事件的日均值**成为本站首个正式的营收先行指标
- 阶段 1 验收：订阅链路真实发出第一封提醒邮件（非 CI 自测）
- 阶段 2 验收：非 curl agent 调用连续 7 天日均 > 0，且能按 UA 区分来源
- **每一阶段的收费动作都必须先过三级证据门槛**——本 PRD 不豁免任何一条

## 七、诚实的总结

以现在的流量，**没有任何一种变现方式能产生有意义的收入**，
差别只在于「几乎为零」和「精确为零」。
所以本轮给出的方案把重心放在**修分母**而不是**装收银台**：
把机制接好（边际成本为零、将来不用返工），把 MCP 推到发现入口
（唯一在增长的那条线的唯一变现出口），把邮件通道打通
（唯一自有的触达方式）。收钱这件事，等门槛达标再谈——
这不是保守，这是不想用一次性的收入换掉唯一让人愿意引用我们的理由。
