# PRD：AI 短剧真相中心——品类流水线的第一次完整落地

> 来源调研：`docs/research-ai-short-drama.md` ｜ 撰写：2026-08-15 ｜ 状态：待 owner 确认后实施
> Owner 验收标准：体系化、可售卖、有复利——本 PRD 按此设计，不是又一个单点板块

---

## 一、定位

**一句话**：AI 短剧赛道所有人都在卖"能赚钱"，我们提供"规则、成本、真相"的可信对照——并把"规则一变就通知你"做成第一个可售卖物。

服务对象不是看短剧的人（C 端发现在平台 feed 内部，没有我们的位置），而是**想靠 AI 短剧赚钱/接单/求职的人**——本站四层阶梯的原生人群。

## 二、为什么是这一格（调研结论摘要）

1. 规则月度级变动且钱直接挂在规则上（抖音砍分成 33%、红果 0 保底、腾讯 100 万扶持——三件事发生在同两个月内）
2. 现有供给全是无出处二手转述，数字互相打架、无生效日期——**结构性缺位**
3. 决策类页面是零点击时代唯一保流量的页面类型（前轮调研已确认）
4. "标出处+定期巡检+变更留痕"是本站 limits 线的既有纪律，同构复用
5. 这个品类骗局密度是我们调研过的所有品类之最 → 审计线（PRD-method-audit）的最佳首发弹药

## 三、MVP 范围（三类资产 + 一个售卖钩子）

### 3.1 规则对照表（数据资产）

`data/drama-rules.json`，复用 limits 的字段纪律（source / checked / effective_date 必填）：

```
{
  "platform": "hongguo",
  "track": "ai-manju",            // ai-manju | ai-realistic | script | overseas
  "rule": "万播分账单价",
  "value": "5-10 元/万播",
  "effective": "2026-05",
  "source": "https://...",        // 原始出处，拒绝二手汇总
  "checked": "2026-08-15",
  "prev": "30-100 元/万播（2025）", // 变更留痕
  "note": "红果否认全面取消保底，但有从业者收到 0 保底通知"
}
```

首批覆盖：红果（漫剧分账/剧本分账/保底）、抖音（分成系数、AI 大赛）、快手（星芒）、腾讯视频（星火计划）、TikTok（企业主体门槛）、ReelShort/DramaWave（剧本收购价、比赛条款）。全部数字以本轮调研已核实的 24 条断言为底。
**写入走 `scripts/limits-edit.mjs` 同款护栏**（新增 drama-rules 支持或复制该脚本模式）。

### 3.3 接单作业（执行资产）

`data/hustles.json` 新增 `ai-drama-jiedan`：免费三件套工具链（全部用站内已收录工具：豆包/即梦/可灵/剪映/PixVerse/Flow）、第一周做什么（作品集 3 条）、真实行情与报价参照、**合规标识步骤**（2025-09 强制标识办法，所有教程都不教，我们教）、reality 与 traps 按站规写满。

### 3.4 售卖钩子（产品层第一步）

规则对照页与审计页挂**"规则变了通知我"订阅入口**——与 PRD-revenue 阶段 1 的邮件通道是同一基建（额度变更提醒的品类扩展）。免费订阅先跑，付费档（更高频、按平台定制推送）等 PRD-revenue 三级门槛达标后开，**不豁免既定门槛**。

### 3.5 页面

`/drama/` 品类页：规则对照表（可按平台筛）+ 审计入口 + 作业入口 + 订阅框。中文根路径 + `/en/`（出海侧规则表英文版——ReelShort 剧本收购价等信息对英文用户同样缺供给）。llms.txt / MCP resources 同步暴露（attribution 沿用）。

## 四、不做什么

- ❌ 爆款推荐/榜单（打不过 DataEye 与平台 feed，且是在替被弃剧的品类背书）
- ❌ 自己下场做短剧制作或接单代工（制作占成本 7.5%，瓶颈在投流；那是打工不是复利）
- ❌ 短剧内容聚合/剧情库（版权硬伤，0.85 元盗版素材包的世界我们不进）
- ❌ 卖课、卖"包接单"、承诺任何收入数字
- ❌ 首期不做 C 端短剧评分/评论社区（冷启动双边，且与"给想赚钱的人"的定位不符）

## 五、复利机制（体系化的部分）

本 PRD 同时定义**品类流水线模板**，AI 短剧是第一次实例化：

```
选品类（热点+骗局密度+规则复杂度三高） → workflow 调研+对抗核实
  → drama-rules 式规则表 + audits + hustle → 订阅提醒 → 下一个品类复用全部基建
```

流水线本身沉淀为：调研 workflow 脚本（已有，本轮的 `ai-short-drama-research` 可参数化）、规则表 schema、审计 schema、订阅通道。**每复制一次，新增品类的边际成本递减，订阅列表跨品类累积——这是复利的具体机制，不是口号。**

## 六、验收

1. `data/drama-rules.json` ≥ 20 条规则，每条 source/effective/checked 齐全，写入护栏就位
2. audits 新增 4 篇、hustle 新增 1 篇，"失败原因+骗局图鉴"硬断言通过
3. `/drama/` 上线，构建四项全零
4. 订阅入口就位（邮件通道打通前先落库，通道打通后自动激活）
5. 观测指标：/drama/ 的搜索展示与点击、AI 爬虫抓取占比、订阅转化数——**订阅数是本 PRD 的北极星**（它同时是 PRD-revenue 阶段 1 的分母）
