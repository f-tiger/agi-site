# PRD：订阅该变成什么（2026-08-16，v2）

回答一个具体问题：**「订阅不好，是不是没有强诉求？那么订阅该变成什么？」**

> **v2 修订说明**：v1 写于对抗核实失败之后（150 个 agent 里 140 个因额度报错，
> 47 条 findings 只有 1 条跑完核实）。重跑后 21/21 全通过，**44 存活 / 4 杀掉 /
> 0 未核实 / 抓出 1 条编造**。核实结果推翻了 v1 的**两处论证、两处事实**，
> 并补上了 v1 缺的最关键一环（选赛道）。本文逐条改过，被推翻的部分保留痕迹。

## 0. 证据分级

| 级别 | 含义 | 可否作为决策依据 |
|---|---|---|
| **A** | 我方一手数据，可复查（D1 / CI 日志 / 构建产物） | 可 |
| **B** | 主控亲自 WebSearch 核实 | 可 |
| **C** | 调研 agent 产出且**通过三视角对抗核实**（本轮 44 条） | 可，标注 kill_votes |
| **D** | 未通过核实或票数不足 | **不可** |

## 1. 「没有强诉求」这个判断成立吗？

**分成两个问题，答案相反。**

### 1.1 自有数据对此没有分辨力（A）

- 表单曝光 39 次、提交 0 次。按 1–3% 常规转化，期望提交数 0.4–1.2，
  **0 与「完全正常」在统计上不可区分**。
- `/watch.html` 真人访问 0 次——watch 表 0 行不需要解释。

**⚠️ v1 的两条论据在本轮被判死，已删除：**

1. ~~「星标点击 3 次 → 表单曝光 3 次，转化 100%，说明按钮位置和触发时机没问题」~~
   **这是偷换指标。** 查证 `scripts/build.mjs:855`：星标按钮变成 `is-on` 后 150ms
   **自动弹出**滑入卡片，`:849` 随即打 `sub_view/slide-star`。
   曝光是点击的机械后果，100% 是代码耦合的恒等式，n=3。它不能证明任何意愿。
2. ~~「Perplexity 那位访客看 4 页、触发表单 9 次未提交，是可解释的信号」~~
   **n=1，且 9 次曝光对 4 个页面说明的是表单在反复弹，不是用户在反复犹豫。**
   站内数据无法区分「拒绝留邮箱」与「从未注意到表单」。降级为观察，不作依据。

### 1.2 站外证据：诉求存在，但触发时机站错了（C）

**（a）「额度到底多少 / 现在还能不能用」——强，且复发。**

- Google 2025-12-06/07 无预告砍 Gemini API 免费额度，未发邮件；开发者是收到
  `429 quota exceeded` 才发现。该事件的 SERP 头部**全部是补救型标题**（kill 0，本轮最强）。
- 编程赛道 14 个月至少 6 次重大改制：Cursor 2025-06 转算力制、Augment 2025-10、
  Windsurf 2026-03 转日/周配额并涨价、Copilot 2026-06-01 转 AI Credits、
  Anthropic 两次临时上调周限额、**DeepSeek 峰谷计价**（kill 0）。

**（b）「变了提前通知我」——搜索层面查不到信号。**

- 整轮检索**没有找到任何一条**「希望有人提前告诉我」的社区原话；
  而「找替代品」遍地都是（Heroku 免费层终止后 4 个 HN 帖 + 3 个仓库全叫 alternatives；
  Cursor 2025-06 改价后整页 SERP 全是 alternatives）（kill 0 / kill 1）。
- 愤怒指向厂商（tag Sundar Pichai、逼 Cursor CEO 道歉），**不转化为对第三方的订阅意愿**（kill 0）。

### 1.3 直接回答

**「没有强诉求」对「预防型订阅」这个形态成立，但依据来自站外供给结构，不是那 39 次曝光。**
对「额度事实本身」明确不成立。差别在时机：**诉求在事后 0 秒被错误码触发，不在事前被担忧触发。
订阅是只有事前才成立的动作，它站错了时间点。**

## 2. 谁、在什么场景、卡在哪

### 人群 A：自付费的个人 / 独立开发者，在用 AI 编程工具（beachhead）

不是「开发者」，是**自己刷卡、无公司报销、同时用 2–4 个工具**的那一档。
（团队采购预算大得多，但要 SSO / 审计 / 合同，我们连账号体系都没有——**团队功能不要提**，kill 0。）

- **场景**：周三下午写着代码，Claude Code 提示周限额用完 / Copilot credit 不足 /
  DeepSeek 今天起峰谷计价。需要在 10 分钟内决定：忍、充钱、还是换一个。
- **卡在哪**：官方不发公告（Gemini、Oracle 都是静默改）；报错只说「超了」，
  **不说新上限是多少**，**也不说现在换谁还有额度**。
- **现有供给为什么不解决**：
  1. 测评/对比文有数字，但**无逐条官方出处、无核实日期、无变更历史**——撞墙时不知道它写的是哪版规则（kill 1）
  2. 429 修复指南的 SERP 头部被 **API 中转商**（aifreeapi / apiyi / yingtu）占住，落点是卖中转
  3. LLM 价格追踪器（BenchLM / LLMRates / TLDL）已很专业，但**只做 per-token 单价，不做订阅套餐配额与免费额度**——这一格空着（kill 1）

### 人群 B：中文侧个人用户 / 学生 / 独立开发者

动词是「平替」「还能白嫖多久」，不是「变了通知我」（kill 0 / kill 1）。
中文供给全是无出处、无日期的攻略——**「已核实 + 官方出处 + 核实日期」在中文侧是真空**。

### 人群 C（机器）：把额度事实硬编码进 pipeline 的脚本 / agent 作者

**诚实标注：这是设计推理，不是核实过的需求。**
「agent 选型时会主动查免费额度」在查不到清单里；`SaSame-MCP-Audit/0.1` 归属方查不到。
唯一硬支撑是先例：litellm 的 `model_prices_and_context_window.json` 被无数系统硬编码（kill 0）。

## 3. 候选形态判定

| 形态 | 需求证据 | 能不能做 | 判定 |
|---|---|---|---|
| **邮件订阅** | **无→负**：预防型订阅搜索层面无供给无需求语（kill 1）；AI newsletter 是 beehiiv 报告中月流失第二高品类（kill 1）；PricingBot 真实版一年 3 客户 $600 MRR 后放弃（B，锚点） | **不能**——无发信通道 | **撤**（v1 写「缓做」，本轮升级）：把表单从**查询路径**上撤下，只留在变更事件页底部作次级动作 |
| **RSS / 变更记录页** | 中偏弱（开发者习惯真实；「72% 开发者用 RSS」出自内容农场，不采信） | **已在跑** | **维持，不给 KPI**。边际成本为零的期权 |
| **webhook 推送** | **无**：市面同类产品无一例外面向 B 端竞对情报（kill 1） | 已上线 | **停止投入**。留代码不留承诺，只在出现**具名消费方**时单独接 |
| **MCP 常驻** | 弱（真实外部调用 8 次/7 天，n≈1 个 UA）；规范自带 `resources/subscribe` 但客户端支持有 gap（kill 0） | 已上线 | **维持 + 一处零成本收口**：把 `get_free_tier_changes` 的 `days` 补成 `since=<date>`，与 HTTP 端点同契约，不让两个出口分叉 |
| **快照 + 增量 diff** | 中（litellm 先例 kill 0；50%+ 爬取在重复抓没变的页 B） | **已经做完大半** | **做，但性质是分发不是构建**（见下） |
| **数据集授权** | **无**（对我们这一档）：长尾站无谈判筹码，Nieman Lab 直接以《Publishers will see no meaningful AI licensing revenue》为题（kill 0） | 声明可做，谈判不可做 | **不立项，但留被动接口**：加一段 RSL 机器可读声明，成本以小时计。v1 把这个近乎免费的期权一起砍掉了 |
| **付费 API / 按次收费** | **无**：x402 日交易 73.1 万 → 5.7 万（-92%），周钱包留存 87%→5%（kill 0）；按引用付费**在 2026 年不存在内容方可独立验证的计量**（kill 0）；个人向监控价格天花板被 changedetection.io $8.99/月 + 32k star 开源版封死（kill 0） | 能做，无买家 | **不做**。只留价目页当定价锚，不写一行计费代码 |

### ⚠️ v1 的两处错误，已改

**错误一（事实）**：v1 §6 指标 2 写「增量 diff 端点（现在：端点不存在）」。
**查证为假**：`dist/limits.json`(150KB)、`dist/changes.json`(**35 条**，
带 `date/slug/kind/fields_changed/checked/page`)、`dist/limits.md`(147KB)、
`data/limits-history.json` **全部已存在**，MCP 侧 `get_free_tier_changes` 已支持 `days`。（A）
**所以「下一个自研动作 = 做 diff」这个安排是错的：东西已经在那了，缺的是契约——
版本号、`since=<date>` 参数、稳定路径承诺、在 `llms.txt` 与页面 `<head>` 里可自动发现。
把它当构建任务，会得到一个「做完了但没人用」的结果。**

**错误二（论证）**：v1 用「Cloudflare 承认按抓取收费不成立」推出「付费 API / 数据集授权不做」。
**这是 non sequitur**：Pay Per Crawl 失败说明的是「按抓取向 AI 公司收租」不成立，
推不出「变更情报卖不出钱」——PricingSaaS 在 B2B 侧就在卖「定价历史 + 变更告警」，
Crayon/Klue 客单价五位数美元（kill 0/1）。**结论对，理由换成上表那三条。**

## 4. 能赢的那一格（v1 完全缺失这一节）

> **赛道：AI 编程工具的「套餐配额与免费额度变更史」——不是「AI 工具」。**
> **形态：双面单源——人这面是「撞墙落地页」，机器那面是「带版本的快照 + `since` 增量」。**

**为什么是它：**

1. **变更频率最高，因此「带核实日期」从成本变成资产。** 绘画/写作工具半年不动一次，
   编程赛道 14 个月改制 6 次。在半年不变的赛道里「我们核实过」不值钱；
   在两个月翻一次牌的赛道里，没有核实日期的内容三个月后全是错的。
2. **这一格空着，相邻两格已满。** per-token 单价有三家在拼秒级时效（不进）；
   通用 SaaS 定价追踪全部面向 B 端竞对情报（不是我们的人）。
3. **痛感强到能上主流媒体、逼 CEO 道歉**——事件当口有真实搜索脉冲。
4. **中文侧「带出处 + 带日期」是真空。**

### ⚠️ 必须撤掉的一个隐含前提

v1 隐含「我们核实过 = 差异化」。**推翻**：至少 6 个站在做「带核实日期的免费额度/定价目录」
（FreeTier.co 857 个产品、CostBench、PricePerToken、TokenTab、CostGoat），
机器侧抓取成本已跌到约 $1.20/1000 页（kill 0）。
**「带出处、带日期」是入场券不是护城河。** 护城河只可能是组合：
赛道够窄 + 中文侧真空 + 有变更历史留痕 + 机器可读同源。

## 6. 验收指标（能证伪本 PRD 的三个数）

**① 事件脉冲能不能接住**（测选题 + 时效）
事件页上线后 72 小时内自然搜索到达 **≥ 24 次**（= 全站现有七天到达总量）。
打不过存量 1285 页的一周总和，说明「事件驱动脉冲」这个流量模型不成立。**当前：0。**

**② 赛道能不能承接查询意图**（测人群 + 入口词）
30 天内编程赛道页面**带来源域到达 ≥ 60 次**，且 Search Console 出现
**至少 3 个带错误码/限额语义的查询词**（`429`、`quota exceeded`、`周限额`、`额度用完`）。
只有到达上升而查询词全是工具名，说明只是被更多人翻到，撞墙那一刻并没接住。
**当前：Google 12 次/7 天；查询词未知——这条要求先接 Search Console。**

**③ 机器侧有没有被「写进代码」**（测契约，不测抓取）
30 天内 **≥ 1 次外部代码引用**：GitHub 代码搜索能命中我们的 `limits.json` / `changes.json` URL。
**⚠️ v1 用的「非本站 UA 请求 ≥ 10 次/月」被判定为坏指标**——每日数百次通用 AI 爬虫
能轻易把它刷过线，而这类抓取是 118:1 至近 50,000:1、50%+ 重复的噪声。
**它会在什么都没发生时报成功。** litellm 模式的最小可信信号是**被 vendored，不是被抓**。
**当前：0。**

**负向条件**：三个数都没出现、但抓取次数大涨——那不是成功，
是确认了我们在给爬虫做免费的重复抓取。

## 7. 诚实缺口

1. **所有「社区原声」都是二手的。** HN / Reddit / V2EX / InfoQ 全被本环境 egress 代理 403 阻断，
   每一句带引号的社区表达都来自搜索摘要，不是逐条读到的原文。
2. **没有任何搜索量数字。** 无 Keyword Planner / Trends / Ahrefs。
   **§4 的赛道选择是「结构性判断」而非「规模验证」——我知道这一格空着，不知道它有多大。**
3. **三个关键一手页面被拦截**（aifreeapi / getpricepulse / pecollective），
   Gemini 12 月那组「50–92%」的数字来自搜索摘要。**按站点规矩，写进页面前必须二次核实。**
   「竞品不做 X」这个 PRD 级硬结论目前也建立在搜索摘要上，落地前需人工复核。
4. **编程赛道用户对「监测服务」本身的付费意愿：零证据。** 只查到他们为工具本身付费
   （$20–200/月）。这不影响 §4（§4 不含收费），但**任何往这一格加收费的动作都无依据**。
5. **人群 C 是设计推理不是核实需求。** 「快照 + diff」判为「做」，
   理由是**成本近乎为零（数据已经在）**，不是需求已证实。
6. **最上位的问题仍无答案：为什么只有 3.4 次/天。**
   §6 三个指标里有两个是到达类，能否达成主要取决于收录与分发，
   而不取决于我们把订阅换成了什么。**本轮调研没有推进它一寸。**

**不确定性总评**：人这一侧（编程赛道 + 撞墙落地页 + 替代推荐）证据最厚，
多角度独立指向、含两条 kill_votes 为 0 的条目，**可以按结论执行**。
机器这一侧是单先例推理 + 成本近零，**按期权执行，不给资源优先级、不给抓取类 KPI**。
赛道选择本身证据强度居中：改制频率与空位可核实，市场规模与付费意愿两项都空着——
**它是一个可被 30 天内三个数字证伪的赌，不是一个已被证明的判断。**
