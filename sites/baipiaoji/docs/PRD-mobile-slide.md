# PRD:移动端滑入触发(slide-up)——把已验证的转化器补上移动端信号

一页薄 PRD(2026-08-24),按三门+五步闭环。属舰队 standing goal(owner:「持续升级
4个站点,直到达成订阅与营收」)下的**转化管线工作**,不是新页/新内容面——冻结令
针对的「零新页、零新功能」指内容与产品面;本项只给既有滑入卡补一个触发信号,
产物是零个新 URL、零个新 UI 组件。

## 三门证据

- **数据门**:28 天 D1 实测——`sub_view` 77 次 → `sub_submit` 1 → `sub_ok` 1,
  且那 1 个真实订阅(2026-08-23,本站与全舰队第一个)来源正是 `/slide/exit`。
  滑入卡是全站唯一被验证能转化的部件。而它的 exit 触发挂在
  `matchMedia('(pointer:fine)')` 上——**移动端读者永远没有触发资格**
  (原始决策 2026-08 早期:「移动端没有可靠信号,宁缺」,当时滑入卡尚无任何
  转化证据;现在有了,这个决策值得用一个轻信号重估)。
- **需求门**:真实订阅者的行为路径 = 读完判定页 → 离开动作 → 滑入卡 → 留邮箱。
  移动端读者读同样的会变的数字,离开前的「快速上滑」是移动端最接近同一时刻的
  信号。不做全屏 modal(Google 移动端插页敏感 + 本站规矩),同一张小卡、不挡内容。
- **商业门**:订阅数即 standing goal 的第一指标;bpj subs 直接计入舰队 5/5。

## MVP 范围(全部)

`build.mjs` 内联脚本加触发三:`pointer:coarse` 且深读(滚动深度 ≥60% 页高)后,
600ms 内累计上滑 ≥220px → `slideIn('up')`。全部既有规矩经 `slideOK` 复用:
每会话一次、关闭记 14 天冷却、订过的人永不再见、Esc/× 可关。
测量自动分流:`sub_view` 落 `/sub_view/slide-up`,订阅行 `src='/slide/up'`,
与桌面 exit 完全分开,谁在转化一目了然。

## 不做什么

不做定时弹出、不做全屏、不做 iOS 后退手势劫持;不改桌面 exit 行为;不改文案
(exit 文案「走之前——这页的数字都会变」对上滑场景同样成立)。

## 判定线(2026-09-21,28 天)

- `slide-up` sub_view ≥10 → 触发器活着;其中 ≥1 `sub_ok` → 保留并宣布模式成立,
  移植到 eco/gridlings 的移动端。
- sub_view 为 0 → 触发条件太苛,先查阈值再判死。
- sub_view ≥40 且 0 submit → 该场景不成立,撤触发器(桌面 exit 不动)。
