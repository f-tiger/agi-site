# BPJ 自动付款确认与排期投放

2026-09-19，Owner 明确要求升级付费链路。新指令授权本次改造，历史冻结不阻止执行。

## 问题与证据

线上只读 `/api/ads?doctor=1` 返回 selling=false，四项支付配置均 false。旧代码只消费 checkout.session.completed，缺少异步到账；ads 查询 LIMIT 3 可让其他付费者消失；更新和订单写入不在同一事务，DB 错误可吞成成功；广告 UI 用 f.name 读取表单字段，会与 HTMLFormElement.name 冲突。

需求来自 Owner 的明确交付要求，尚无新买家付款证明。第一方竞品 Futurepedia 证明有目录付费上架报价，不证明 BPJ 的流量/报价成立。沿用现有 EUR49/30天做待验证价格，不提高报价或伪造触达。

## 本次交付

服务端创建 Stripe Checkout（一单一次付款）；金额/币种/时长在下单时冻结；能力令牌哈希查询私有状态；验签到账；D1 batch 事务内安排分类赞助位1–3，满位等待最早空档，完整天数从实际计划开始计。有效时间使用秒和半开区间。测试支付与真实库存隔离，测试广告不公开展示。退款（含部分退款）/争议暂停整个订单，提前到达的逆向事件也阻止后续激活。无重复扣款、自动续费或商家后台会员承诺。

旧广告继续展示，不改目录事实/编辑排序。新单不再发裸钱包转账指令或可篡改 client_reference_id 的通用付款链接；旧 ad-claim 与旧链接回调仍处理历史订单。老合同可能暂时使展示数量超过3，这是存量兼容，不把旧买家的钱白收。

## 验收

真实 SQLite 集成测试：并发四单不重叠、第四单完整排期；跨分类及测试/生产隔离；税额与购买价分开校验；重复/异步/乱序事件、退款、争议、验签轮换、DB故障回滚、服务端定价、订单查询授权。构建与既有静态验证通过；浏览器检查中英桌面/移动端、未开售与结账跳转、付款返回的服务端状态。

生产收款验收仍需账户绑定、测试环境 provider 回调、live小额真实交易与退款。在这些完成前不得说已经收款或已产生营收。付款不是会员；自动续费需独立订阅合同、取消入口、invoice.paid与subscription事件驱动权限，另立实施项。
