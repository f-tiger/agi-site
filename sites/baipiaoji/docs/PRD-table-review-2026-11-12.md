# AI table rewrite review: production pilot

Owner authorization: release the validated prototype and start automatic marketing, 2026-11-12. This is a bounded BPJ tool release, not a change to unrelated fleet experiments.

Audience: people rewriting or translating CSV text while IDs, amounts and quantities must remain unchanged. The repeated paid-workflow hypothesis is review across recurring batches; no interviews, paid retention or savings have been verified. Current checks, repair and export are free. No new subscription, checkout, AI model bill or cloud storage is introduced.

Contract: unique stable IDs, identical column names, explicit editable columns. Match rows by ID and columns by name, restore all other original strings exactly, retain allowed edits. Missing/duplicate/unknown IDs, invalid schema and formula-like output block CSV export. The tool cannot detect IDs swapped within the same ID set, wrong-record content or semantic errors. It does not establish that original facts are true.

Inputs: UTF-8 CSV, 1 MB file / 1,000,000 pasted characters, 2,000 data rows and 60 columns. Output: reviewed CSV, complete JSON change report and optional English/Chinese AI handoff. Only 100 changes per group and 30 preview rows render to bound DOM size. Data stays in memory and browser downloads; no automatic persistence. Pending file reads cannot revive stale approvals.

Acquisition: bilingual studio, homepage tool links, site search, toolkit and feature map; canonical URLs and sitemap; factual machine-readable application/FAQ metadata. No fabricated model benchmark, customer quote, market lead or time-saving percentage. Marketing uses a real English screen recording with labelled synthetic errors and original audio.

Measurement: fixed `table_review` actions import/handoff/check/blocked/preview/report/export, split into demo and declared own inputs. Demo mode persists through edits until cleared and recognizes unchanged built-in sample rows on import. This is classification, not proof of genuine customer identity. File text, names, IDs, amounts and report contents never enter events. DNT/GPC, opt-out and QA exclusions follow the site contract. `table_review_actions` in the existing conversion-stages report is an action count, not a visitor funnel or revenue. GA4 uses the existing isolated analytics frame and registered campaign `bpj-table-review-01`. Existing campaign measurement counts arrivals/active reading; it does not join file events to individual people.

Acceptance: exact-string core regressions; corrupt identities/formulas blocked; real file download; asynchronous import races; English/Chinese and mobile keyboard-labelled controls; literal HTML rendering; bounded telemetry and no content payload; site discovery/canonical/schema/GA4 tests; successful production deployment and live interaction verification before publishing owned-channel promotion.

Operations: one truthful launch asset for existing YouTube/TikTok accounts, zero paid spend. Subsequent marketing checks reuse existing GA4/reach reports; keep publication receipts and dedupe state privately. Never count a scheduled post as published, a click as export, or export as subscription. First completed seven-day review decides whether the problem attracts real own-input completions; no automatic feature expansion or pricing claim from small samples.
