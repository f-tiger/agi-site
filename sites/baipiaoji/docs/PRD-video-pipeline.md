# PRD · 零成本短视频流水线（垂直打透第一条链路）

> owner 2026-08-18 指令：「垂直一个赛道的完整解决方案研究，打破一个赛道，而不是发散后
> 没有焦点，然后再打造一个整体解决方案」。本 PRD 是这条指令的第一次落地：**只打视频这一格**，
> 打透之后再复制到 coding / image。

## 一、为什么是视频（数据门）

赛道不是我拍脑袋选的，是一手数据选的。D1，since 2026-08-05，`ev=''` 且来源域非空的真人到达：

| 落点 | 带来源到达 | 来源 |
|---|---:|---|
| 工具页合计 | 42 | 绝大多数 Google |
| 其中 **视频三家** | **10** | hailuo 4 / haiper 4 / pixverse 2，**全部 Google、全部 EN 侧** |
| coding + API 基建 | 17 | fireworks 7 / fastgpt 3 / cursor 2 / comate 2 / trae 1 / deepinfra 1 / cerebras 1 |
| 通用对话 | 15 | claude 4 / kimi 6 / grok 2 / ms-copilot 2 / hunyuan 1 |

coding 的绝对数更大，但它散在「API 基建」和「IDE 插件」两个不同意图上；
**视频那 10 次高度一致**——三家都是文生视频，全是英文自然搜索，全部落在我们已核实额度的名单里。
更关键的是护城河匹配度：coding 的解决方案内核是 SDD/harness 方法论，
**任何人都能写，与本站「已核实额度」无关**（这句是 PRD-own-tools 早就写下的自我否定）；
而视频流水线的可行性**本身就是一道额度算术题**，只有握着逐家核实数字的人算得出来。

## 二、需求门：真实用户卡在哪

搜索到的用户原声（2026-08 当期）集中在三点，且**都不是「哪个工具好」**：

1. **credits fatigue**——积分制不透明、消耗不可预测，即使出片质量好也被弃用；
   生成失败照样扣积分的投诉成片出现（Adobe 社区多条 bug 报告）。
2. **免费档到底能出几条**——第三方文章给的是模糊区间（「bootstrap $0–25/月 → 3–8 条/月」），
   没有一篇按环节逐条算过账。
3. **卡点在链路而不在单点**——「每个工具各强一点，于是订了一堆，再花 4 小时手工拼」。

现有供给为什么没解决：市面上的计算器（Playcut、freeaivideohub、costgoat 等）**全是付费成本计算器**，
回答的是「每秒多少钱」。**没有一个回答「全免费的情况下，这条流水线一个月能产出多少条」**。

## 三、洞察：产能不取决于最强的一环，取决于最稀缺的一环

一条完整的短视频流水线是五环：**脚本 → 分镜图 → 生视频 → 配音 → 剪辑字幕/配乐**。
每一环都有自己的免费额度墙，**整条链路的月产能 = 各环产能的最小值**。
所以「哪个 AI 视频工具最好」是个错问题；对的问题是「**我的瓶颈在第几环**」。

把已核实数据摊开算，得到一个本站独有、且可被直接引用的结论：

> **13 家视频工具里，只有 Kling 一家同时公布了「每天发多少」和「多少换一条」。**
> 其余要么只给积分不给换算（google-flow 50/天、pixverse 30–60/天、runway 125 一次性），
> 要么只给换算不给总量（hailuo、haiper），要么两个官方数字自相矛盾（vidu 40 与 80 并存）。
> **恰恰是瓶颈那一环，全行业最不让你算。** 配音（ElevenLabs 10,000/月≈10 分钟、
> Fish Audio 8,000/月≈7 分钟、TTSMaker 20,000 字符/周）、配乐（Suno 50/天≈10 首）、
> 图片（即梦 50 张/天、LiblibAI 40 张/天、Ideogram 40 张/周）三环都算得出来。

这就是本站能说、竞品说不出的一句话——因为它不是观点，是把 13 份已核实数据摆在一起才看得见的事实。

## 四、商业门：它把用户推向哪条营收路径

计算器的输出天然是一个**升级决策**：产能不够时只有三条出路——同环换一家（站内跳转）、
降规格（保持 0 元）、**为瓶颈那一环付费**。第三条直接落到已有的 `/upgrade/`「该买哪档」，
而且**只为一环付费**是本站一贯主张（不是让人订一堆）。视频类也是 `/for-vendors.html`
询价探针最可能被触发的类目——厂商最在意的就是「被算出来产能垫底」。

## 六、计算器的诚实规则（新增硬规矩，与 limits 两步走同级）

零新增事实一直包括**不代做算术**（Consensus 的 15−3=12 就是被门禁抓住的先例）。
计算器是唯一的例外，代价是它必须**把算式和来源一起显示**：

- **静态正文只写有来源的原始数字**；任何乘除只发生在计算器运行时。
- 每个派生数字旁必须同时出现**算式**与**来源工具 + 核实日期**。
- 原始数据只能从 `data/*-quotas.json` 读取，**不得在 pipelines.json 里重抄数字**。
- 官方没给换算的，一律标「无法计算」并排除出 min()，**不得用行业均值补**。

## 七、不做什么

- 不做「最好的 AI 视频工具排行」——那是竞品做烂了的东西，且与护城河无关。
- 不写 SDD/harness 式的方法论长文（同样的理由：谁都能写）。
- 不新增视频工具页（本轮零新增工具 URL，只新增 1 个 pipeline URL）。
- 不给任何未公布额度的厂商编一个「大概」。
