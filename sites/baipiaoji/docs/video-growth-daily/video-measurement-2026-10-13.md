三状态可重叠，不能相加得到任务数；没有新增“输入充分”“有用”或“成功发布”指标。旧 `video_complete`、`video_export` 保留原含义，复制/下载细分未扩大到本轮。实际任务与复用仍按既有知情反馈观察。

API 返回固定 `manju-video-actions-v2` 能力版本。导出不把旧缓存硬标为新版本；缺少新键保留 null，未知版本不回显任意文本，标记 partial。服务端缓存版本更新，小时 TTL 与键规则不变；不增加查询或绕缓存取数。

## 单站发布边界

既有路径过滤会因共享分析映射及 BPJ lib 改动匹配另 17 个站点部署。原 BPJ dispatch 又会重跑每日抓取/统计，且跳过部分仅 push 的浏览器门禁。为执行本轮范围，给原 BPJ workflow 增加默认关闭、仅 main 可用的 `readonly_release` 输入，与既有只读产品发布模式等价：保留构建、浏览器、GA4、current-main 防回滚和发布后页面验收；不执行每日刷新、reach 导出、注册/支付生命周期或外发动作。

提交使用 `[skip ci]` 抑制跨站 push 触发，随后仅对当前 main 的原 BPJ workflow 发起一次带明确输入的功能发布。它仍运行完整适用门禁，不能把 push 自动跳过说成测试通过。提交中的 `[outcome-readonly-release]`、固定触发 SHA、事件类型和只读运行标题共同排除 BPJ 两个 MCP 登记后继，不重复调用或登记；以后同一提交的普通日任务仍保留原登记能力。默认日任务、默认 dispatch、其他站点规则不变。

实际运行、有效部署源、上线起算时间和 IndexNow 回执写入[状态](state.json)。未取得回执前不称已上线。无页面实质正文变化时 IndexNow 应为零；不得为了埋点刷新全站日期。

预发布构建发现旧 hash 算法会把脚本的缓存参数变化列成 103 个页面内容变化。新增归一化仅覆盖生成器实际引用的八个帧选 JS/CSS 资源路径及其 `v` 参数，正文链接、JSON-LD、其他资源、额外参数和真实正文仍敏感。使用未修改的 `938bfcf` 原代码独立构建，在写 manifest 时核对全部 2,019 个唯一历史条目的旧 hash，零不匹配；只迁移其中 103 个帧选 hash，所有原日期原样保留。迁移不使用本轮新内容消除真实差异。该修复由审查代理转为实施，迁移与 57 项测试属于其实施验证及根执行者补充自检，不冒称同一作者的独立评审。
