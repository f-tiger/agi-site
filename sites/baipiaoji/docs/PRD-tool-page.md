# PRD：工具详情页

版本 1 ｜ 2026-07-29 ｜ 状态：本轮已实现「替代方案」与「额度机制」，`limits` 数据待逐条核实

---

## 一、为什么是这个页面

不是拍脑袋选的，是 GA4 指的（详见 `docs/ga4-baseline.md`）：

- 上线四天，**唯一带来真实中文用户的入口是 `/tools/<slug>`**，且全部来自 Google 自然搜索
- 用户搜的是**工具名**（deepl、wps-ai），不是「AI 工具导航」
- 首页零自然流量——这正常，没人搜一个还没人知道的品牌

**结论：杠杆在工具详情页，不在再开一个板块。**

## 二、用户到底想知道什么

调研方法：`customer-research` Mode 2，取搜索结果里用户的原话与高频追问。

搜「某个 AI 工具 + 免费」的人，脑子里其实是**一个判断题**：

> **这个工具的免费额度，够不够我用？不够的话怎么办？**

拆成三个必答问题，按用户提问顺序：

| # | 问题 | 用户的原话/证据 | 我们现在答得怎样 |
|---|---|---|---|
| 1 | **免费能用到什么程度？具体数字** | 「免费版单次翻译上限 5000 字符……文件翻译限制 5MB/份，每月仅允许翻译 3 个文件」——用户要的是**数字**，不是"有免费额度" | ❌ 只有一句话描述，没有量 |
| 2 | **会在哪撞墙？** | 「最大的问题不是不会用，而是钱花得太快，而且总有限制」；更狠的是额度用完后**不报错、自动降级到更弱的模型**，用户只觉得「AI 变笨了」 | ❌ 完全没有 |
| 3 | **撞墙了怎么办？** | 「免费版是入门级选择，付费版适合专业用户」——用户此时要么升级，要么换一个 | ❌ 有「同类工具」，但没回答「哪些同样不花钱」 |

第 2 条在第二轮调研里就被标为「最痛但未落地」（`docs/user-research.md` 主题 6）。这一轮把它变成机制。

## 三、设计

### 3.1 新字段 `limits`（可选，逐条人工核实后才填）

```jsonc
"limits": {
  "quota":  "单次 5000 字符；文件 5MB/份，每月 3 个",   // 具体的量
  "wall":   "超出后需要分段贴，或升级 Pro",              // 撞墙表现
  "source": "官方定价页",                                // 依据来自哪
  "checked": "2026-07-29"                                // 谁核的、什么时候
}
```

**硬规则（与全站一致）**：
- **没核实就不填。** 字段缺失时页面**不显示这一块**，绝不显示"暂无"或编一个。
- `source` 与 `checked` 是必填项。**没有来源的数字不许进这个字段**——限额是会变的硬数字，写错就是直接打脸。
- 站内 `free` 字段回答"有没有"，`limits` 回答"有多少、到哪为止"。两者不重复。

> **进展（2026-07-29）**：深度调研跑完，10 个目标工具里**只有 Gamma 一条通过了「有官方来源」这一关**，已填。
> 其余九个一条官方来源都没拿到，维持缺失、页面不渲染该区块——规则正在生效，不是偷懒。
> 特别记一笔：DeepL 那个满互联网都是的「500,000 字符/月」**官方文档里没有**，在拿到官方页面前不许进站。
> 详见 `docs/research-limits.md`。

### 3.2 「额度不够用了？」——同类免费替代（本轮已实现，全覆盖）

这是本轮最划算的一块：**它完全由已有数据推导，零编造，却直接回答了用户的第三个问题。**

推导规则：
1. 同分类
2. 带「完全免费」标签（即不会撞墙的那批）
3. 排除自己
4. 若当前工具是「国内直连」，替代也优先国内直连——撞墙时换一个还要翻墙，等于没解决
5. 取前 4 个，各带一句它的免费点

没有符合条件的替代时**整块不渲染**，不放空标题。

### 3.3 FAQ 增补

在已有五问基础上加第六问：**「免费额度用完了怎么办？」**
- 有 `limits` → 用 `limits.wall` 回答，再给替代
- 无 `limits` → 只给替代，并直说「站内未记录该工具的具体额度上限」

**不编"大概能用多少次"。**

## 三·五、政策约束：每页必须有独立数据（2026-07-29 新增）

深度调研核实了 Google 的垃圾内容政策原文（见 `docs/research-limits.md` 第三节），对本站这种
「154 个同模板生成的 `/tools/<slug>`」架构有直接影响：

- **Scaled content abuse**：判的是每页是否有独立价值，**「不论由自动化、人工还是两者结合产生」**——
  「是不是 AI 写的」不是判定标准。
- **Doorway abuse**：「创建**实质相似的页面**」被点名。只换工具名、其余雷同的模板页有政策风险。
- **Thin affiliation**：官方列举的「附加价值」里第一项就是**价格与限制的额外信息**——
  正是 `limits` 字段要装的东西。

**由此新增一条硬约束：**

> 工具页模板**必须**保证每页至少有三项页面独立数据。
> 当前每页的独立数据是：已核实日期、福利原文、引用它的方案、同类免费替代、以及（填上后的）额度上限。
> **若某个工具除了名字之外无任何独立信息可写，宁可不收录它**，也不要生成一个只换名字的页面。

这条同时说明 `limits` 不只是「用户想要」，也是这个页面类型**在政策上站得住**的关键。

## 四、不做什么

| 不做 | 为什么 |
|---|---|
| 用 AI 生成工具评测正文 | 没核实的内容会直接摧毁这个站唯一的差异化 |
| 猜或估算额度数字 | 限额随时变，猜错即失信；宁可这一块不显示 |
| 给每个工具配图/截图 | 违反 `docs/DESIGN.md`「零图片」，且截图会过期成为新的失信源 |
| 加「相似工具对比表」 | 对比要求两边数据都核实过，目前只有一边有 |

## 五、验收

- [x] 有替代方案的工具页渲染「额度不够用了？」区块；没有的不渲染空块
- [x] 替代只取同分类 + 完全免费；国内直连的工具优先给国内直连的替代
- [x] FAQ 第六问在有/无 `limits` 两种情况下都说得通，且不编数字
- [x] `limits` 缺失时页面无任何"暂无/待补"占位
- [x] 中英双语，英文侧无中文残留
- [x] 全站构建通过，内链零断裂，JSON-LD 全部可解析

## 六、下一步（需要人）

1. **逐条核实 `limits`**。优先级按 GA4 里被搜到的工具排：目前是 `deepl`、`wps-ai`。
   一次填一条，`source` 必须指向官方页面。
   注意：自动调研这条路**已经试过且基本走不通**——本会话的代理挡住了绝大多数官方域名的直连（403），
   10 个工具只捞到 1 条。**由人直接打开官方定价页抄一遍，反而更快也更可靠。**
2. 填够 20 条之后再评估：要不要把「额度」做成可筛选的维度（例如"每天都能领的"）。
