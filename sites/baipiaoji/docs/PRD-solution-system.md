## 一、三轮调研收敛出的三个事实

1. **供给侧已死，需求侧缺核实**（第一轮）：教人赚钱的内容/课程/方案交易全部过剩且信任破产；
   稀缺且零点击时代还保流量的，是决策类的"可信核实"（is X legit / 规则到底是什么）。
2. **AI 时代真正新出现的买家是 agent，不是人**（第一轮"赚钱工具"的答案）：
   被抓取不可计费，被调用可计费；本站唯一指数增长的线（AI 爬虫 690 次/天）只有 MCP 一个变现出口。
3. **单点不复利，流水线才复利**（owner 判断 + 第二轮验证）：AI 短剧调研证明"品类调研→核实资产→
   订阅"这条流水线可以在任何热点品类上复制，且骗局越密集的品类，我们的结构性优势越大。

## 二、体系架构

**核心资产只有一个：核实过的"AI 赚钱相关事实"数据库。** 三类事实，同一套纪律（source/checked/生效日期/变更留痕/护栏写入）：

| 事实类型 | 数据 | 已有/新增 |
|---|---|---|
| 工具事实（额度/价格/条款） | `tools.json` + limits | 已有 218 个，半年纪律 |
| 规则事实（平台分账/扶持/合规） | `drama-rules.json` 起步，schema 品类通用 | 新增（PRD-drama-truth） |
| 方法事实（审计：真伪/成本/失败/骗局） | `audits.json` + `hustles.json` | 新增（PRD-method-audit）+ 已有 6 作业 |

**一份资产，两个出口，两种买家：**

```
                    ┌─ 人端出口 ────────────────────────────┐
                    │ 决策页（/audits /drama /money /tools）│→ 搜索+AI引用带来的人
核实事实数据库 ──→  │ 邮件订阅：额度/规则变动提醒            │→ 免费订阅 → 付费档
（品类流水线生产）  └───────────────────────────────────────┘
                    ┌─ agent 端出口 ─────────────────────────┐
                    │ MCP 13 工具/9 资源 + 新增规则/审计资源  │→ agent 调用（可计量）
                    │ llms.txt / attribution 回链人端         │→ 付费调用层（阶段2）
                    └───────────────────────────────────────┘
```

**生产侧：品类流水线**（AI 短剧已实例化，workflow 脚本可参数化复用）：
选品类（热度×骗局密度×规则复杂度三高）→ 多角度调研+对抗核实 → 三类事实入库 → 双端出口自动获得新内容 → 订阅列表与 agent 调用量跨品类累积。

**复利的三个维度**（都在同一基建上，不新增摊子）：
- 品类维度：每复制一次流水线，边际成本递减（schema/护栏/workflow/页面模板全复用）
- 买家维度：同一份数据服务人和 agent，两条收入线共享一次核实成本
- 时间维度：事实会过时 → 巡检与变更留痕让数据越老越值钱（历史曲线是独家的），订阅的价值正来自"变化"

## 五、Owner 点名问题：AI 爬虫到底能不能转换为营收

**直接回答：抓取本身，今天≈0 收入，且任何"直接向爬虫收费"的动作在当前量级下期望值是个位数美元/月，还要以杀死引用飞轮为代价。爬虫线的真实身份是先行指标和燃料，不是收入本身。** 四条转化路径逐一算账：

**站内现状**（2026-08 实测）：约 690 次抓取/天且指数增长；来源实测 9 类 UA 全部可达且未被拦（GPTBot、OAI-SearchBot、ChatGPT-User、PerplexityBot、Perplexity-User、ClaudeBot、Claude-User、Google-Extended、Bingbot，`data/ai-crawler-probe.json` 每日巡检）；AI 来源 referral ≈ 0；非 curl agent 调用 2 次/天；订阅 0。

| 路径 | 能不能 | 账 |
|---|---|---|
| **① 直接收费（Cloudflare Pay Per Crawl）** | 技术上能，经济上不值 | 本站就在 Cloudflare 上，机制现成（全网日发 10 亿次 402；2026-09-15 起新域名默认拦训练/agent 爬虫）。但价格由买方接受度决定：头部出版商能谈到 $50K–200K/月，**小站只能拿爬虫愿意给的零头**——按 690 次/天×小站单价，量级是个位数美元/月。且一旦收费=拦截未付费爬虫=引用消失=唯一在增长的线归零。**判定：不开。** 唯一例外留给未来：对"纯训练、不产生引用"的爬虫可以单独收费/拦截，OpenAI 等 9/15 后被迫拆分 UA 恰好让这件事变得可执行——列为观察项，不是现在的动作 |
| **② 抓取→引用→人回流→联盟/订阅** | 能，但分母极小 | 零点击研究：AI 来源访客转化率是普通搜索 2 倍，但量小（本站 go 点击 ~10 次/天）。杠杆不在爬虫侧，在 attribution：llms.txt 与 MCP 描述里的回链要求已就位，决策页（审计/规则表）是最容易被引用后还让人点过来的页面类型——这正是本方案把内容重心压在决策页的原因之一 |
| **③ 抓取→引用→agent 调用 MCP→付费层** | **唯一真正可计费的形态** | 抓取不可鉴权不可计量，调用可以。690 次/天的抓取证明 AI 在消费我们的数据，转化动作 = 把这些消费者从"爬页面"迁移到"调 MCP"（发现入口铺设：Registry 已收录，社区目录待 owner 提交）。现状 2 次/天 → PRD-revenue 阶段 2 门槛达标后开付费层。**爬虫线变现的正解就是这一条** |
| **④ 抓取→训练语料付费** | 不能 | 语料交易是出版商体量的生意（Reddit/AP 级别）；且本站数据已 CC BY 4.0 开放，不可逆也不该逆（PRD-revenue §2.4 已论证） |

**结论写死**：爬虫线的运营目标不是"向爬虫收钱"，而是**两个转化率**——抓取→引用回链的点击率（喂路径②）、抓取→MCP 调用的迁移率（喂路径③）。这两个转化率的分子，就是本方案的两个北极星分母。每日爬虫巡检继续（它是免费的先行指标），但任何"装收费闸"的冲动都按本节的账否决。

## 六、不做的边界（三轮调研反复确认，写死）

- ❌ 卖课/承诺收入/包接单——本品类信任破产的根源，也是我们存在的理由
- ❌ 付费收录/排序/徽章；联盟关系影响判定（PRD-revenue 硬规则原文有效）
- ❌ 内容聚合站、方案交易平台、爆款推荐、下场做制作——四轮研判全部否决，理由在各调研文档
- ❌ 全自动内容生产——候选自动拉，正文人工核实（三次事故换来的纪律）
- ❌ 在分母为零时装收银台——先修分母，这是 PRD-revenue 的结论，本方案全部继承

## 七、预验尸：这个站会怎么死（2026-08-15 补，按概率排序）

每条死法配可观测的**死亡信号**与触发动作——信号出现就执行动作，不许用"再等等"糊过去。

| # | 死法 | 依据（站内真实数据/先例） | 死亡信号（阈值） | 触发动作 |
|---|---|---|---|---|
| D1 | **分母永远起不来**（最大概率） | 当下：订阅 0、go 点击 ~10/天、agent 调用 2/天；阶段 0/1 的 owner 动作清单完成 0 项，**联盟收入已因此空转**——这条死法不是预测，是正在发生的现状 | 执行顺序 1–2 上线后 8 周：订阅 <50 或 go 点击无增长 | 停止新品类扩张，全力做分发实验（社区投放/协作互推），而不是继续生产 |
| D2 | **分发单点死**（HouseFresh 型） | HouseFresh 被一次算法更新拿走 91% 流量，点名巨头后遭 keyword swarming 报复；我们把命押在"被搜到/被 AI 引用"这个租来的渠道上，AEO 规则一年数变（9/15 CF 默认拦截生态又是一变） | 抓取量涨但引用回流连续 8 周横盘/下跌 | 自有触达优先级压倒一切：订阅钩子铺满全站；同题内容分发到不受算法控制的第二渠道（邮件/RSS/社区） |
| D3 | **买错人群**（结构性） | 目标人群"想赚钱的人"=无预算、易流失、被割怕了谁都不信（三轮调研自己证明的）；Wirecutter/CamelCamelCamel 赚钱靠的都是"要花钱的人" | 审计/作业页流量健康但联盟点击率 <0.5% | 变现重心按§八δ1 移到升级决策页；审计线只承担获客与信任，不背营收 KPI |
| D4 | **数据腐烂**（信任资产变负债） | 单人维护 218 工具 limits+规则表+审计，巡检债务线性涨；limits 已出过三次覆盖事故；一条过时数据被 AI 引用=拿信任资产赔付 | 待复核条目 >15% 或单条 stale >60 天仍在展示 | 扩张冻结：新品类必须先配自动巡检信号源才准入库；stale 条目自动降级展示"待复核"徽标（诚实本身是护城河） |
| D5 | **审计线被打死**（法律/名誉） | 审计要点名（拿云文化等）；HouseFresh 点名 Dotdash 后遭报复性打压；中文环境还有投诉/删帖压力 | 收到第一封律师函/平台投诉 | 预案前置：点名仅限已被主流媒体公开点名者、每条断言挂公开报道/判决文书出处、证据链存档；审计主体写"方法"，机构名只做引用 |
| D6 | **地基条款变**（低概率高冲击） | MCP/爬虫/联盟全跑在别人地基上（CF、OpenAI Registry、联盟平台） | 任一通道单方变更条款 | 已有的多通道冗余（页面/MCP/llms.txt/RSS）保底，不新增对策，仅保持 |

## 八、成功站点的经验移植与方案刷新

四个已验证十年级别存活的同构样本，各取一条可抄的机制：

| 样本 | 存活方式 | 移植到本站 |
|---|---|---|
| **CamelCamelCamel**（2008–今，无订阅费） | 价格历史免费+降价提醒邮件，**提醒即佣金触发器**——提醒送达的时刻就是购买意图的时刻，邮件里的商品链接挂联盟返佣，18 年没收过用户一分钱 | δ2：变动提醒永久免费，变现=邮件内嵌意图时刻的联盟链接；"付费提醒档"从阶段 1 移除 |
| **Have I Been Pwned**（2013–今，单人起家） | 免费查询建立公共信任，**收钱的是 API**：按 RPM 分层（Core/Pro）+ 年付，买家是把数据嵌进自己产品的公司（1Password/Mozilla） | δ3：MCP 付费层照抄此模——API key+调用量分层+年付；买家画像=要消费"AI 工具事实数据"的 agent 开发者与选型企业，不是散户 |
| **Wirecutter** | 核实型评测+联盟，服务"要花钱的人"，卖给 NYT | δ1（本轮最重要的刷新）：**信任在"想赚钱"侧建立，钱在"要花钱"侧赚**——新增"升级决策页"页面类型（"免费额度不够了，该买哪档/换哪家"），这是全站唯一的购买意图场景，且 limits 数据是独家决策依据；已插入执行顺序 1.5 |
| **HouseFresh**（反面样本，幸存中） | 渠道单点+点名巨头的代价=91% 流量蒸发；靠多平台分发+自有列表撑过两年 | D2/D5 的对策来源；另一条教训：它 2024 年就警告"大媒体正在吞掉核实型小站"，这个预言在 AEO 时代对我们同样成立 |
| **TAAFT/目录坟场**（背景板） | 头部目录活着靠卖位置与先发分发；大量克隆目录已死 | 佐证既有判断：目录不是产品；我们不卖位置，所以订阅+API 两条腿是唯一活法 |

**刷新汇总（δ）**：δ1 升级决策页入执行顺序 1.5（购买意图+联盟挂载）；δ2 提醒免费化+佣金触发器机制（阶段 1 表已改）；δ3 MCP 付费层按 HIBP 分层模式具体化；δ4 预验尸六条死亡信号入常规巡检（growth-report 每轮核对）；δ5 owner 阻塞项标红——阶段 0 收入、阶段 1 通道、选题雷达全部卡在 owner 三个动作上（联盟注册/邮件密钥/YOUTUBE_API_KEY），这是当前最大的单点风险，方案本身无法代偿。
