## 二、用户洞察

**订阅最多的赛道是 AI 编程（开发者）**——市场最大、付费意愿最强、档位最高。
（原文此处还写了「而且恰好是我们站上人流最大的类目页」，该证据已在上方订正中作废：
带 referrer 的真实来访里 coding 与 chat/api 并列，不占优。本节结论改为只由外部市场证据
与社区原声支撑——它们本来就是更强的那一半。）

但**他们的痛点不是「哪个免费」**——他们已经在付钱了。痛点是：

> 我同时在付 Copilot / Cursor / Claude / ChatGPT，
> **每家的额度口径还都不一样（补全 / 请求 / Credits / 消息数），
> 我根本算不出哪一个是白付的。**

这就是那**一格能赢的细分赛道**：

> ### 不做「AI 工具目录」，做「AI 订阅账单体检」

现有供给为什么没解决：
- 评测文章给的是**主观排名**（「只有 3 个值得用」），回答不了「**我**该停哪个」；
- 各家官网只讲自己，不给横向可比口径；
- 比价站有价格没额度——而 Credits 时代**价格已经不是决策变量，额度才是**；
- 想做这件事必须有一份「每家免费档到哪为止 + 官方出处 + 核实日期」的结构化数据，
  **全网只有我们有**（coding 19 家、chat 10 家、video 13 家、image 17 家已结构化）。

**关键设计约束（也是最优雅的一点）**：
价格与用量**由用户自己填**——他自己知道每月付多少、每天写多少。
我们只提供已核实的天花板。于是：**输出的是他自己的钱，我们一个数字都不用编。**

> 顺带记一条今天撞到的墙：厂商定价页（cursor.com 等）在本会话被出口代理拦截，
> **我们无法核实付费价格**。所以「帮你算省多少钱」如果由我们填价格，就必然违反
> 「无官方来源不发布数字」。让用户自己填价格不是妥协，是唯一合规的做法。

## 三、产品需求

### 定位
一页体检：**把你正在付的 AI 订阅，逐个对上已核实的免费天花板，告诉你哪几个可以先停。**

### 目标用户
1. 同时付 2 个以上 AI 订阅的开发者（主）
2. 想在付费前先确认免费档够不够的人（次）

### 硬规则（继承全站，不豁免）
1. 天花板只用已核实数据，带官方出处与核实日期；官方没公布的**如实显示「未公布」，不猜**。
2. **我们不填任何价格**——价格是用户输入。
3. 计算全在浏览器里做，**用量与花费不上传**（这是隐私，也是信任）。
4. 付费与否**不影响任何判定、排序、推荐**（PRD-revenue 第四节硬规则）。

### MVP 范围
- **工具 A｜订阅体检 `/subscription-audit.html`**（中英双语）✅ 已上线
  覆盖 **coding 19 家 + chat 10 家（去掉已合并的 marscode，共 28 个候选）**。
  刻意**不含 video / image**：那两类的官方折算写在中文散文里（「约 6 个 5 秒视频」），
  解析散文取数就等于我们自己造数——宁可不覆盖。
  勾选 → 填月费与用量 → 输出六档：可以停 / 确实该付 / 官方给了数字但和你的用量对不上
  （计的是 Credits 或 Token）/ 官方没公布 / 只是试用期 / 本来就不是订阅。
  **上线即得的一个结论**：28 个候选里 **13 个官方压根不公布额度**——
  这不是我们没查到，是厂商不公布，而这正是「哪个白付了」算不出来的根因。
- **付费层**：见下一节。✅ 定价页 + 授权码校验已上线，开关默认关闭。
- **工具 B｜撞墙日历 `/free-tier-countdown.html`**：下一轮。
  面向还没付钱的人：按日均用量，各家免费档在本月第几天用完、几时重置、撞墙后会怎样。

### 不做什么
- 不做价格比价（无法核实价格）
- 不做「哪个更好用」的主观排名（我们没有评测能力，也不该假装有）
- 不做账号打通/自动读取账单（要 OAuth 与信任，MVP 阶段成本远大于价值）

### 验收
- 双语页面上线，构建八道门禁全零
- 每条结论可点回工具页看到官方出处与核实日期
- 「官方未公布」的工具在结果里**单独成档**，不混进可停/该付两档

## 四、付费订阅设计

### 先说清楚一件事（诚实，不是保守）

`PRD-revenue.md` 定过一条硬规则：**三级证据门槛未达标不上收费**，而当前
真人手势事件约 10 次/天、订阅数 0。**今天挂上收银台，收入会精确为零**，
并不是模式不对，是分母不够。

所以本轮的做法是：**把付费机制完整建好并保持关闭**。
边际成本为零、将来流量到位不用返工，同时不在一个日活个位数的站上摆一道付费墙。

### 免费 / 付费的切法

| 能力 | 档位 | 理由 |
|---|---|---|
| 全部已核实数字、全部工具的**单次计算** | **永久免费** | 这是分发本身，动它等于自断被引用的理由 |
| 数据集、API、MCP | **永久免费**（CC BY 4.0） | 已开放，不反悔 |
| **持续监控**：你体检过的那几个订阅，额度或条款一变就通知你 | 付费 | 唯一自有触达通道；也是唯一真正持续产生价值的能力 |
| **报告导出**（CSV / 可传阅的一页版） | 付费 | 团队场景的真实需求 |
| MCP 高频配额、自定义订阅源、变更 webhook | 付费 | 承接 PRD-revenue 阶段 2 |

### 支付形态：不绑定支付商

现在没有任何支付商账号，且接一家等于绑一家。所以实现成**授权码机制**：

- owner 用任何渠道收款（爱发电 / Ko-fi / GitHub Sponsors / 对公转账都行）
- 收款后签发一枚 **HMAC 签名的授权码**（`scripts/license.mjs`，密钥存 Cloudflare env）
- 前端把授权码交给 `/api/entitlement` 校验，通过则解锁付费能力
- 支付商将来接哪家都行，**授权码这一层不用改**

授权码里只有「档位 + 到期日 + 随机串」，**不含任何个人信息**。

### 硬门禁
- `PAID_ENABLED` 默认 **false**：关闭时定价页只展示「即将开放」，不出现任何付款入口
- 构建期断言：付费状态**不得**进入排序 / 推荐 / 判定的任何一条代码路径
