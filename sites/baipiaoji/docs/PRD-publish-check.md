## 一、需求调研（证据，不是判断）

### 1.1 站内流量：coding 的强势只存在于类目页那一层

D1 第一方打点，按 Google 自然搜索落地页拆分：

| 层级 | 结论 |
|---|---|
| 类目页 | `/en/c/coding` 88 次浏览、7 次来自 Google——**唯一有自然搜索的类目页** |
| 工具页 | coding 只有 3 次（cursor 2、codebuddy 1） |

工具页长尾按类目汇总（Google 自然搜索，共 33 次）：

| 类目 | 次数 | 工具 |
|---|---|---|
| chat | 11 | claude, poe, ms-copilot, yuewen, grok, chatgpt |
| **video** | **8** | haiper, hailuo, jianying |
| agent | 6 | fastgpt, dify |
| api | 4 | fireworks, siliconflow, deepinfra |
| coding | 3 | cursor, codebuddy |
| image | 1 | leonardo |

**这推翻了「只有 coding 被验证」的前提**：coding 赢在「免费编程工具有哪些」这类**浏览型**查询，
而具体工具的**决策型**查询集中在 chat 与 video。两者是不同的用户任务，不该混为一谈。

chat 类目的头部（ChatGPT、Claude）是巨头主场，本站在那里没有结构性优势。
video 不同：它的问题不是「哪个好用」，而是「我做出来的东西能不能用」。

### 1.2 站内数据：113 条已核实的「墙」里，重复出现什么

`wall` 字段是官方口径下「额度用完之后会怎样」，是**被厂商自己确认过的痛点语料**。聚类结果：

| 墙的形态 | 工具数 |
|---|---|
| 按天回血 | 38 |
| 官方不公布数字 | 29 |
| 一次性额度 | 16 |
| 清晰度／时长受限 | 13 |
| **商用授权受限** | **13** |
| 要绑卡／实名 | 11 |
| 协作人数 | 11 |
| 速率限制 | 8 |
| **水印** | **8** |

「产出能不能用」这一簇（水印 + 商用授权 + 规格）合计 24 个工具，集中在 video(10)、audio(5)、image(4)。

### 1.3 站外需求语与社区原声

中文侧搜索「AI 视频生成 免费版 水印 商用」返回的是决策卡点式内容：
知乎提问「我使用豆包 AI 生成的图片，可以免费用于商业用途吗？」、

## 二、用户洞察

### 2.1 全行业在回答错误的问题

英文检索里一条来自厂商博客的原话点破了要害：

> **a watermark-free export is not automatically a commercial license**
> （能导出无水印，不等于拿到了商用授权）

所有竞品都在回答「有没有水印」——因为这个词有搜索量、好写、好比较。
而用户真正要解决的是「**我把这段视频发出去，会不会出事**」。这两件事被普遍混为一谈。

本站数据里它们**本来就是分开的两列**：`quota` 记额度，`wall` 记撞墙表现，
水印与授权是两条独立事实，各自带官方出处与核实日期。

站内自查印证了这个混淆的规模：**只提水印、完全没提商用的工具有 6 个**——
这正是最容易被读者默认成「无水印 = 可商用」的那一批。

### 2.2 细分赛道（不做大而全，做能赢的那一格）

> **面向要把 AI 产出交出去的人（自媒体、接单的自由职业者、小团队），
> 回答「这个免费档的产出，我能不能发／能不能商用／能不能交付给客户」，
> 每条判定都带官方原文出处与核实日期。**

不是「最好的免费视频工具排行」，是「你手上这个工具，这个用途，行还是不行」。

### 2.3 为什么本站能赢这一格

| 要素 | 本站现状 |
|---|---|
| 需要逐家读官方条款 | 这就是本站唯一在做的事，已积累 113 条 + 方法论页 + 七种拒绝情形 |
| 条款会变 | 每日复核流水线 + 变更检测（`page-lastmod` / `guard-regression`）已在跑 |
| 错了有代价 | 法律与商业风险 → 付费意愿高于「省钱」类需求 |
| 竞品护城河 | 清单文无出处、不更新、混淆水印与授权 |
| 已有验证 | video 是 Google 工具页流量第二（8 次），仅次于 chat |

### 2.4 为什么不选「每日额度领取助手」

「按天回血」是最大的一簇（38 个工具），但：
付费意愿低（省的是几毛钱额度）、本站首页已免费提供「今天能领的免费额度」、
且它不需要本站的核心能力（读条款），谁都能做。**大不等于能赢。**

## 三、硬规则（违反即不做）

1. **判定必须可追溯**：每条结论附官方原文出处 + 核实日期。查不到官方表述 → 输出「查不到」，不输出「可能可以」。
2. **不提供法律意见**：只转述厂商条款，不做法律判断。文案必须写明这一点。
3. **不锁公开数据**：`limits.json` 保持 CC BY 开放。付费卖的是**工作流与凭证**，不是访问权。
4. **不猜、不补全**：条款没说的维度就是空的，空的要显式说明是空的。
5. **变更即失效**：厂商改条款后，旧凭证必须能看出「这是哪天的判定」。

## 四、先决条件：数据覆盖才是瓶颈，不是代码

现状（实测，非估计）：

- 已核实 113 个工具中，触及「产出能不能用」的 **24 个**
- 其中**明确写了商用授权的只有 11 个**
- 水印与商用**都**写清楚的只有 **2 个**

**结论：现在开工，会做出一个对 89 个工具只能回答「不知道」的产品。**

因此 Phase 0 不是可选项：

> **Phase 0（数据）**：把 video / audio / image / design 四类共约 40 个已收录工具的
> 「授权维度」补齐——是否允许商用、是否带水印、无水印是否等于授权、
> 付费后生成的内容在退订后能否继续用。每条走既有 `limits-edit.mjs` 流程与判例。
> **验收：这四类里「授权维度有明确结论（含明确的『官方未说明』）」的比例 ≥ 80%。**

Phase 0 完成前不写产品代码。这不是保守，是因为一个答不出话的工具会一次性烧掉信任。

## 五、MVP 范围（Phase 0 达标后）

**免费**
- 选一个工具 + 一个用途（自用 / 发社交媒体 / 交付客户 / 投放广告 / 二次售卖），
  给出判定：可以 / 不可以 / 官方未说明，附官方原文与核实日期。

**订阅（付费）**
- **批量核查**：一次传入多个工具（做一条片子常常用了 3–5 个），一次出总结论——
  只要有一个环节不允许商用，整条产出就不干净，这是单个查询给不了的价值。
- **可存档的合规凭证**：导出带日期、出处、逐条原文的 Markdown/PDF。
  自由职业者交付给客户时，「某年某月某日该厂商官方条款如此」是一件真实的业务凭据。
- **条款变更提醒**：你用过的工具改了授权条款就发信——直接复用已建成的订阅与变更检测管道。

## 六、明确不做

- 不做「无水印工具排行榜」——那是竞品在做的错题
- 不做去水印工具（协助绕过厂商限制，与本站立场相悖）
- 不做法律意见、不做合同模板
- 不为了凑功能收录没有官方条款可查的工具
- 不把已公开的 `limits.json` 关进付费墙

## 七、验收标准

| 阶段 | 验收 |
|---|---|
| Phase 0 | 四类目授权维度结论覆盖率 ≥ 80%，每条含官方出处 + 核实日期 |
| MVP 免费版 | 任一已覆盖工具 + 任一用途，能给出三态判定与原文；构建验证六项全零 |
| 订阅版 | 批量核查、凭证导出、变更提醒三项可用；退订链路复用现有实现 |
| 商业 | 上线后有付费转化再谈定价档位——**本文档不预设价格**，无数据支撑的定价是编的 |

## 八、待验证的风险

1. **付费意愿未经证实**。上面全部是需求证据，不是支付证据。
   最小验证方式：先做免费版，在导出凭证处放一个「需要可存档凭证？」的意向登记，用真实点击率决定要不要做付费档。
2. **厂商条款可能不可直连**：当前出站网络受限时只能走搜索索引引文核实，覆盖速度会被拖慢。
3. **责任边界**：即使写明「不构成法律意见」，仍需谨慎措辞，避免读者把判定当作担保。

## 附二：Phase 0 完成后的认知更新（会改写 MVP 设计）

补完 32 家后，「产出能不能商用」浮现出**至少十一种彼此独立的形态**，
远超立项时假设的「可商用 / 不可商用 / 未说明」三态。这直接推翻了 MVP 原定的三态判定：

| # | 形态 | 例子 |
|---|---|---|
| 1 | 免费档即享完整商用权 | Runway、Ideogram、Figma |
| 2 | 免费档明确不可商用 | Kling、HeyGen、D-ID、Vidu、Krea、Playground、remove.bg、Haiper |
| 3 | 产权给你、合同禁止商用 | Pika |
| 4 | 产出归平台所有 | Recraft |
| 5 | 给了产权、没给结论 | 即梦 |
| 6 | 官方对商用只字未提 | 海螺、清影、通义万相 |
| 7 | 可商用但无排他权 | Canva |
| 8 | 可商用但不保证不侵权、责任在你 | Bing 图像创作 |
| 9 | 逐个模型不同，且许可只是「请求」不是正式授权 | Civitai |
| 10 | 软件许可 ≠ 模型许可 ≠ 产出许可 | Upscayl |
| 11 | 附带标注义务，且义务绑定「创作时的档位」 | Udio、Kling |

**对 MVP 的三条修正：**

1. **判定不能是三态，至少要输出「结论 + 附带义务 + 责任归属」三段**。
   「可商用」在 Bing 与在 Runway 含义完全不同：前者可商用但不保证不侵权、
   出事你担责；后者逐条列举了适用场景。只给一个绿灯会误导人。
2. **必须能表达「同一厂商多条线」**。清影 vs 智谱开放平台、通义万相网页版 vs 百炼 API、
   Krea 的免费档/订阅/开源自部署/企业版四条线——答案完全不同。
   按「工具」建模不够，得按「工具 × 使用线路」。
3. **标注义务要单独成一栏**。Kling 要求无水印也须标明来源，
   Udio 的标注义务绑定创作时的档位、事后订阅也消不掉——
   这类义务不影响「能不能用」，却决定「怎么用才合规」，混在结论里会被忽略。

另有一条与授权无关但更紧急的发现：**Motiff 妙多已于 2026 年停止服务**
（官方中英两处日期不一致：英文帮助页 2026-06-23、中文关停说明 2026-07-31），
而站内此前仍将其作为可用的免费工具展示。已改写为存档与迁移指引。
**这暴露了每日巡检的一个盲区：域名仍可访问，链接检查就不会报警，
但产品可能早已停运。** 建议后续增加「停运/下线」状态位与相应巡检信号——
这不属于本 PRD 范围，另行记录。

| — | 分档授权（标准／扩展／商品类）+ 单独的所有权购买 | 无界 |
| — | 反向条款：厂商可拿你的产出做自己的营销 | Haiper、无界 |

**第 12、13、14 条尤其推翻了「一次查询给一个答案」的产品设想：**

- **第 12 条（短板效应）**：用 LoRA 是常态，一张图往往叠了底模 + 数个 LoRA。
  判定对象根本不是「工具」，而是「**这一次生成实际用到的模型组合**」。
- **第 13 条（审核门）**：文心一格的门不是付费，是过审。产品必须能表达
  「不是不许你商用，是你可能根本拿不到文件」。
- **第 14 条（无人担保）**：Pixlr 明说它没法授予自己也没有的权利，且免费档
  不适用其责任条款。这意味着「可商用」有时并不意味着有人为你兜底——
  必须与 Runway 那种逐条列举适用场景的「可商用」区分开。

**结论：MVP 的数据模型至少需要四个字段，而不是一个判定：**

1. `verdict`——可以／不可以／官方未说明（三态仍是骨架）
2. `obligations`——附带义务（标注、审核、仅限个人、不得代第三方使用……）
3. `liability`——责任归属与是否有厂商担保
4. `scope`——判定适用的线路（免费档／订阅／自部署／企业／具体模型组合）

只给第 1 项，就是把十四种形态压成三态——那正是竞品清单文在犯的错，
也是本站不该重复的错。

## 附四：MVP 免费版已上线（2026-08-06）

`/publish-check.html`（中英双语），三部分：

1. **交互查询**：选「我用的是」＋「我打算」（自用／发社媒不变现／交付客户／投放广告／二次售卖），
   给出四段结果——回答、该档整体商用判定、附带义务、责任与担保，并链回工具页看官方原文。
2. **全量静态表**：39 条判定全部渲染成表格，不依赖 JS——爬虫与 AI 检索拿到的是完整内容，
   不是一个空壳 widget。
3. **免责声明**：只转述厂商条款、不构成法律意见；每条判定旁标注核实日期作为保质期。

数据落在 `data/licence.json`（四字段模型），与 `limits` 里的散文互为表里：
散文给人读，结构化给程序判定。覆盖率由 `scripts/licence-coverage.mjs` 守着。

**实施中修掉的一个真实误读风险**：最初把「整体商用判定」徽标放在回答之前，
于是 recraft 选「自用」时，徽标写「不可商用」而正文写「可以」，一眼扫过会看反。
已改为回答在前、徽标在后并显式标注「该档整体商用判定」。
对一个专门拆解「水印 ≠ 授权」这类混淆的产品来说，自己制造新的混淆是最不可接受的。

**用途判定刻意保守**：「不可商用」档位下选「发社媒（不变现）」，本站不给绿灯也不给红灯，
而是明说「官方只授权个人非商业使用，是否涵盖公开发布多数未明说——本站不替你判断」。
这正是 PRD 硬规则第 1、4 条的落地。

**尚未做（付费档）**：批量核查、可存档凭证、条款变更提醒。
按第八节的风险控制，先用免费版验证付费意愿，再决定要不要做——
订阅表单已随页上线，来源标记为 `/publish-check.html`，可从 D1 直接读转化。

## 附五：deep-research 复核（2026-08-06）——两条改进、一条否决

一轮 103 个 agent 的深度调研跑完，五个角度里**只有 5 条结论通过三票对抗验证**。
写在这里是因为「哪些没通过」比「哪些通过了」更值钱：它直接决定了下一步不该做什么。

### 通过验证、已落地（两条）

**1｜二态授权模型在结构上就是错的。**
最干净的反例是 Midjourney：商用权同时取决于「是否付费档」与「你所在企业上一自然年
gross revenue 是否超过 100 万美元」，两个条件与运算；条款里的动词是 **own** 而非
merely use，免费/试用产出则是 CC BY-NC 4.0（非商业）。用一个 ✅/❌ 字段回答，
会对「大公司里的付费用户」给出确定但错误的答案——确定的错答比说不知道更伤人。

Midjourney 本身没有免费档、不在本站 39 条数据集内，**所以不写它的数据**，
只把它暴露出的结构缺陷修掉：`data/licence.json` 增加可选 `condition` 字段
（`type` ∈ tier／purchase／review／model／attribution，附 `gate_zh`/`gate_en`），
并新增第三态 `conditional`。

19 条补上了解锁条件——**全部从已核实文本里提取，不新增任何未核实的厂商事实**。
已核实文本里没写解锁条件的（heygen、recraft、haiper、opusclip、pixverse 等）就空着：
「官方没说升级之后算不算」与「官方说了升级就行」是两种不同的事实，不许混。

第三态目前只有文心一格一条：官方允许商用，但图片**要先过审才拿得到文件**——
压进「可以」会让人以为下载得到，压进「不可以」又与官方口径相反。
一条也要单列，因为模型能不能表达这种情况，决定了将来遇到第二条时会不会说谎。

**2｜「有没有权利发」之外，还有「发的时候必须做什么」。**
《人工智能生成合成内容标识办法》（网信办等四部门，2025-03-14 公布，2025-09-01 施行）
配套强制性国标 GB 45438-2025，**义务直达个人发布者**：

- **第十条**：用户通过网络信息内容传播服务发布生成合成内容的，应当主动声明，
  并使用服务提供者提供的标识功能进行标识。
- **第十一条**：任何组织和个人不得恶意删除、篡改、伪造、隐匿标识，
  **也不得为他人实施上述行为提供工具或者服务**。
- **第九条**：允许用户要求提供不含显式标识的内容（服务提供者须在用户协议中明确
  用户的标识义务与使用责任，并留存日志不少于六个月）。

第九条这条豁免很关键，它挡住了一个我们本来会犯的错：**「免费档导出没有可见水印」
本身不违规**，把所有无水印导出或去水印工具一律标红，在法律上是错的。
真正变的是——标注责任转移到了用户身上。

落地为 `/publish-check.html` 的「中国大陆发布模式」：勾选后、且用途不是「自己看看」时
（不发布就谈不上第十条），追加三条使用者侧动作项。法条区块同时以**静态 HTML** 渲染，
不只在 JS 里——AI 抓取器不执行脚本，只藏在 widget 里等于没写。
数据落 `data/china-labeling.json`，带 issuer/issued/effective/source/checked。

页面另加了一条硬区分：**删除「AI 生成」标识（第十一条明确禁止）与去掉图库/品牌水印
（版权与合同问题，不在本办法射程内）是两件事**，同一个动作名、两套完全不同的后果。
这正是本站赛道的老本行——把被混为一谈的两件事拆开。

### 未通过验证、因此不做（一条，最重要）

调研的第 1 角度（社区痛点）与第 4 角度（已验证的付费意愿）**产出零条通过验证的结论**。
被 0-3 否掉的候选包括：某 Leonardo 用户「卖了两次才想起问授权」、Figma 付费订阅者撞上
AI 额度墙、IndieHackers 上「40+ 工具，一半以上是 2-3 个 prompt 的 demo」、
用量计费正在成为最大成本项。否决理由一致：目标页面 403、结论只落在搜索摘要与标题上，
或把单个轶事外推成结构性需求。

**所以：在拿到需求侧一手证据之前，不据「免费档其实是 demo」「付费监控有人买单」
这类说法设计付费功能。**批量核查、可存档凭证、条款变更提醒三项继续挂起。

下一轮需求调研必须换用**可抓取的一手源**（Reddit / HN 公开 JSON API、知乎、V2EX、
少数派、Gumroad / Stripe 公开定价与销量页、Product Hunt 评论），并**强制逐字取证**，
不接受搜索摘要作为证据。本轮环境限制记录在案：docs.midjourney.com、cac.gov.cn、
community.adobe.com、forum.figma.com、opentermsarchive.org 全部 403，
web.archive.org 不可达；上述法条表述系经搜索索引引文与人民网转发稿交叉核对，
而非抓取正文——`data/china-labeling.json` 的 `source_zh` 里已如实写明这一点。

### 一条附带确认

Open Terms Archive 的 58 类本体全部是法律文书类型，**不含任何额度/限制类目**，
其 `version` 定义还会剥离「法律上无关」的内容——所以本站 113 条已核实免费额度
确实不在那份开放数据集的覆盖范围内。（验证方同时提醒：由此推出「这是可防御资产」
属战略判断而非既定事实；关于 OTA 抓取频率、ODC-BY 复用、ChatGPT 规则分布的
另外三条相关主张均被否决。）
