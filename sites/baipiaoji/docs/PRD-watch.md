调研日期：2026-08-14｜方法：5 角度并行深度调研 + 逐条对抗复核（39 条结论杀掉 18 条，
下文只使用存活结论）｜承接：PRD-revenue（阶段 2）、PRD-paid-tools（付费机制）、PRD-selfbuilt（自研判据）

## 一、调研结论（只留经受住对抗复核的）

### 哪些赛道的付费是真的

| 模式 | 存活证据 | 对我们的含义 |
|---|---|---|
| **监控 + 通知** | Distill.io 付费档 $15/$35/$80+/月，**卖的是更短的检查间隔**；changedetection.io 开源自托管之外，$8.99/月的托管版照样有人付 | 「盯着某个东西、变了告诉我」在个位数到几十美元价位有稳定付费习惯 |
| **垂直数据订阅** | BuiltWith：约 1 人运营，三档 $295–$995/月，约 3000 家付费客户（含 Google/Meta/Amazon），**$14M+ ARR** | 一人 + 爬虫 + 企业买家密度高的垂直数据 = 天花板级案例 |
| **帮人管订阅** | Truebill 以 $1.275B 被收购（250 万用户、约 $100M ARR）；Rocket Money Premium $7–14/月 | 「替我盯钱」有十亿美元级验证——但通用盘子轮不到我们，AI 细分才是缝 |
| **合规窗口** | EU AI Act 第 50 条 **2026-08-02 起可执行**（12 天前！），罚则至 €15M 或全球营收 3%，举证责任在企业；实施细则 2026 年中才定稿 | 窗口极早期。参照 GDPR 时代 cookie-banner 工具（Cookiebot）的路径 |

### 哪些赛道的付费是假的（同样重要）

- **个人 AI 花费管理收不到钱**：需求被 8.6k stars 的免费开源工具吸收；连专营 AI 账单的
  Vaudit 都把个人版设为免费、只从企业追回款抽成。
- **LLM observability 是 feature 不是 product**：Helicone 处理了 14.2 万亿 tokens、
  1.6 万组织在用，仍在 2026-03 被 Mintlify 收购转维护模式；行规是**免费档不卡核心功能，
  付费卖留存时长、合规报告与支持**（Langfuse：Hobby 免费 50k units，付费解锁的是留存与 SOC2）。
- **AI 内容标注工具个人不付费**：Adobe Content Credentials 免费、设备厂商内置、
  中国侧被阿里云内容安全吸收成附属功能。

### 第一手数据的两个硬事实

- `calc` 事件历史**零记录**（埋点渲染后自动触发）：自建计算器从未有真人停留超过 1.5 秒。
  **转型 PRD 里分发权重必须与开发相等**——工具做得再对，没人走到门口也是零。
- 真实的「监控」需求信号已经有了：3 个真人点过「关注额度变化」（star 事件），
  而我们至今给不出任何通知——邮件通道没有密钥。**这是「确定有人要、我们给不出」清单上
  挂了两周的头号项。**

## 二、洞察

把存活证据叠在我们已有的资产上，只有一格同时满足「有人真的在付钱的模式」×「我们独有的数据」×「窗口期」：

> ### 做「AI 上游依赖监控」：你的产品建立在别人家的额度、价格和条款上，
> ### 它们会在没有公告的情况下改变——我们逐日核实、变了就推给你。

三个论据：

1. **变更是真实且无公告的**。我们自己核实过的实例：2026-04 三家编程助手同时转 Credits
   无一家发公告；Perplexity 把重置周期从按天改成按周、旧帮助页还留着旧口径；Suno 的商用权
   只覆盖订阅期内生成的歌。**依赖这些服务的开发者，其成本结构或产出的合法性会在一夜之间改变。**
2. **付费模式已被验证，且和我们的成本结构同构**。Distill/changedetection 证明监控值
   $9–$80/月；但通用页面 diff 是红海，我们的差异化是**核实层**——不是告诉你「页面变了」，
   是告诉你「免费档从 X 变成 Y，官方出处在这，商用判定没变」。这正是 Langfuse 行规的
   镜像应用：核心数据永久免费（CC BY 4.0 不反悔），**付费卖的是通知的及时性、覆盖广度、
   历史深度与交付形态**——服务，不是数据。
3. **天花板由 BuiltWith 标定**。它的公式是「企业买家密度高 + 可程序化采集的垂直数据」。
   我们逐日积累的「AI 厂商额度/条款变更时间序列」是全网没有第二份的数据——今天卖给
   个人开发者 $5/月，数据积累两年后是 FinOps/采购/法务愿意按 BuiltWith 价位买的东西。
   近期可达区间（多个先例支撑）：$10k–50k MRR 的小而美；远期上限：垂直数据订阅。

**转型的一句话**：目录是「查一次就走」，监控是「持续在岗」——同一份数据，从快照生意变成时间序列生意。

## 三、产品需求

### MVP：webhook 监控（本轮上线）

为什么先 webhook 而不是邮件：**邮件通道卡在 owner 的服务商密钥上，webhook 不卡任何人**。
且 webhook 的买家（开发者，接 Slack/Discord/自动化）恰好是付费意愿最高的那批人。

- `POST /api/watch`：注册 { webhook URL, 关注的 slugs, 可选授权码 }
- 每日构建产出 changes.json 后，CI 触发 `POST /api/dispatch-changes`：
  **端点自己从同源拉 changes.json**（不信任调用方载荷），按每个 watch 的 `last_sent`
  幂等分发，POST 结构化 JSON（slug / 变了什么字段 / 当前口径 / 核实日期 / 出处页链接）
- `/watch.html` 双语页面：粘贴 webhook URL、勾选工具、完成注册；给出 curl 示例供 agent 用

### 免费 / 付费切分（遵循 Langfuse 行规：免费不卡核心）

| | Free | Pro（授权码解锁） |
|---|---|---|
| 监控工具数 | 3 个 | 全部（218+） |
| 通知延迟 | 每日批 | 每日批（数据本身每日核实，**不假装有实时**） |
| 交付 | webhook | webhook + 邮件（通道打通后） + 历史时间序列导出 |
| 价格 | 0 | **未定**。锚点：Distill $15 起 / changedetection $8.99 / Langfuse Core $29；定价放在有 10 个真实 watch 之后 |

### 硬规则（全部继承，不豁免）

1. 通知内容 = 已核实的变更记录，**每条带官方出处与核实日期**；机器不写事实。
2. 免费档不卡核心：任何人不花钱也能盯 3 个工具——这同时是分发钩子。
3. 不假装实时：我们的核实是每日的，通知就是每日的。「更快」只有在核实真的更快之后才能卖。
4. webhook 注册要 SSRF 守门（仅 https、拒绝 IP 直连与内网域名），退订自助（token）。
5. 付费状态不影响任何判定/排序/收录（老规矩）。
6. `PAID_ENABLED` 仍按 PRD-revenue 门槛控制**收款**；但免费档监控现在就上——
   它本身就是验证需求的度量（watch 注册数是新的北极星前置指标）。

### 不做什么

- 不做通用网页监控（Visualping 的红海，且与核实层无关）
- 不做「实时」爬取厂商页面的承诺（核实是人守环节，快不了也不该假装快）
- 不做个人 AI 花费管理独立产品（调研已证收不到钱；订阅体检保留为引流工具）
- 企业级 GRC/审计（Vaudit 的位置）：数据积累未到，两年后再评估
