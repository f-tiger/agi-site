# EcoBack: grow through useful decisions

Owner request: learn operating practices from mature sites and apply them across EcoBack to grow users. Scope: existing public site and existing build cadence. No new spend, outreach, Growth Loop restart or storage/PV restoration.

## Three optimization passes

1. Goal: grow relevant users and verified net commissions, with country and intent kept separate. A released page, search action or affiliate event is not a buyer.
2. Evidence: co2online answers by room/season; Topten compares condition-specific performance and ownership cost; Meaco routes by household job and compares a small set of choices. These public patterns were read on 2026-11-01. Competitor conversion rates/revenue and causal effects are not known.
3. Acceptance: all public canonical pages receive discoverable native-language tasks; search accepts household wording, excludes private pages, and sends no query text. Prove mobile/no-JS/error usability and full-build persistence. Verify live and existing IndexNow eligibility after release.

## Operating rules

- Start every proposal with an observed question, the intended country, existing URL, and evidence. Prefer improving an existing answer over a duplicate model/region page.
- Put the immediate answer and its applicability before detail. Explain when measuring, repairing or doing nothing is appropriate.
- Compare products at the same temperature, humidity, test method and model generation. Unknown facts stay unknown. Exact local seller, delivery and affiliate eligibility must be verified before a purchase recommendation.
- Reduce user effort with static examples and a small set of explicit choices. A calculator must explain its inputs, units, formulas and limits. Initial examples are not completed decisions.
- Reuse patterns, not another publisher's prose, images, ratings or unverified test claims. Include evidence and honest update dates.
- Every canonical page must be discoverable in the site index automatically. Curated need shortcuts stay in the exact content language/market; real translations alone get reciprocal hreflang. New aliases need reviewed relevance, not keyword stuffing.
- SEO: intent-matched title/description, canonical, indexability, sitemap and contextual links. GEO: readable factual answers, formulas and attributable sources; HTML/Markdown parity. Neither guarantees rankings or citations.
- Publish only within the existing daily source/demand gate. Insufficient new evidence means no expansion. Do not fabricate freshness or mass-notify unchanged URLs.
- Keep search terms local. Record fixed navigation actions separately from tool completions, merchant clicks and revenue. Respect opt-out, DNT/GPC, QA and private-page exclusions.

## This release

One progressive search interface replaces the two older search implementations after all generators. Static, reviewed task links cover DE, EN, NL, AU, FR, ES, IT and ZH where actual content exists. Four German category hubs expose relevant next tasks. The canonical index scans future directories instead of a hard-coded folder list, so generated tools are included. No new claims of demand, product suitability or merchant availability are introduced.

The first complete DACH observation window previously planned for Nov 2–15 is now a combined rollout baseline: this release overlaps navigation on those pages. Record actual verification time and use the first complete property day afterwards; never attribute effects to either rollout alone.

## Measurement and decision rules

- Primary acquisition: relevant country-specific organic landing sessions and active users over complete 14-day windows; review at 28 days. Keep sources and browser language distinct. User growth must come from real arrivals, not automated QA or extra events.
- Search exposure: Google/Bing impressions and clicks in their own source windows. AI citation and assistant-referral evidence are separate. No source access means unknown.
- Utility: `eco_discovery_open`, `eco_discovery_task`, `eco_discovery_result` are once-per-page navigation events. They do not define unique users, clicked sessions or completed tasks; no event/user conversion formula.
- If impressions are scarce, investigate crawl/indexing and relevant external discovery; if arrivals exist but choices are unused, revise the entry; if tools are used without merchant hand-off, check actual fit. Commission requires readable matched merchant data, shipped/approved status, refunds, currency and attribution window.
- Windsor currently returns a plan/account-limit placeholder instead of real data (Nov 1). Do not ingest the placeholder zeros. No subscription or account disconnection is authorized by this task.
- No randomized A/B is launched on current small traffic. Once a stable baseline permits a pre-specified sample-size calculation, test one entry-copy variable with fixed assignment, power/MDE and stopping rules. Two full 14-day windows are an operating review cadence, not proof of significance.
