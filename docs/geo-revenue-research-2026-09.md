# AI 数据站与 GEO 变现:第一方读数下的裁定(2026-09-09)

owner 原话:「先完善prompt再执行，如果内容消费是永恒的主题，那么构建一个ai数据站，
是否价值最大？ai最终导流geo，这块如何利用突破geo，实现创造营收？」

**一句话结论**:「内容消费永恒」成立,但**消费者已经换人了**,而换来的这批消费者
在本舰队 90 天的实测里**付得更少不是更多**——AI 助手送来的读者转化 **6,1%**,
搜索引擎送来的读者转化 **21,8%**。所以「建一个 AI 数据站」不是价值最大的动作:
舰队三个月前就把它建完了(llms.txt / MCP / markdown 镜像 / CC BY 数据集 / for-agents),
今天第一次量出它的产出是 **€0,17 / 90 天**。

**但这不等于 GEO 没价值。** 本轮量出的四段链路里,只有一段是「大站级」的:
agiscorecard 在判定型通用问题上拿 **33–37,5% 的引用份额**,而全站真人读者约 44/日。
引用是舰队唯一一个**与流量脱钩**的资产。它今天卖不掉,不是因为它不值钱,是因为
**买方市场还没开门**(Cloudflare 按答案付费 2026-07-01 才宣布、闭beta;ProRata/RSL
按归因分成但没有公开费率)。

**因此裁定:GEO 是期权,不是渠道。** 正确的持有方式 = 成本压到零、可见度做到最大、
把仪表建起来、在按答案付费的市场开门时第一批进去。**今天为 GEO 写新页、开新站、
加新基建,一律负收益。** 本轮据此只建了一件东西:一台把引用翻译成欧元的仪表。

### ② 仪表盲区(本轮最值钱的发现,已修)

## 四、裁定

### Q1:「构建一个 AI 数据站,是否价值最大?」——**不是。它已经建完了,产出是 €0,17/90d。**

「内容消费是永恒的主题」这个前提成立,但它推不出「所以要建 AI 数据站」。三条理由:

1. **舰队已经是 AI 数据站**:llms.txt(26KB)、公开 MCP 服务器、逐页 markdown 镜像、
   `data.json` / `invest-data.json`(CC BY 4.0 原创数据集)、`/for-agents`——五站都有。
   再建一个,是把已经零收入的形态**再复制一份**(根 CLAUDE.md 已把「先复制壳」列为杀单)。
2. **机器面的消费方还没出现**(§三⑥):四周实测可归因助手用量 = 0。
3. **开新站/新子域另有三条铁律**(独立技术形态 + 完全不同受众 + 自带变现闭环),
   「GEO 数据站」一条都不中;2026-09-05 已裁定「新子站是稀释不是杠杆」,本轮无新证据推翻。

**那什么价值最大?** 按台账,未来一个月能改变收入的只有三件既有的事:
① Metaculus 额度到手后打开(唯一不靠流量的现金路径);
② eco 三条判定线(US 切换 09-25、分体机簇 09-28、湿度活数字 09-28)如期结算;
③ 把 GEO 的**维护成本压到零**并保住可见度——本轮交付的就是这一条。

### Q2:「ai 最终导流 geo,如何突破 geo 实现营收?」——**别在第 3 段用力,那段是产品设计。**

链路四段,本轮把每段的现状都量出来了:

```
①被抓 1067次/28d(bpj) → ②被引用 564次/30d、份额 33–37,5%(agi) →
③送回真人 19–34 pv/28d(占各站 1,6–3,1%) → ④转化 6,1%(搜索是 21,8%)
```

- **②→③ 漏损一个数量级**:这是答案引擎的产品设计(zero-click),不是站点缺陷。
  任何 GEO 手法都改不动它。**「多写判定页 → 更多引用 → 更多流量 → 更多收入」这条
  因果链,在第三个箭头上断了,而且断在结构上。**
- **③→④ 比基线还差**:再多的 AI 流量,单位价值也低于搜索流量。
- **唯一还有算术空间的是 ②本身**:引用是舰队唯一一个「大站级」的指标。
  **564 次/月的引用,只要有人按 €0,05/次 付钱,就是 €28/月——超过 eco 整条 Amazon 线。**

**所以突破口不是「把引用变成点击」,而是「进入按答案/按归因付钱的市场」。**
这类市场 2026 年确实出现了,但都还没开门到本舰队这个量级(§五)。因此本轮的正确动作是
**建仪表 + 零成本占位 + 预登记判定线**,而不是建产品。

## 五、按答案付费的市场:现状与本舰队能做的

| 机制 | 机制是什么 | 现状(2026-09-09) | 本轮动作 |
|---|---|---|---|
| **Cloudflare Pay Per Crawl** | 站长自定价,爬虫带支付意图拿 200 或收 402;Cloudflare 做 Merchant of Record | **闭 beta**,需 signup 表或 Enterprise AE(官方文档,更新于 2026-07-28) | owner 1 分钟填表**排队**;**永不启用定价**(见下) |
| **Cloudflare Pay Per Use(按答案付费)** | 2026-07-01 宣布:内容**出现在答案里**才付钱,不再按抓取付 | 「2026 年晚些时候」广泛可用,**无具体日期** | 盯;由 Pay Per Crawl 的排队自然衔接 |
| **ProRata / Gist Answers** | 订阅与广告收入 **50/50** 分成,按**归因份额**分配 | 已运营;**每次引用的美元数未公开** | owner 5 分钟提交出版商申请(免费) |
| **RSL / RSL Collective** | robots.txt 里声明许可条款,含 **pay-per-inference**;50+ 伙伴(Reddit、Yahoo、Medium、O'Reilly…) | 2025-09-10 发布;**目前主要是「请求」,强制执行需 CDN 配合** | **不动 robots.txt**(见下);先看 Collective 是否给本量级站点付款路径 |
| **Perplexity Comet Plus 出版商池** | 出版商分成池 | 2026-09-05 已备好邮件草稿,**owner 尚未发** | 沿用 09-05 判定线:发信 +60 天无回复归档 |

**为什么「排队但永不启用定价」不是自相矛盾**:

- 给引用爬虫定价 = 它们收到 402 = 不索引 = **引用份额归零**。舰队的保险丝
  (根 CLAUDE.md:「引用队列爬虫任何时候不设价不屏蔽」)优先级更高。
- 用自己的数字算一次天花板:即使按 **$0,10/次**这个没人同意过的激进价,
  bpj 那 1 067 次引用爬取也只值 **$106,70 / 28 天**——**代价是那个站的全部 AI 可见度**。
  而按答案付费**不需要交出可见度**:同一份内容既被引用、又被计价。
  **两者不是一回事,舰队要做后者的卖家,永远不做前者的卖家。** 这条以本轮的
  1 067 与 564 两个第一方数字为依据,写进根 CLAUDE.md。

**2026-09-15 的外部变更(6 天后)**:Cloudflare 起将默认拦截「混用型」爬虫(把训练/代理
用途与搜索用途混在一个 UA 里的),范围据报道是**带广告的页面**,并适用于新客户、
新站点与现有免费计划客户 [thin,一手页在本会话沙箱不可达]。
**本舰队的暴露面已核**:`grep adsbygoogle|googlesyndication` 全仓 **0 个文件**——八站
都没有广告位,按「带广告页面」这条口径不适用。但免费计划那条口径在转述里含糊,
所以**本轮把它变成自动熔断**而不是备忘录:heartbeat 每天检查五家引用爬虫,
任何一家超过 10 天没来就把 run 打红 → owner 收到 GitHub 失败邮件。
