# 交易型商业与新站：三轮对抗执行记录

2026-09-18 · Owner 扩大范围后的最终决策稿 · 已完成本地代码与模拟链路，未发布、未收款、未进行访谈

## 这次改变了什么

前一轮被“旧站已有资产”和“容易实现”牵引，过早把厂商人工核实当成主线。这个判断已撤回。大市场不应因为难做就被排除；但建一个外观像 Alibaba 或 B.ai 的网站，也不等于拿到了它们的供给、客户、结算能力与毛利。

本轮按 ECC 优化后的任务，比较外贸、股票相关、Web3、AI 调用与按结果交付。优先开发的新站为 **LocaleBatch：面向商家/代运营的第三语言商品 CSV 批处理**。这是优先实验，不是已经证明最容易赚钱的行业。选择理由是付费者已在经营商店、输入和交付可以限定、无需等待双边供给、同一处理与支付引擎能复用于后续任务。真实购买、质量、获客成本和复购仍未知。

这三轮是连续的证据审查、经济压力测试和程序测试；不是三个独立专家意见，也不是已经跑了三轮市场 A/B 实验。所有新站代码位于 `sites/localebatch/`，没有使用现有广告的付款链接。

## 第一轮：找付款机制，然后用需求与替代品反驳

| 对标与可取机制 | 已核事实 | 最强反方与此次取舍 |
|---|---|---|
| 外贸：Alibaba.com | 官方卖家页以会员、RFQ 报价机会等获客能力收费，页面标示 0% commission；不能把它概括为每笔外贸订单抽佣。见 [卖家页](https://seller.alibaba.com/pricing)、[RFQ](https://seller.alibaba.com/rfq)。 | 小平台没有活跃买家时，供应商会员很难卖；没有信任与履约信息时，成交金额也不能算平台收入。保留“跨境商家的重复任务”作为单边入口，暂不做通用供应商撮合市场。 |
| 交易软件：TradingView、Alpaca | [TradingView](https://www.tradingview.com/pricing/) 销售图表、提醒等软件能力；页面 Essential 为按年计费折合 $12.95/月。[Alpaca Broker API](https://docs.alpaca.markets/us/docs/about-broker-api) 围绕开户、资金和交易提供经纪集成。 | 股票信息工具、交易记录工具和真正的交易执行是三门不同生意。已有金融门户有强免费供给；我们没有核实可再分发的数据、经纪合作或付费交易用户。保留软件/数据服务候选，不在本轮用一个下单按钮冒充交易平台。 |
| Web3：x402 | [Coinbase 文档](https://docs.cdp.coinbase.com/x402/welcome) 描述按请求付费与验证结算，适用于人或 Agent 购买 API/内容。 | 它解决收款流程，不自动带来买家；调用数也不是独立付费客户。可成为同一结果 API 的后续支付通道，不能先加钱包就宣称发现需求。 |
| AI 基础设施：B.ai、OpenRouter | 已打开 [B.ai](https://b.ai/) 的实际渲染页面，核实多模型调用、加密支付及 Agent 结算定位。[OpenRouter](https://openrouter.ai/pricing) 当前 Standard 标示 5.5% 平台费，另提供统一调用与路由。 | 我们没有取得其净利润、CAC 或真实增长率；B.ai 宣传的价格优势不能当作可套利的采购合同。纯转售只有很小一段费用空间；高用量客户仍可能成立，不能一概否定。 |
| 垂直 AI 结果：商品批处理 | [Shopify 官方应用](https://apps.shopify.com/translate-and-adapt) 自动翻译两种语言免费；页面的商家评价明确提出两语言限制。[官方说明](https://help.shopify.com/en/manual/international/localization-and-translation) 支持按固定字段导入翻译 CSV。 | 这只支持具体任务与限制，不证明会购买我们的 €19 批次。免费翻译、第三方 Shopify 应用、ChatGPT 和自建脚本都构成强替代。必须交付完整文件与可检查的差异，而非只卖一段提示词。 |

**推翻了一个已经接近开发的想法。** [采购讨论](https://www.reddit.com/r/procurement/comments/1mr3p0x/better_way_to_compare_supplier_quotes/) 中确有 PDF、表格搬运与格式不一致的困扰，也有人建议让供应商填写统一模板。另一个 [硬件采购讨论](https://www.reddit.com/r/hwstartups/comments/1q9wxw6/early_test_tool_to_compare_supplier_quotes_for/) 的评论者自述投入定制软件后仍返回表格，甚至很难让同行免费试用。不能独立核实其经历，但它是强反例，不应被过滤掉。

进一步打开 [Accio](https://www.accio.com/) 实际页面，发现其已覆盖电商运营、产品与供应商搜索等任务，并宣传报价整理。企业自述不是独立效果证明，但足以否定“通用 AI 采购还没有竞争者”。因此没有继续把一个通用报价表格工具包装成高把握新业务。

社区证据分层：采购求助帖支持任务存在；产品测试帖及厂商推广不计独立买家；采购评论支持反证；Shopify 商家评价支持功能限制痛点；所有这些都不计为我们的付费承诺。搜索中出现的无关结果未计入研究。

**本轮决策变化：** 厂商人工审核 → 外贸报价软件候选 → 被免费表格与 Accio 反驳 → 选择一个商家可独立购买的有边界交付。股票与 Web3 没有被认定“不能赚钱”，只是尚缺使其优于本实验的用户与运营证据。

## 第二轮：把流水、净收入、利润与人力分开

新增可运行模型 `tools/fleet/profitability.py`，共 14 组情景。全部价格、转化、退款、CAC 和人工输入均为可修改假设，不是竞品实测数据或支付渠道报价。金额以欧元、不含增值税口径计算；所得税未计入。“经营余量”已扣支付、退款、模型/服务成本、获客现金、交付/客服/获客工时及固定维护，仍不是税后利润。

新增两项容易使撮合业务误判的计算：**平台收入 = GMV × 费率**；支付费可能按全额 GMV 扣，也可能只由平台承担服务费部分，必须分别建模。模型调用的失败和退款订单仍可能有成本，不随销售退款自动消失。

| 假设情景 | 单位贡献，计入人工 | 月 €1,100 经营余量所需单位 | 判断 |
|---|---:|---:|---|
| LocaleBatch €19 基准 | €9.505/批 | 143 批 | 条件是退款 5%、模型完整尝试 €1.20、平均 1.15 次、获客现金 €3、客服与获客合计 6 分钟/批 |
| LocaleBatch 压力 | -€9.36/批 | 无解 | 退款 20%、两次尝试、获客 €8、人工 25 分钟时，扩量放大亏损 |
| LocaleBatch 复购渠道假设 | €14.135/批 | 96 批 | 依赖更低 CAC、返工和客服；不是已建立的代理商渠道 |
| 外贸 €1,000 GMV、5%费率、平台承担全额支付费 | -€48/笔 | 无解 | 本情景另假设 90 分钟总工时，说明“交易额大”仍可能亏损；不代表 Alibaba 的真实成本 |
| AI 客户每月 €100 用量、5%平台费，仅平台费承担支付成本 | -€0.325/客月 | 无解 | 小客户、低费率很容易被获取与支持成本吃掉 |
| AI 客户每月 €1,000 用量、5%平台费，同样只按平台费扣支付成本 | €31.25/客月 | 44 客月 | **保留的大机会**：高用量客户可以改善经济性，但尚无这 44 位客户，也未确认这种结算结构 |

€19 基准的月固定经济成本假设为 €250（现金 €10 + 8 小时 × €30）。若只看退款后、不含税收入，€110 需 7 批，€1,100 需 61 批；若看计入人工的经营余量，则分别需要 38 与 143 批。143 批在假设 3%“合格报价访问→购买”下需要约 4,767 次合格访问，月人工约 22.3 小时。这些访问不是普通 PV，更不能用爬虫请求替代。

当前 BPJ 的诊断快照仅有 331 次带 referrer 的 JS 页面浏览，口径和合格报价访问不同，不能说加一个入口就有上述规模。必须检验新的分发渠道。也不能将 AI 高用量客户情景的 44 个客户误称为比 143 个批次一定更容易获得。

**本轮决策变化：** 取消“低价抽佣自然规模化”的推论；保留高用量 AI 基础设施机会，首个实际产品按有边界的批次交付。只有在重试、支持和获客都受控时，代码自动化才可能转为盈利自动化。

## 第三轮：实现产品，再攻击输入、收费与交付

已创建 `sites/localebatch/`，包含工作台、免费检查器、固定完整样例、导入指南、隐私/实验条款、价格状态、任务恢复界面以及 Cloudflare Worker/D1/Queue 后端。不是只有落地页。

1. **输入到输出**：CSV 解析，保留长整数 ID 与原始字段；拒绝重复键；保护品牌、数字和模板变量；只有通过结构检查的结果才可进入导出。HTML、现有译文与不支持字段保持原样。导入文件与电子表格安全检查文件分开。
2. **收费到执行**：新产品专用 Stripe Checkout；服务端固定价格与币种；验证回调签名或从 Stripe 读取付款状态，回跳 URL 不授予资格。报价不匹配、未付款、其他产品的付款不能解锁。
3. **自动交付**：D1 保存不可变输入和任务状态；Queue 在用户关掉页面后继续；每行最多两次尝试，调用前保留预算；活跃租约阻止重复调用，中断仍记成本。只有真实配置后才调用模型。
4. **退款与恢复**：随机恢复密钥、服务端只存哈希；七天全额退款请求、幂等处理、退款状态更新；过期访问拒绝，30 天删除；队列与退款异常仍需运营监控，未声称完全无人值守。
5. **开售门槛**：缺支付、模型、队列、真实经营信息、价格上限、清理任务或质量复核时，后端关闭收费路径。公开样例明确是固定数据，不冒充实际 AI 输出或客户案例。

程序测试覆盖付款金额/产品不符、伪造签名、重复支付/任务、预算耗尽、模型失败、长 ID、数字缺失、越权读取、恢复和退款等。模拟链路使用真正 SQLite 执行 SQL，外部 Stripe 和模型接口为替身。具体测试结果和后续修正见 `docs/review/transaction-validation-2026-09-18.md`。

反方仍成立：检查数字并不等于翻译正确；模型可产生错误语义或非数字的新承诺；第三语言需求不等于足够高的付费意愿；按批次购买没有自动形成续费。当前没有真实 provider 输出评测、Cloudflare staging 验收或 Stripe 测试账户实测。云端浏览器安全策略拒绝本地预览，未绕过，视觉与移动端验收仍待完成。

**本轮决策变化：** 扩展范围不等于立即支持一切。先限定文本字段，保证失败可见、预算可控、不能无款调用；不把复杂 HTML、商品事实生成或自动写入店铺混进初次付费承诺。交付的核心和后端已实现，生产资格尚未通过。

## 从 €11 到 €110、€1,100，再到可复制的业务

目标从首次公开有效实验开始计时：14 天争取 3 位无关联真实付费者；60 天组合近30日退款后净收入 €110；120 天 €1,100，并连续两个30日窗口计入人工后为正。进一步争取 €1,100/月经营余量，是更高门槛，不与收入目标偷换。这些是经营目标，不是时间预测；尚未发布，时钟没有启动。

| 阶段 | 已准备的资产/动作 | 通过条件与失败后的行动 |
|---|---|---|
| 找到第一个交易 | 免费 CSV 检查器、完整演示、明确 €19 报价、导入指南和付费交付后端 | 至少3个无关联付费者，提供真实文件且能完成实际导入；零订单时不复制新域名 |
| 找到高频渠道 | 面向管理多个店铺的服务商定义批次交付；准备已有 BPJ 相关内容的发布后入口 | 必须测量来源、展示报价、支付、退款与第二次购买。至少两位不同买家再次购买；口头兴趣不算 |
| 达到正单位经济 | 每批记录实付、税、退款、支付费、模型账单、支持/获取时间 | 基准贡献约 €9.51 只是测算；实测负贡献时先改交付、价格或渠道，不投流放大 |
| 复制相邻任务 | 复用支付、任务、重试、恢复与导出组件 | 只新增一个有客户重复请求的 adapter，例如更多文本字段；HTML/其他店铺平台仍需独立质量验证 |
| 成为任务平台 | 有多个可靠 adapter、重复客户与可解释账单后，对外提供有版本的结果 API | 再考虑第三方供给接入、服务费和 x402 支付；当前未提供开放市场或链上结算 |

首轮分发候选是“Shopify translation CSV”“第三语言”“CSV 翻译保留 ID”等具体任务查询、商家/代运营的现有工作流，以及已有 BPJ 中确实相关的页面。没有伪造搜索量、社区发帖、合作伙伴或外链；新域名尚未部署，故没有把坏链接加到现有线上站。

独立实验台账已更新。到达不足与收费增量失败要分开：28 天少于100次合格到达，先检查分发；达到20位完成真实检查且看到报价的目标用户仍零付款，撤回当前报价/增量假设。3笔付款只是初始信号，不是统计上的市场证明。有人付费但不能导入或需要逐行人工重写，则暂停扩量。

Eco 已有历史确认佣金，保留此前工具与决策页扩展；但仍不能用历史约 €0.10/平台点击的比例保证100倍增长。BPJ 工具端暂无有效联盟配置，不把免费出站点击记营收。Learn、Goldrush 的旧实验保留，资源优先级由实际付款与贡献更新，避免每站平均分配工作。
