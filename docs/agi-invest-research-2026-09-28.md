# AI 股票投资线：三轮 Prompt 优化、研究决策与首轮实现

日期：2026-09-28。对象：`f-tiger/agi-site` 中的 `sites/agiscorecard` 投资入口。当前指令授权深化股票研究；本轮在既有 `/invest`、`/zh/invest` 完成一条研究任务，不新增域名。研究辅助的目标是提升判断质量；站点收入与用户投资损益分别计量。

## 三轮 Prompt 优化

**第一轮——把“AI 时代赚钱”变成明确任务。** 检查已有投资产品、数据、流量与订单证据；比较主动股票研究、指数基准、13F 跟踪、量化/AI 信号；确定谁在重复做什么研究、为什么会回来及为什么可能付费。交付代码和研究记录，而非一份概念清单。

**第二轮——对抗检查范围和方法。** 原请求没有区分产业增长、公司利润、股票回报、网站营收；不能把四者混为一谈。不能沿用历史上下文对股票子站位置的混淆。核对实际仓库后：主站是证据入口；SunWatch 在 `sunPredition`，Compass 在 `aistock`，Gushen 在独立仓库，FilingLens 已有财报数字工具和 MCP。拒绝再造通用股票数据 MCP。保留来源期间、披露日期、会计口径、反证、复查条件，任何回测都需检查数据当时是否可知。

**第三轮——对抗检查商业与验收。** 历史低流量不证明没有需求，竞品价格也不证明本站能卖。原计划若直接推出付费提醒，会把未实现能力包装成产品；改为先交付免费可重复研究记录，沿用独立现有产品入口，不宣称自动监控该记录。既有商业判定线不改期，新工具事件独立命名，示例与自填区分。计算、无效输入、隐私、移动端、两种语言、保存/导出/导入、部署均需检查。

最终执行 Prompt：

> 审计 agi-site 股票投资线，用当前代码与真实流量定位问题，使用一手资料比较竞争工具和研究方法。保持原有品牌、中文浅色风格和独立子产品契约。在中英投资入口实现“产业链→披露事实→可证伪假设→盈利/估值情景→仓位压力→研究记录导出→复查”的完整流程。数据注明日期、期间、币种和来源；事实、管理层指引、用户假设分开。严禁以完整性、主题得分或历史回测代替胜率、真实利润或买卖建议。不连接券商、不新增付费模型、不擅自发营销消息。验证计算与边界、浏览器流程、机器可读内容和部署，提交可核验成果，分别报告已交付、未实现和商业待验证项。

采用方法：ECC prompt-optimizer（任务拆解与上下文缺口）；market-research（官方证据、反证、可证伪商业门槛）；frontend-design（沿用中文 Swiss 视觉约束，工具按研究顺序组织）。未声称多模型或独立团队评审。

## 好的方法如何落进产品

1. **先分产业受益与股票回报。** 算力/网络、存储/制造、电力/散热、云平台、应用软件分别核对不同指标。行业高增长不自动推出利润高增长，利润增长也不自动推出股价上涨。分类是研究框架，不是机会排名。
2. **一手证据、相同口径。** 用公司披露/SEC 原文核对，不把云收入都当 AI 收入、不把订单或指引当已确认收入。首批教学快照是 NVIDIA FY2027 Q2 数据中心收入 $89.0bn 与 Microsoft FY2026 Q4 Microsoft Cloud 收入 $59.3bn；均不是当日行情。它们不在同一财政期间，不直接作横向增速排名。
3. **估值敏感性而非目标价。** 借鉴 [Damodaran 的现金流/估值假设框架](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/valquestions.htm)，此处仅实现可复核的正 EPS×P/E 恒等关系，未实现完整 DCF。20% EPS 年增长、3 年、40→25 倍，对应累计盈利 +72.8%，价格仅 +8%。这是虚构计算例，不是任何公司的预测。
4. **预登记反证。** 写清什么观察会改变判断、在哪天复查。字段齐全只说明完成记录，绝不评分为“优质/看多/高胜率”。AI 导出指令先核来源、寻反证、标未知；工具本身未调用模型。
5. **组合而非单票幻觉。** 仓位×价格冲击，并同时考虑其余资产下跌；参考 [FINRA 分散投资说明](https://www.finra.org/investors/investing/investing-basics/asset-allocation-diversification)。压力结果是给定假设的算术，不是最坏损失上限或建议仓位。
6. **信息时点纪律。** [SEC 13F FAQ](https://www.sec.gov/divisions/investment/13ffaq)说明季度申报滞后和股票空头不披露。发现旧页面“申报日收盘价是真人能买到的价”过强：盘后披露时这仍是前视偏差。已更正本次中英入口表述，旧收益旁加限制；独立 aistock 回测引擎本轮未重算，历史收益没有因此获得验证。Q3 2026 申报截止是 **11-16**，不要误写成 11-15；原商业复盘日期保持原样。

方法比较：指数/分散组合适合作为同窗基准；主动基本面研究需要估值与来源；13F 是滞后快照而非完整组合；趋势规则需要前瞻、成本后的对照；LLM 适合抽取/质疑/结构化，不能因为能写报告就宣称有交易超额。现有纸面台账保留，不用本轮计算器替代实盘或前瞻实验。

## 变现路径与停止条件

优先买家假设：会反复跟踪少数 AI 相关上市公司的独立研究者。可能付费的增量是来源变化核验、持久历史和可复查提醒，不是“AI 推荐股票”。当前没有访谈或付款验证。

本轮免费工作台→下载自己的研究记录→重复复查→在现有独立产品查看记录/条款。FilingLens 承接数字溯源；SunWatch 只承接用户明确选择的现有服务，**不会自动跟踪本研究表单**。不展示尚未建成的新产品价格，也未改付款、TG、账号或券商设置。

- 先观察 28 天窗口或 100 次相关页面浏览器访问。流量不足：渠道未验证，不宣布需求失败。
- 观测 `invest_tool_click`，location=`research_<en|zh>_<action>`，label=`sample|own`。工具事件需主动勾选；QA `__qa=1` 不发工具事件。页面原有统计独立存在。输入、公司名称、来源 URL、研究正文和数字都不进入工具事件。
- `own`导出达到 10 次只是任务信号，不是 10 位用户或付费需求。重复使用需另外通过真实反馈核验；无身份事件不能算留存。
- 继续收费功能建设前：至少 3 位独立同类用户用真实任务复查两次，比较原有表格/AI工作流后的准备＋校验总时间，确认愿意付费的具体增量；获得合法授权后再开展这些测试。本轮未联系任何人。
- 付费成功以已收款、交付后正贡献、退款后净收入、实际续费计。假设每位净月收入 ¥99，则 ¥1,000 需 11 位、¥10,000 需 102 位；这只是算术，不是上线价格或营收预测。数据授权、模型、客服、支付、税、获客和固定成本均需另计。
- 若用户主要要实时买卖信号，或表格＋现有工具同样容易，则本切口未成立，不继续添加相似计算器。既有 10-29/11-15 复盘线保留，新模块影响本页行为，前后不是随机对照实验。

## 实现与验证范围

已实现：中英现有页面嵌入研究模块；静态一手数据卡；假设与反证记录；EPS/P-E、组合冲击、回本算术；本机保存/恢复/删除；JSON 导出导入；Markdown AI 复核文档；显式示例/自填模式；可嵌入版；工具入口、WebApplication、sitemap、feed 和机器可读来源。静态数据不会假装自动刷新。没有新增 cron、外部消息或付费 API。

未实现：站内大模型、自动研报、实时行情、自动提醒该记录、付费云工作区；独立子仓算法未改，历史回测收益未重新核验。不能说已经帮助用户赚到钱。

验证：确定性数学与非法输入单测、双语浏览器端完整流程、移动端溢出、嵌入、导出/导入/存储、匿名事件边界，外加原站 validate/hreflang 与部署 CI。实际部署状态由 GitHub Actions 结果确认，不以本报告替代。
