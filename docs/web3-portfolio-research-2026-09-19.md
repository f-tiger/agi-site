# AI × Web3：剩余十个方向的竞对研究与首版上线方案

研究日期：2026-09-19。范围：用户明确要求“其他的几个完成调研，完善竞对分析打造竞争力，然后都上线”。既有 Agent Delivery Lab 继续运行；本轮交付十个独立工具子站及统一入口。本文区分官方产品事实、我们的判断、尚未验证的商业假设。

## 本轮完善后的执行 prompt

在 f-tiger/agi-site 中完成既有 Web3 研究的剩余方向。逐项明确用户、任务、直接竞对、免费替代、供应链依赖、真实差异、反证和收费前提。用一手资料核对现有产品能力，不把 AI、上链或新域名当作竞争壁垒。每个方向交付能使用自有材料完成一次任务的首版：输入、处理、可检查的输出、错误处理、示例、方法、隐私与适用边界。实现可复算算法和供 AI 工作流使用的数据合同；不得声称发明了未经论证的新密码学算法。复用已授权的域名与部署系统，验证全部子站，保留已有项目。报告必须列明各站 URL、实现范围、验证证据与尚未成立的商业结论。用户已授权本轮全部上线，无需再次确认。

## 决策结论

十个方向全部上线免费首版，以独立任务页验证不同人群。后续投入优先级是 **对账、任务证据、采购路由**，其次是许可与算力；其余以小工具观察。此顺序是基于任务频率、输入可获得性和维护成本的产品判断，不是测得的市场规模或收入排序。

首版共同实现：本地表单与 JSON 输入、真实计算、异常说明、JSON 报告和手动复制、同引擎离线 CLI、虚构示例、竞争替代说明、来源和中文上手指南。Protocol Ledger 额外提供可调用的免费 GET API 与 OpenAPI 合同。数据默认留在浏览器；主动反馈只提交枚举选项，不提交业务材料。

**竞争力目前属于待验证的切入点。** 所用固定点计算、Wilson 区间、有限枚举和有上限的比例分配均为已知方法的产品化组合。没有独家模型、授权专有数据、真实客户数据网络、审计认证、受控性能实验或已经证实的护城河。AI 的当前作用是帮助用户按严格合同准备输入，以及让输出进入自己的 Agent 工作流；站内没有接入模型，也不凭空生成事实。

## 逐项竞争分析与投资条件

### 1. Stable Reconcile — 稳定币收款对账

- 用户与任务：小型服务商、机构财务人员；将已导出的应收单与交易记录核对，找到少付、多付、拆分付款、错误链或资产及待确认记录。
- 竞对事实：[Request Finance](https://www.requestfinance.com/pricing) 覆盖财务支付工作流，Growth 在研究日标示为按年付费每月 250 美元并包含自动对账；[Cryptio](https://cryptio.co/) 提供机构数字资产会计、对账和 ERP 工作流。免费替代是电子表格与脚本。
- 差异与取舍：上线版突出异常审阅、精确小数金额、本地处理和透明分配规则。不能与它们的连接器、审批、团队审计链竞争；需人工准备记录，可能抵消省下的时间。
- 算法：以发票 ID、链、资产精确匹配；固定点整数求和；pending/reverted 不结清发票；重复事件 ID 拒绝，错链错币单列。
- 后续商业假设：重复月结中的异常历史、连接器与协同复核可能付费。当前不收款，不声称已有需求。
- 证伪：用三个独立真实月结数据集比较“准备输入＋复核”总时间、异常召回和误报；若比现有表格更慢，停止订阅开发。历史数据需由自愿参与者提供，不以抓取钱包替代授权。

### 2. Agent Evidence — 任务证据与信誉输入

- 用户与任务：采购 Agent/API 服务的集成团队；针对特定任务和版本评估供应商的验收证据。
- 竞对事实：[8004scan](https://8004scan.io/) 已有 Agent 发现、排名及生态信号；[Promptfoo](https://www.promptfoo.dev/docs/intro/) 已能本地/CI 运行评测、断言和安全测试。[ERC-8004](https://eips.ethereum.org/EIPS/eip-8004) 当前为 Draft，规范本身提醒未筛选反馈的 Sybil/spam 风险，注册不能证明能力真实。
- 差异与取舍：对导入结果做样本去重、版本隔离、过期过滤、关系声明与不确定性展示。免费替代是 Promptfoo 输出加 notebook。上线版不运行 Agent，不验证评审身份，也没有真实信誉数据库。
- 算法：按任务/版本/日期筛选；同 provider/sample 合并，冲突保守计失败；给出描述性 95% Wilson 区间。重复标签与声明独立并不能证明统计独立，区间不能当成功率保证。
- 商业假设：有独立任务夹具、被核验的评审和长期版本历史后，采购证据管理可能收费。
- 证伪：在保留的任务批次上与原始均值比较采购决策，核查是否有减少误选且可解释的改善；没有改善则保留免费报表功能。

### 3. Route Lab — 预算约束的服务采购路由

- 用户与任务：按次调用付费服务的 Agent 集成者；在尝试之前确定候选、回退顺序、最坏费用和延迟上限。
- 竞对事实：[OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection) 支持供应商路由、价格约束、性能偏好和回退；[LiteLLM](https://docs.litellm.ai/docs/routing) 已支持路由、预算策略、冷却、重试和回退。预算控制并非本项目发明。
- 差异与取舍：面向可手工复算的采购计划，输出每条可行序列的假设、最坏费用和期望值，不要求更换网关。免费替代是脚本枚举。没有在线调用、真实质量预测、支付或网关集成。
- 算法：最多八个候选、三次不同供应商尝试；有限枚举，以固定点整数过滤最坏费用，再检查最坏串行延迟与用户给定的最低成功概率。期望值依赖独立失败假设，共同故障会使它失真。
- 商业假设：只有连接真实任务结果、相关失败分组和实时价格后，策略审计及历史对照才可能值得付费。
- 证伪：固定回放集比较现有 OpenRouter/LiteLLM 配置的成本、成功率、尾部延迟；不能只拿虚构概率与最便宜单模型比较。

### 4. Protocol Ledger — 给 Agent 用的协议资料 API

- 用户与任务：需要有来源、版本、日期和边界的协议资料的开发者与研究 Agent。
- 竞对事实：[The Graph](https://thegraph.com/docs/en/) 提供索引与链上数据查询基础设施；[Dune](https://docs.dune.com/api-reference/overview/introduction) 提供查询/API。它们的数据广度、基础设施和实时性远超当前编辑快照。直接阅读官方规范是免费替代。
- 差异与取舍：首版五个窄范围资料记录，覆盖 x402 v2 exact EVM、ERC-8004、ERC-20/721/1155；保留官方来源、原核对日期和过期状态；JSON API 与 OpenAPI 可实际访问。资料字段是编辑摘要，不是完整 schema、兼容性认证、实时索引或付费数据源。
- 商业假设：经证实有人持续依赖后，差异通知、版本迁移夹具、变更审核才可能收费。
- 证伪：核查是否有至少两个独立工作流持续调用且因资料更新采取行动；仅有爬虫请求不构成客户。30 天未核对显示 stale，不伪造新日期。

### 5. Data Permit — AI 数据许可与分成检查

- 用户与任务：正在组织 AI 数据协作的运营人员；在正式执行前检查自己记录的使用目的、地域、撤回、期限和拟议分成。
- 竞对事实：[Vana](https://docs.vana.org/) 提供权限、身份、文件、支付与 SDK 等数据协作组件；[Ocean](https://oceanprotocol.com/) 提供数据资产/访问控制及 compute-to-data。直接替代是合同台账或数据治理系统。
- 差异与取舍：无需先发行数据 token，就能查看拟议用途与已录入 grant 的冲突，并保留收入分配余量。没有认证授权人、法律判定、数据交付或权限执行。
- 算法：按声明字段匹配、过期/撤回/用途冲突剔除；以 bps 和固定点金额计算分成；不合格份额留在未分配池，不暗中挪给其他人。
- 商业假设：只有真实 grant 版本、撤回执行记录和完整来源链后，协作审计功能才可能收费。
- 证伪：选取已由专业人员判断的固定案例，检查错误放行与误拒绝；任何字段匹配都不能作为合法许可的替代。

### 6. Compute Lens — AI 算力的有效产出成本

- 用户与任务：选购算力的小型推理/训练团队；对同一工作负载比较合格输出的成本。
- 竞对事实：[Akash](https://akash.network/) 已提供算力市场与部署路径；[Runpod](https://www.runpod.io/pricing) 列示多类 GPU 和独立存储费用。供应商首页价格不是同负载受控实验，不能直接当性能结论。
- 差异与取舍：把设置时间、失败尝试、存储和出站费用纳入用户实测数据的成本表，以合格结果做分母。表格、供应商计算器和自建 benchmark 都是替代。没有实时库存或代购部署。
- 算法：按工作负载、模型标签、币种、显存与最低质量过滤；零合格结果成本不可估，不写成零；对输入费用做透明算术估算。
- 商业假设：可复现实验夹具、跨供应商基准和历史价格才可能形成后续订阅，而非当前的通用计算器。
- 证伪：至少两个供应商同一输入集/权重/量化/区域的实测，验证结论是否在冷启动、失败重试与出站后仍成立。没有实测就不贴真实供应商“最便宜”标签。

### 7. Incentive Lab — 去中心化 AI 激励的经济实验

- 用户与任务：设计计算/标注协作激励的项目人员；分清真实任务收入和外部 token 补贴，检查奖励是否超支及过度集中。
- 竞对事实：[Bittensor](https://www.bittensor.com/docs) 已有矿工、验证者和评分激励体系；[Gensyn](https://www.gensyn.ai/) 研究和构建可验证/可复现的机器学习与反馈激励机制。两者实际网络能力不是本地计算器可替代的。
- 差异与取舍：上线的是不发币的现金流与奖励沙盘；分列有机收入、补贴和奖励之后余额，要求验收任务数与质量输入。免费 notebook 同样能实现基础计算。
- 算法：验收数×质量权重，按预算分配，严格执行单人上限；使用整数余数分配，预算守恒；未发出部分保留。它不识别真实独立贡献者，也不解决串谋或 Sybil。
- 商业假设：有真实验收记录、抗作弊证据和协作方之后，激励审计可能有价值。
- 证伪：关闭补贴重算后若任务经济长期为负，不能用 token 涨价解释盈利；还需历史回放检验作弊是否比正常贡献更赚钱。

### 8. Proof Plan — zkML 工程预算与工件清单

- 用户与任务：准备部署 zkML 的工程师；基于实际测量检查成本、时延和模型/输入/验证键版本是否完整。
- 竞对事实：[EZKL](https://docs.ezkl.xyz/) 能将模型转成证明电路并生成/验证证明；[snarkjs](https://github.com/iden3/snarkjs) 提供实际证明工具。它们是底层实现，不是被本工具取代的竞品。
- 差异与取舍：上线版计算部署预算、SLA、证明体积，并整理固定工件 manifest；本地文件 SHA-256 仅帮助核对字节。它绝不生成或验证 ZK 证明。免费替代是工程表格和底层工具日志。
- 商业假设：只有真实框架适配、测量复现和项目交付服务后才考虑收费；当前没有“可信 AI 认证”。
- 证伪：在同版本、同模型实际部署中比较估算与账单；未计 L2 数据费、失败证明或队列就不能承诺成本与 SLA。

### 9. Call Lens — 钱包调用解释

- 用户与任务：手头已有 calldata，希望解释已知 token 调用的开发者和操作人员。
- 竞对事实：[Blockaid](https://blockaid.io/) 提供威胁情报和安全能力；[Tenderly](https://docs.tenderly.co/simulations/overview) 提供真实交易模拟及资产变化等结果。钱包模拟、区块浏览器与 ABI 解码脚本是免费/现有替代。
- 差异与取舍：本地显示目标、金额或 token ID、操作人授权和不支持状态；不需要连接钱包。ERC-20 与 ERC-721 的 approve selector 相同，必须使用用户声明的 token 标准，不能把 NFT ID 当授权额度。
- 算法：对支持的两参数 ABI 调用执行严格长度、padding、uint256 与 bool 解码；所有结果 securityVerdict 仍是 not-assessed。未知选择器不强行翻译，声明的标准本身未经链上核实。
- 商业假设：在可靠模拟/情报合作之后，企业审批记录才可能收费；解码器本身壁垒低。
- 证伪：已知恶意与良性样本上测量解释错误和遗漏，禁止将“成功解码”当作“安全”。没有恶意判断模型，所以不公布伪造准确率。

### 10. RWA Notes — 现实资产披露变化

- 用户与任务：整理资产发行方披露的分析人员；比较两份记录的数量、口径、日期和缺失字段。
- 竞对事实：[RWA.xyz](https://docs.rwa.xyz/home) 提供 RWA 数据平台及方法/API 文档；底层替代是发行人原始报告、电子表格与通用文档比较。当前没有同等数据覆盖或专业数据合作。
- 差异与取舍：保留两个时期来源与单位，对可比较数字算 delta，对币种/单位不一致、过期、未来日期和缺失数据显式报出。不是储备证明、审计意见、产品评分或投资推荐。
- 商业假设：真实源文件归档、字段血缘、持续更新和人工审核可能支持团队订阅；当前用户自行录入，未提供监控。
- 证伪：对固定的真实历史报告盲提取并人工核验召回、错误率及准备时间；缺失不能补成零，不同口径不能硬算增长。

## 可形成的组合价值与待验证“新模式”

可检验的组合是：Data Permit 记录准入条件 → Agent Evidence 整理任务质量 → Route Lab 规划尝试 → 既有 Delivery Lab 检查交付 → Stable Reconcile 复核收款 → Incentive Lab 对已验收贡献分配预算。Proof Plan、Compute Lens 和 Protocol Ledger 辅助工程决策；Call Lens、RWA Notes 处理各自的操作复核任务。

这是一种“交付证据驱动采购与分配”的产品假设。首版各站可独立运行，**没有宣称上述跨站链路已经自动集成**。真实价值应来自同一任务 ID、可核验交付、稳定输入合同、用户许可的数据历史与复用，而不是重复落地页、发行 token 或未经验证的全局信誉分数。

## 获取用户、维护与商业门槛

- 自有分发：统一 hub、各站互链、原有 for-agents 入口；每站提供可被引用的方法、示例、robots/sitemap/llms 和可下载 CLI。没有代用户发社交帖、群发邮件或购买流量。
- 渠道事实：仓库 2026-09-18 的 28 天 AI 引荐统计显示 AGI 主站 22 次，舰队合计 70 次；这是既有统计口径，不能推成新站访客或需求。2026-09-19 demand-digest 没有确认这些十个工作流的需求，多项社区源抓取失败。竞对存在证明供给与可能的预算类别，不证明本工具有人买。
- 维护成本：共享一个 Worker 与代码引擎；不新增数据库服务、计划爬虫或付费 API。仍使用现有账户配额，不能承诺零托管费用。协议资料需人工核对日期，定期维护尚未自动化。最大持续成本是来源核验、客户输入支持和真实连接器。
- 30 天首轮判定：每站在 2026-10-19 读取 /api/stats，排除 qa=1；自报自有材料完成且有帮助的提交 ≥5、重复任务 ≥3，仅触发进一步人工核实。随机提交 ID 不代表独立用户，“值得讨论”不等于愿付价格或付款。无相关触达证据则记 insufficient，不能直接判产品失败。
- 加大开发之前：核实至少两个独立团队在两个周期重复使用且较当前替代节省总时间；需要收费时单独确定真实可交付服务、成本、价格和验收。公开价格存在于竞对，不属于本项目收入证据。
- 暂停条件：无可重复任务、输入准备负担大于收益、来源无法维护、无法降低关键错误，或必须依靠未经授权的个人材料才能运作。保留工具/并入 hub 比继续扩建更合适。

## 验证与发布证据

本地：50 项测试覆盖十个引擎、输入边界、整数预算守恒、ABI 标准歧义、过期/冲突、Worker 路由、公开 API、独立反馈表；33 张 HTML 页面通过结构与内部链接检查。部署工作流会再次运行这些检查与 Wrangler dry-run。

生产验收：11 个主机都须返回本次构建的 revision；每站逐字节比对生成页面和全部共享资源；检查 JS MIME、错误路由、响应头、示例、隐私、指南、离线包；协议 API 对照仓库记录；提交明确 qa=true 的反馈并检查统计隔离。部署是否成功以工作流的最后验收步骤和线上结果为准，不以“已提交代码”代替。

UI 浏览器验收及实际部署结果记录于同目录的 `web3-portfolio-release-2026-09-19.md`。
