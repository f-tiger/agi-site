owner 原话：
> 「舰队各个站点配置每天自动化升级能力，避免不跑后就不更新了…网站内容都应该每天实时
> 刷新，按照德国或者其他国家的Google trends趋势，从趋势中优化网站。并执行geo，seo等
> 优化。你应该为每个站点设置一个更新算法，这个更新算法应该是网站自动运行的，算法应该

### 顺手挖出来的、比算法更值钱的三件事

1. **sitemap 的 lastmod 在撒谎（往旧了说）**。agiscorecard 的 211 条 URL 里 **60 条写着
   `2026-06-30`**；508 条 URL 分布在 6 个手打 sitemap 里。lastmod 是爬虫排重抓优先级的
   主要输入，把改动报成三个月前 = 自己把重抓请求撤回。
2. **fleet_trends_rising.py 的两个槽位在空转**（已确认已修）。eco-us（geo=US）与 eco-it
   （geo=IT）每天照抓照写，但 `fleet-trends.yml` 的提交步骤从来没 `git add` 过它们 ——
   数据随 runner 销毁，**20 个种子的轮转池里 4 个（20%）在空跑**，全池覆盖从 8 天拖到
   10 天，而且这两个槽位的 keep-last-good 永远是空的。run log 还把它们记成 `OK: n/7`。
3. **计划任务根本不准时**。260 次真实 run 实测：00:30–08:00 这一段的 cron **中位数迟到
   257–308 分钟**（最长 461），且 **2026-09-08 GitHub 整天丢掉了全舰队所有计划运行**。
   仓里每一句「03:45 抓完给 04:00 的循环读」现在都是假的 —— fleet-trends 实际落在 08:20，
   比 agi 的循环晚四小时。**任何依赖两条 workflow 先后顺序的设计都是坏的。**

## 二、算法：它做什么，和它为什么不写正文

`tools/autopilot/`，一条 workflow（`fleet-autopilot.yml`，每日 02:40 UTC），八站共用
一份算法 + 每站一个 `sites/<x>/autopilot.json`。

**它不写一个字的正文。** 这不是能力不足，这是这一层能在 AI 层死掉之后还活着的**全部
理由**：一个每天自动写句子的机器人是这支舰队能造出来的最危险的东西，因为舰队唯一的
差异化就是「这里的数字是真的、而且带日期」。它只做可计算的事实那一半。

### 五个阶段

**① 内容哈希记账（`ledger.py`）** — 这是整套东西的地基。
每天算一次规范化后的页面哈希；**哈希变了才把日期推到今天，没变就沿用台账里那一天**。
日期因此在结构上不可能比真实内容新 —— 它只能在字节真的不同的那天前进。

> **这里差点出一个大事故，写下来给后续会话。** 第一版我用 `git log -1 -- <file>` 做
> 引导日期，跑出来「60 条 URL 应该从 2026-06-30 改成 2026-09-06」，看起来是白捡的
> SEO。设计评审的 organic-growth 那一路把它否了，我复核后确认**他是对的**：
> ① 9 条 deploy 里 8 条用裸 `actions/checkout@v4`（depth 1），job 里 git 压根没有
> 单文件历史可返回；② 提交 `3fe8104`（2026-09-06「chore: record daily metrics」）
> **一次性新增了 2744 个文件**，其中 229 个是 agiscorecard 的页面 —— git 因此认为
> 它们那天被改过，那是一次仓库操作不是编辑；③ 本 clone 是 shallow 的（173 个提交，
> 到 2026-08-28 为止），更早的历史根本不存在。
> **照那版发出去，就是给 208 条 URL 盖上一个没人赚到的新鲜度** —— 正是这套台账被造
> 出来防的那种谎。
> 现在的引导值 = **sitemap 自己原来那个日期**（站点自己先前的公开声明），并夹到不
> 晚于今天。**第一天一个日期都不动**；从第二天起每一次真实编辑自动带上正确日期，永远。
> 慢，但是真的。

**② sitemap 外科手术（`sitemapfix.py`）** — 只改已存在 `<url>` 块里的 `<lastmod>` 文本。
绝不新增/删除 URL、不改 `<loc>`/`priority`/`changefreq`、不重排。清单是编辑判断，
lastmod 是可计算的事实，**autopilot 只碰事实那一半**。
`<loc>` 解析不到文件 → 原样保留并计数；超过 `max_unresolved` → **整轮失败**，不半写。

**③ 需求匹配（`demand.py`）** — 读已提交的 rising 文件（不发任何网络请求，所以**不
依赖任何别的 workflow 有没有跑过**，这是对上面「cron 不准时」那条实测的直接应对），
把词对着站内已有页面做词元重叠，分成 covered / gaps / off-topic，写成排序队列交给第②层。
- **按 seed 逐条卡时效，不按文件**。这些文件是累积的：buysomething 的 rising.json 一个
  文件里同时有 08-25 到 09-10 的种子，按文件卡最旧的那个会**扔掉 17 个新鲜种子**。
  （eco 的 rail 用 min() 是对的 —— 它要在页面上印**一个**"Stand" 日期，不能报高。
  队列没有单一日期要报高，每一行自带它那个种子的日期。）
- `v` 可能是字符串 `"new"`。来自 Google Trends 的 breakout 与来自**配额用尽后
  autocomplete 兜底**的 "new" 是两回事，靠 `source` 区分，**绝不混进同一个排序** ——
  否则一次配额中断看起来会像一波需求爆发。
- niche 词表守门：2026-08-29 实测 seed 太小时 Google 会拿全国热搜填充 related_queries
  （"akku staubsauger" 回来的是 belstaff / lululemon，分值还都在阈值之上）。

**④ IndexNow 只提交增量** — 今天内容哈希真的变了的 URL，别的一律不提交（全量重提
被 IndexNow 自己的 FAQ 判为垃圾信号，会贬值本站以后的提交）。key 从每站已经发布的
那个 `[0-9a-f]{32}.txt` 校验文件里读出来，所以这里没有要同步的密钥。

**⑤ 收据** — `data/autopilot/receipt.json`：做了什么、哪些信号是降级的、哪些被丢弃
及原因。**并且 `fleet-heartbeat.yml` 现在会断言这份收据不超过 3 天** —— autopilot
自己停了必须从那条「唯一不经过任何 AI 会话的告警通道」发出来，否则它停掉之后的十二天
看起来会和之前十二天一模一样（tds 的 D1 导出步骤连续十二天全绿却一次都没成功，就是
这个形状）。

### 自检能红（已用变异测试证明）
`tools/autopilot/selftest.py`，15 条全是红色夹具。2026-09-11 实测：
把 chrome 规范化关掉 → 第 4 条转红；把引导日期改成「盖今天」→ 第 1/2/4 条转红。
挂在 workflow 的**最前面**，不变式坏了就一个字节都不写。

## 三、这一轮没做的，和为什么

- **没做 bandit 重排序**（按实测点击自动调整页面上模块的顺序）。设计已经有了，但
  **喂不进数据**：8 个站里 7 个没有任何机器可读的已提交度量快照，D1 REST 导出卡在一个
  Cloudflare token 权限上（`Account · D1 · Read`），**三个 token 全试过，全是 403 / 7403**。
  在 5 个 pv/周的样本上跑排序优化不是算法，是表演。
  → **owner 一分钟动作**：Cloudflare → API Tokens → 那个部署 token → 加 `Account · D1 · Read` → 保存。
  导出代码早就写好、加固过、且已证明能连通（它是在鉴权处失败，不是连不上）。
  绕开它的路也已经探明：每个 Worker 用自己的 D1 binding 发一个公开聚合端点
  （buysomething 的 `/api/pop` 15 行就是现成样板，eco 有 `/api/top`），那条路一把密钥都不要。
- **goldrush 没有纳入**。它没有生成器、没有数据输入、没有 Routine，自 08-30 冻结。
  自动化救不了一个没有话要说的站 —— 每天在一个静态页上洗牌只会增加爬虫噪声和一个
  每天说谎的机会。**这是一道给 owner 的题：要么派人（AI 层）养它，要么正式退役。**
  它现在拿到了每日部署（保证不掉线），但没拿到算法。

## 四、判定线（预登记）

- **2026-10-09（+28d）**：若任一天 receipt 声称有 lastmod 修正却什么都没 staged（proof-of-work
  转红）累计 ≥3 天 → 关掉写路径。这条不变式是承重的，而本仓已经被「绿着跑、什么都没提交」
  烧过五次。
- **2026-11-06（+56d）**：**一次即永久，按站**。只要有一个说谎的日期、一个冻结却标着
  新鲜的面、一条编造的行进了生产，该站永久停用 autopilot 并把事故写进该站 CLAUDE.md。
- **2026-12-05**（并到已有的舰队营收线）：八站 sitemap 的 lastmod 诚实化 + 每日不掉线之后，
  若 GSC/Bing 的收录与曝光没有可见改善 → 如实写「诚实化不产生流量」并保留（它的正当性
  是诚实，不需要靠流量证明），但**不再往这一层加面**。
