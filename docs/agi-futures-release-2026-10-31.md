# AGI AI future simulator release

Scope date: 2026-10-31. Owner request: unify the existing simulation with AGI, publish on the canonical site and work toward registered users and revenue. Canonical public routes are `https://agiscorecard.com/ai-futures` and `/zh/ai-futures`; product ID `ai-futures`. The old private standalone site is not the acquisition destination.

## Product and buyer hypothesis

The reader wants to compare assumptions about AI research automation, social change, business opportunities and investment exposure, and return when evidence changes. A useful output is a reproducible scenario record: assumptions, model version, evidence reference and personal notes, from which the result is recomputed. This job and willingness to pay have not been validated with customers. No revenue or performance uplift is claimed by this release.

The simulator is separate from the interview-led Future Guide and the site's graded prediction tracker. Monte Carlo frequencies are conditional on the chosen model and priors; RSI/SI are operational proxy thresholds. The neural model learns synthetic simulator outputs, not observed examples of future RSI/SI. Neither system supplies calibrated arrival probabilities, stock price targets or investment returns. Official announcements remain publisher claims unless independently corroborated. Automatic news discovery is labeled separately from manually reviewed evidence.

## What the visitor receives

1. Free, anonymous source reading, adjustable scenarios, local save and export. Existing results are not hidden behind registration.
2. A separate free registration entry for continued bounded Jarvis research and moderated discussions. Preserve a safe public return pathname and language, retain the tool tab, and explain the shared account service. No notes or scenario inputs are sent in the account redirect. Free registration does not buy or automatically link AGI's independent paid member key.
3. Optional existing AGI cloud workspaces and version history for the same record. Existing terms remain 9 USDT per 30 days plus order-matching decimal and network fees; 50 workspaces, 10 versions each, 64 KiB per version and 5 MiB total. No automatic renewal, new payment method, extra AI allowance or alert/report subscription. The member page checks readiness and asks the user to Save explicitly before uploading. An unavailable payment service must not be described as currently buyable.

Cloud handoff uses an independent product, exact origin/window checks and a random handoff nonce. Save acknowledgements must refer to the version handed over, not a subsequently edited draft. Local records and exports are useful alternatives if cloud payment is unavailable or unnecessary. Model/evidence versions stored in a backup are provenance claims; importing a backup does not verify its contents.

## Distribution and measurement

The authorized release places entries in the bilingual tools table, the shared navigation's Tools group and Future Guide's related-scenario link. It preserves the homepage countdown and five questions. The directory is hand-maintained; the Future Guide link belongs to its builder, and navigation belongs to the shared renderer. There is no new top-level section, domain, advertising spend, outside message or recurring expense.

Measure the sequence rather than treating it as proven: relevant page visit → user-run assumptions → saved/exported record → repeat research → registration or cloud intent → verified order → delivered cloud record. `futures_register_intent` records an actual click on Register / sign in; `futures_research_open` separately records opening Jarvis. Neither event establishes account creation or a completed research task. Fixed `futures_*` browser actions carry no notes, inputs, seed, company selection or result values. Shared analytics honors opt-outs, private-route exclusions, QA, DNT and GPC. Default demonstrations are not own-task completions. An event is not a distinct person; a checkout or receipt check is not revenue.

Use comparable UTC daily reporting for a first two-week observation window. Record registered accounts through the existing server account reporting and payments through verified `ai-futures`-attributed orders. Keep paid totals, refunds and delivery/support costs separate. Missing account attribution or GA4 backend access is unknown, not zero. Low reach means distribution is untested; repeated use without payment warrants investigating the need for cloud storage and the existing USDT friction before adding more paid scope. No invented targets, customers, testimonials or sales.

## Refresh and publication contracts

The existing daily `future-discovery` job also refreshes five allowlisted company sources into `futures-assets/snapshot.json`. No new schedule is created. Published dates, checked dates, source status and last success remain distinct. On failure, keep last good content and report the failed source after committing the visible status. Push builds use the committed snapshot and do not launch another news crawl. Each build runs the actual model for the default 1,024-path scenario and publishes forecast.json with its evidence reference and real computation time; the browser separately computes user scenarios. The public app uses the latest published snapshot; missing dates or stale evidence cannot be presented as today's verified news.

New pages have canonical/hreflang, WebApplication and breadcrumb schema, tool-hub membership, free-offer metadata, sitemap entries and Markdown mirrors. All generators precede the final GA4 coverage write/check. IndexNow remains the existing incremental weekly/manual workflow after successful deployment; receipt is not indexing, unchanged URLs are not resubmitted, and private routes are excluded.
