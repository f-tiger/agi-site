## Product listing

Name: TDS Delivery Record

Tagline: Keep client handoff files and source notes together.

Description: Create a local file inventory with SHA-256 fingerprints, scope references and client response notes. Export JSON or a readable record, then compare a later set of files against the inventory. Files stay in your browser. Free, with no account required. This checks file equality; it does not verify delivery, identity, consent or a trusted time.

Launch URL: https://thedollscout.com/delivery-evidence

## Community contribution draft

Disclosure: I build TDS. One useful distinction in client handoffs is the difference between the exact file you sent and evidence that the client received or accepted it. A hash helps with the first; it does not establish the second.

Our checklist is to preserve the agreed scope, the original delivered files, the actual delivery message, and the client’s response. Missing evidence should stay marked as missing. We made a free browser tool that keeps the file inventory and your source notes together and exports a portable record. Nothing is uploaded.

For people handling at least five client handoffs a month: where does your current email/Drive workflow break down, if at all? If it already works well, that is useful feedback too.

## 45-second demonstration script

0–8s: Show two versions of the same fictional client file. Ask: “Which exact version did we hand over?”

8–20s: Select the first version and enter a fictional scope/source reference. Leave client acceptance blank. Create the record and point out the missing field.

20–32s: Export JSON. Paste it into the verifier, select the unchanged file, show “Same file bytes.” Select the revised file and show “File differs.”

32–40s: Say: “This confirms matching bytes only. It doesn’t prove that the client received, approved or authorized payment.”

40–45s: Show the free tool URL and the clear export/privacy note. Invite viewers to describe their current handoff workflow. No revenue, winning-dispute or adoption claim.

## Customer interview outline

1. How many client handoffs did you complete in the last 30 days? Walk through the most recent one.
2. Where do scope, delivered versions and client responses live today?
3. What happened the last time someone disputed a version or requested an unexpected change?
4. How long did reconstruction take? Can you show a redacted example you are authorized to share?
5. What do you already pay for, and why does it fall short, if it does?
6. Try the same handoff using your existing process and TDS. What is missing or slower?
7. Who can approve a purchase? What concrete outcome would justify $149 for setup or $79/month for a team workflow? These are hypotheses, not currently purchasable offers.

Record rejection and “existing workflow is enough” alongside positive replies. Do not treat a friendly response or anonymous plan vote as a sale.
