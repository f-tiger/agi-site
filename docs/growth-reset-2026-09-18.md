## 判断

问题不是缺少站点、自动化或功能。14 个站点和 103 条实验记录已经产生很大的维护面，但用户从搜索进入后，完成任务、带走结果和再次回来之间的路径不够清楚。更严重的是，报表混用不同流量口径，部分事件从未写入数据库。继续据此加页面或一律停开发，都会放大错误判断。

本轮执行选择：**把白嫖计作为产品增长主战场，修复全站组合的测量，并调整 14 站投入分配。** 不是声称已经逐页重做其他 13 个站点，也不是承诺排名或流量翻倍。

## 对标：借鉴用户路径，不照抄规模

| 对标对象与出处 | 有依据的观察 | 本仓采用的设计 |
|---|---|---|
| [Lovable 官方 2025-07-23 公告](https://lovable.dev/blog/agent) | 公司自报从首个 $1M 到 $100M ARR 用时 8 个月，累计超过 1,000 万项目；这是历史收入/项目数据，不是当前网站流量 | 让用户尽快拿到一个属于自己的结果。白嫖计交付工具方案、链接和清单 |
| [a16z 2026-03 消费 AI 报告](https://a16z.com/100-gen-ai-apps-6/) | 基于 2026-01 的网络访问与移动 MAU；讨论 Lovable/Replit 等任务产品的留存，也指出头部 vibe coding 流量增速已放慢 | 不把“快速增长”当永恒属性。抓住具体任务、可重复使用和结果交付；用自己的数据验证 |
| [OpenRouter 排行榜](https://openrouter.ai/rankings) | 用实际使用统计、分类和应用场景组织信息；这一页面本身不证明其增长率 | 发挥本仓的额度、来源、日期、授权数据优势；不要做没有依据的“热门第一” |
| [Toolify 首页](https://www.toolify.ai/) | 分类、排行、收藏、提交与广告入口并存；本轮未核实其增速 | 目录只是发现层。避免和大型目录比条目数量，优先解决免费档是否够用 |

以上是产品机制推断，不是“某个按钮造成某家公司增长”的因果结论。[Google 的内容指导](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)也强调原始价值、受众与明确的站点重心；不能以多主题批量生产替代用户价值。[可抓取链接指导](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)支持用真实锚点串联已有相关页面。

## 本次代码交付

1. **任务优先首页，中英文同步。** 五个任务入口直达组装器的相应配置，保留原有内容和 URL 资产。已有订阅者可进入订阅成本核对工具。
2. **可带走的免费工具方案。** 任务与筛选条件写入白名单 URL 参数，可复制、重开；匿名下载 `.txt`，带工具、额度、核实日期、来源、授权边界。链接使用打开时最新数据，下载保存当前快照；不冒充稳定不变的推荐。
3. **八个工具取消前置邮箱墙。** 工具免费可重复使用，真实操作后才出现可关闭的自愿订阅。分享和导出不要求邮箱。没有接通的即时邮件不作承诺。
4. **六个已获流量入口承接。** 在答案后放已有替代品、相关计算/对照工具、具备数据的免费付费档页面链接；没有事实不造页面。单独记录曝光和导航点击，不能算作 calc。
5. **测量修复。** 服务端接收五类原先丢失的事件；stack-builder 初载不再自动记 calc。公开 reach 只输出自有固定路径的增长事件计数，不公开任意搜索文本。舰队报表分别标注各站分母口径，缺失字段报错而非填零。
6. **推荐可信度。** 商用筛选只对四类创作任务生效，排除明确不可商用、未说明和未核实记录；有条件许可仍明确标注。已停服记录不推荐。资料日期和地区标签不伪装成实时核实。
7. **防止策略回退。** 根/站点手册增加本轮优先说明；旧强制注册实验撤回并保留原因，新实验进入已有 heartbeat 判定台账。没有新增定时任务。

## 发布、验证与复盘

- 分支与 PR 保留完整可审阅差异；主分支已有发布机制仍负责上线。白嫖计 push 发布需要提交信息含 `[deploy]`，定时兜底另算；没有成功发布记录时不能写“已上线”。
- 本地完整构建和 1,603 页校验已通过；事件写入、公开计数白名单和分母解析有回归检查。浏览器测试通过 GitHub PR 的无密钥任务运行，中英任务入口、匿名计算、分享复现、导出、关闭提示、重复订阅、移动端宽度都要验收。
- 浏览器测试拦截所有网络请求，订阅地址使用保留测试域；不污染生产统计。截图留在同仓 Actions artifact 7 天，不公开发布。
- 新增 PR 检查只由相关代码的 PR 触发，预计每次 1–3 分钟，硬上限 6 分钟，不增加日常 cron。本次自检加入现有发布与 heartbeat，秒级。
- **生产部署次日确认埋点确实落库；7 天查入口与使用；28 天判断是否扩大。** 现有公开 reach 每日导出自动携带新 growth counts。未部署或读数不可得时标 pending/insufficient，不能填 0。
- 六工具 + 两分类入口目标：至少 100 次有效曝光才判断点击比例；≥10 次下一步点击且比例≥5%是继续扩大信号。浏览事件计数不能当独立用户转化率或随机 A/B 结果。
- 方案目标：≥20 次 `/gate/stack-use/stack-builder` 真实组装操作，且≥5 次导出/复制操作，才考虑做更多任务模板。复制按钮只代表复制/分享意向，不证明朋友打开。重复访问、回流、营收必须另有证据才宣称增长。
- 有使用却无订阅时先改订阅价值/去掉提示，不恢复强制墙来抬高注册率。入口低于样本门槛时优先检查发现渠道，不批量再造页面。

回滚：可独立撤回首页/入口/软订阅 UI；保留事件白名单修复和口径修复。不得通过把缺失值改成零使报表“变绿”。本轮不购买流量、不向他人发消息、不创建额外 AI 定时循环；分享机制由真实用户自主使用。
