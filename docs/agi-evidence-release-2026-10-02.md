# AGI evidence and usage release — 2026-10-02

## Scope and three refinements

1. Narrow the homepage to checking AI progress/predictions, then making an assessment. Improve existing evidence pages instead of launching another directory or product.
2. Distinguish original evidence windows, ledger dates, citation-note versions and actual behavior. Existing ledger remains 2026-09-06. Do not equate a share-link copy with an acquired visitor, subscription click with a stored address, or a checkout with payment.
3. Deliver four bilingual topics, reusable cited figures, a coherent assessment-to-registration path and owner-only funnel aggregates. Validate locally and after deployment. Reuse the existing daily deployment/reporting and weekly IndexNow tasks; no new recurring cost or schedule.

## Audience and commercial boundary

Primary audience: readers comparing AGI claims and workers interpreting AI evidence. Free value: inspect sources, dates, uncertainty and score history; make a local assessment; export a citation or figure. Existing independent AGI membership sells cloud workspaces; this release does not paywall the evidence or introduce an offer. No paid-demand or retention result is established by the release. Crypto checkout friction and insufficient repeat use remain hypotheses to investigate with real data.

## Measurement contract

GA4 property 541489054 via Windsor.ai, queried 2026-10-02: October 1 had 39 active users, 41 sessions, 45 views. Event breakdown included one `subscribe_click`; that is not one subscription. This is property-level data, not a main-host-only visitor census, and recent GA data may settle. No new funnel events were visible in that returned day. Existing coverage changed October 1; do not reconstruct missing history.

| Stage | Evidence | Unit / limitation |
|---|---|---|
| Homepage entry | `focus_entry` with fixed asset/route labels | Browser actions, not people |
| Assessment | `task_start` / `task_complete` | Starts at first choice; completion once per attempt |
| Citation/share | `evidence_action`: successful copy, source open, download initiation, assessment open | Copy/download does not prove a completed external share or saved file |
| Tagged arrival | `share_arrival` with known reader_share campaign | Once per tab/path/campaign if storage works; tags alone do not prove a different person or an external referrer |
| Signup UI | `sub_open`, `sub_submit`, `sub_ok`, `sub_fail` | Existing browser flow; no email text in analytics |
| New stored signup | New unique `subscribers` row by original creation day | Excludes known CI/verify paths/tags; storage is not mail delivery or a paying member |
| Checkout | New `wb_orders` record by creation time | Payment intent, not payment |
| Paid | Paid state, actual `paid_at` within window and matching `bpj_ad_chain_receipts` | Gross USDT, not net revenue, profit, or campaign-causal attribution |

`/api/evidence-funnel` requires the existing derived membership admin secret and returns aggregate counts only. No PII, account tokens or transaction hashes are returned. Missing queries return null/503, never synthetic zeros. The daily/deploy `tools/evidence-metrics.mjs` prints only aggregates and writes the Actions summary. Auth checks happen before D1 reads; no new tables, scans on public page requests or high-frequency polling are introduced. Event queries use the existing event-name index; new labels are fixed allowlists. DNT/GPC and QA suppress new client events; existing GA4 consent handling is retained.

All stages have different denominators: do not multiply them into a user conversion rate. Share events are not unique users, return visitors or acquired backlinks. No stable cross-session identifier is introduced.

First complete baseline: **2026-10-03 00:00 through 2026-10-17 00:00 UTC**, i.e. October 3–16 inclusive (Beijing October 3 08:00 through October 17 08:00). The release day is partial and excluded. Existing October 1 series remains available; this does not overwrite it. At baseline end, compare entry choices, task completions, confirmed new registrations and receipt-backed payments. If fewer than 30 starts, distribution is inconclusive; if starts occur but completion does not, inspect task friction; copies without tagged arrivals suggest the share loop needs investigation. These are operating rules, not statistical validation. Keep the next 14 days comparable unless a correctness bug requires repair.

## Adversarial self-checks and fixes

1. Evidence and scope: a new page date could falsely imply a new verdict; a four-month gap could falsely imply an October measurement. Kept ledger/history bytes unchanged, separated note dates and study window, retained uncertainty, and verified original sources. Existing individual-verdict history is incomplete and is disclosed instead of fabricated.
2. Behavior and failure: blocked clipboard cannot count success; repeated visits cannot claim a unique referred person; fake paid browser events cannot count revenue; private aggregate failures cannot look like zero. Tests exercise clipboard failure, privacy flags, reload deduplication, collector allowlists, unauthorized access, missing tables and unmatched/old/pending payment rows. Mobile review also exposed the unrelated homepage popup, which was removed. Full-size chart links and PNG export make small mobile charts usable.
