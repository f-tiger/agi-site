# 垂直 Agent / MCP：从买家的重复任务倒推收入

日期：2026-09-18。当前交付为 TradeCheck 本地 MCP、浏览器演示和安装教程；部署状态以文末发布记录为准。没有新增已验证收入、真实付费买家、客户访谈或 OCR 准确率结果。

## 优化后的执行任务

覆盖效率、语言结构工作、财务、外贸和股票五类机会；查第一方产品、价格、数据接口及负面证据。选择一个有明确任务边界、可验收、低增量成本的切口，实现真正的 MCP 工具及 Agent 工作流、反例测试、公开演示和新人教程。把买家价值、分销方式、收费假设、停止条件写清。继承 owner 的推送上线授权，不购买服务、不联系客户、不开放未经验证的收费。

## 选择结论

首个实现：**TradeCheck——面向小型进口商与采购团队的供应商发票 / PO 异常复核**。潜在使用者是采购或应付人员；潜在买家是财务负责人或经营者；潜在渠道是为中小企业配置 AI 工作流的会计服务商与自动化实施方。这些是分群假设，不是已访谈画像。

该选择把语言工作与可验证计算连接起来：AI host 读附件并整理字段 → 人确认抽取 → MCP 做精确计算与规则检查 → 输出异常和未发送的追问。最容易被替代的是重复的信息搬运和对照；判断证据完整性、解决例外、付款批准仍需人处理。不能把“结构化语言任务很多”推导成“所有岗位都可被可靠自动替代”。

MCP 是连接与分发方式，本身不构成壁垒。买家可能为持续减少复核工作、系统接入和可靠留痕付费；不会因为协议名称付费。当前的核对算法容易复制，尚不存在数据或渠道壁垒。

## 三轮对抗结果

1. **商业反证**：泛目录、泛行情 MCP、普通报价计算器都容易替代。选择单据例外复核，不声称蓝海。只在人工准备 + 复核的总时间确实降低时成立。
2. **实现反证**：历史缺失、混币种、重复编号、不同单位、分批开票、日元与小数舍入、供应商不一致，都不能隐藏在“已通过”后。引擎使用整数定点运算；任何状态都不批准支付。
3. **独立工具复核**：评估者只读 MCP 工具与资源，在 10 个稳定场景中发现一个真实缺陷：已排除的重复历史行仍被引用为累计数量证据。已修复为只引用参与计算的行，重新验证通过。详见 `agents/tradecheck-mcp/EVALUATION.md`。测试是工具契约检查，不是 OCR/LLM 效果或买家满意度测量。

## 已交付与仍未交付

已实现：三个 stdio MCP 工具、一个 Agent 工作流 prompt、输入合同资源、稳定示例、金额和数量引擎、双语开头的未发送供应商草稿、JSON 报告、浏览器演示、可下载 beta 包、校验和与新手教程。MCP 不读取任意路径、不发网络请求、不保留文档、不调用收费模型。

未实现：PDF/OCR、独立托管模型、ERP 接入、收货核对、付款、信用证/税务/海关合规、批处理团队空间、账号订阅、托管 MCP 计费服务。用户的 AI host 负责可选的文档读取，其模型费用和数据条款仍适用。不能把工具包描述为已交付全部自动化 Agent。

公开 beta 只分发这个独立子目录；主仓保持 private。没有把原仓代码、keys 或数据打包。无付费注册，不设置虚构倒计时、证言、客户 logo 或省钱数字。

## 收费与规模化路径

本地 MCP beta 免费内部评估，用于证明任务可交付。拟测试 **€29/月团队空间**：历史留痕、供应商映射、重复批次与跨助手使用。支付保持关闭，这些团队功能没有建成。价格是待验证假设。

| 阶段 | 算式（假设） | 不能误读为 |
|---|---|---|
| 约 €110 月收入 | 4 个付费团队 × €29 = €116 | 目前已经有 4 客户 |
| 约 €1,100 月收入 | 38 × €29 = €1,102 | €1,102 净利润 |
| 约 €1,100 月贡献利润 | 48 × €29 × 80% = €1,113.60 | 税前净利润或保证收益 |

第三行假设收入已经剔除 VAT/退款，80% 贡献率还需扣除支付、托管、模型、交付与人力支持。若每客每月仅允许 €5.80 变动成本，用 €30/小时内部人力估值，10 分钟支持就消耗 €5；几乎没有空间承受持续定制。**需要每客户大量人工适配的项目不可称为规模化 SaaS。** 获客成本、固定维护和税费仍另计，不能用贡献利润冒充净利润。

可复制的是经过验证的 schema、检查器、来源映射、回归样例与分销流程；不是复制 100 个换名字的站点。预期的后续顺序是：同一买家更多单据批次 → 固定供应商模板 → 订阅团队空间 → 自带模型的托管 MCP/API。跨行业扩展须重新验证规则与购买者。

## 获取需求与停止条件

已执行分发：RFQDesk 的相关入口连接发票 Agent；新增公开 demo、安装教程、sitemap 页面与可运行下载包。原工具站保留作为低成本探针。没有擅自向 Reddit、会计师或客户发消息，也没有声称已提交 MCP 目录。

下一步渠道假设：采购/应付长尾问题、会计服务商、n8n/AI 工作流实施者与可展示演示的 MCP 目录。先收具体“最近一次怎么做、每月几次、怎样核实”证据，后谈付款。把替代 Excel 的成本算进去，不能只量计算时间。

固定实验判定规则（操作门槛，不是统计显著性）：

- 30 天或 100 次来自相关买家任务的访问后复盘，以先满足的条件做检查；流量不足只说明分发未验证。
- 目标 20 次非示例实际任务完成、至少 5 个同细分群体的重复任务陈述；匿名点击不能证明是 5 个人，因此必须另有获授权的真实反馈才能达标。
- 正式收费前：至少 3 个独立买家完成真实材料试用；每次处理人工准备 + 校验总时间中位数至少下降 50%，严重漏报为 0（仅在已审样本范围）；提供退款和真实交付流程后才开启收费。
- 若用户已经有的 ERP/Excel 同样容易、准备输入时间更长、主要诉求是未实现的 OCR/ERP 接入，停止扩充核对规则，先解决该阻塞或放弃细分市场。
- 第一阶段收入成功：至少 3 位实际付款买家，贡献为正；订阅扩张前要有真实复购/续费，兴趣事件不作收入或留存。

## 埋点口径与部署

Agent 独立使用 `agent_start/complete/export/draft/download/interest/none/once/repeat` 事件。示例编辑继续记为 sample；只有切换到自己的材料才记 own。QA 参数始终排除于正式汇总。下载事件只说明点击，不代表安装。无跨次身份，不推算留存或唯一买家。

Cloudflare D1 管理 API 对当前 CI token 返回 401；沿用 Learn 已授权的现有数据库绑定，运行时只创建 `venture_events`。实际部署已接受该绑定；不修改权限，不查看其他站点表。账户又达到免费 5 个 cron 上限，改为下一次统计请求时清理旧事件，未购买套餐或移除其他站定时任务。无请求时过期数据可能保留更久，隐私页已明确。

最终上线与线上验收结果见 `docs/vertical-agent-release-2026-09-18.md`，不能以本地测试替代。
