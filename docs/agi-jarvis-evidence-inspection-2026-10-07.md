# Jarvis v13：逐条来源核阅

日期：2026-10-07。本记录只保存合成测试与非敏感工程结论；没有读取客户任务、记忆、访问密钥或私有统计明细。

## 三轮任务优化

1. **从引用存在到可核阅**：当前校验能拒绝不存在的引用 ID，但不能证明来源支持结论。本轮目标不是声称自动事实核查，而是让用户无需在长报告中来回寻找，即可逐条展开模型实际引用的来源标题、说明与安全链接。
2. **比较实现路径**：确定性映射消耗 0 次模型调用，且不会新增判断；小模型、当前 8B 或更强模型充当裁判都会新增延迟、用量和误判面。在没有人工标注的冻结语义支持集之前，不发布“模型已验证”的标签，也不改综合提示词。
3. **冻结验收**：中英文页面每条结论只展示其 `sourceIds` 对应的来源，重复 ID 只出现一次，未知/未引用来源不进入结论卡片；来源文本只能作为纯文本；导出保留逐条映射并明确“不证明支持”；任务、权限、额度、调度和模型调用数均不变。

## 一手证据与反证

[SourceCheckup 研究（Nature Communications，2025）](https://www.nature.com/articles/s41467-025-58551-6) 把“引用存在”和“来源是否支持陈述”分开评价。在其医疗问答数据中，模型回答经常没有被所引来源完全支持；研究还用执业医生样本校准自动来源判定。这个结果支持把逐条陈述—来源关系暴露出来，而不是只显示编号。

反证与外推限制：该研究主要是医疗问题，自动核验本身也由大模型承担并需要医生校准，不能把其比例直接外推到 Jarvis，更不能据此宣布本站的任何结论已被验证。来源元数据可能不含正文，逐条展示也可能增加界面噪声或虚假信心。因此卡片默认折叠，明确标注“便于核查，不代表解读正确”，并保留原始来源区。

## 两轮对抗自检

1. **虚假信心与界面噪声**：来源卡默认折叠；标题写“核阅引用来源信息”，而非“已验证”；卡内与导出同时声明局限。语义支持率仍记为未知。
2. **注入、泄露与权限扩大**：来源标题和说明仅通过 `textContent` 渲染；链接继续通过 `safeURL`，只允许安全 HTTPS；恶意 HTML 不执行、不发外部请求。没有新增分析事件字段、任务正文上传、D1 表、会员门槛、额度或工具权限。

## 可证伪实验与结果

冻结条件覆盖：重复引用、未知引用、未引用来源、恶意标题/说明、导出映射、英文、中文及 360px 布局。发布条件为所有映射与安全断言通过，且完整 Jarvis/站点发布门槛无回归；任一结论出现非引用来源、任何 HTML 执行、横向溢出或额外模型调用即失败。

本轮工程测试只证明映射、渲染和安全边界，不测来源是否在语义上支持结论，不等于模型质量提升。后续应先建立人工标注的中英文 claim–evidence 留出集，再比较规则、小模型、当前 8B 与更强模型；按逐陈述支持、遗漏、纠错、真实延迟与 token 决定是否增加自动判定。
