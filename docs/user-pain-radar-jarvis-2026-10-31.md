# 用户痛点雷达与 Jarvis 开发执行

Owner 2026-10-31 明确要求：把用户痛点更新到 AGI 用户雷达，让 Jarvis 主动扩展现有站点。

三轮收敛：目标是复用舰队而非另建工具；约束是保留证据来源、商业边界与现有发布门；验收是雷达摘要和每站 action 都能消费同一持久输入。两轮自检：缓存不是原帖、主题重合不是买家；生成队列不是已发布、默认任务不能覆盖并行工作。

## 权威链路

- 持久输入：`data/user-pain-radar.json`。只存自写的痛点概括、任务与证据状态；原帖、缓存记录与私有用户材料留在私有研究记录。
- 既有摘要：`tools/fleet/demand_digest.py` → `data/autopilot/demand-digest.md`。
- 既有动作队列：`tools/fleet/evolution.py` → `data/fleet-evolution/latest.json` 与每站 `data/fleet-evolution.json`。
- 执行者：既有“持续开发 AGI 贾维斯”托管开发任务；它使用 GitHub/发布工具。网站 `/jarvis` 的私有研究 API 没有获得舰队代码或发布权限。
- 复用原有每日 autopilot；没有新增 cron、付费采集或模型供应商。Reddit 官方读取未恢复，本批输入不改变该状态。

## 首批判断

BPJ：编程额度/续费选择、试用取消条件，来自既有缓存，原帖日期未知，先核验。AGI：AI 结论缺上下文，原帖已读但只有一个当前来源，且受众适配未确认，先用合成任务复现现有 Jarvis 缺口。通用代理商报告不扩建：已有成熟替代，也不改变电商周报导师定位。其余站点继续用各自真实队列，不把 BPJ 的痛点强行套给 Eco/TDS。

## 派发与接续

1. 每项稳定 id、站点、路径范围、验收、反证和来源状态。每站最多一项；有 working 项时整站暂不派第二项。
2. 来源复核须在过去 14 日内，原帖发布日期须在过去 180 日内；未来/未知/过期/重复来源不能满足扩建门。两个不同来源记录也不代表两个独立买家。
3. `site_fit_verified=true` 只能在执行者核对实际用户任务、站点能力和替代方案后写入。至少两条当前原始来源且适配已核实，才生成 `pain_point_extension`；否则只生成 `pain_point_verification`。这是工程投入门，不是商业验证。
4. 执行者先查 main 和打开 PR、既有站点任务。领取时用 SHA 并发保护把 queued 改 working，保存任务分支/PR 指针；同站已有重叠任务则协作接续，不开第二份。
5. 每轮推进一个最小可验收改进：核验、实现、适用测试、PR、既有授权内合并发布、正式 URL 核对；有阻塞记 blocked 与准确原因。环境不可用时可做连接器核验和提交，但不能冒称运行代码/浏览器或线上通过。
6. 完成后写 done、工程收据（commit/PR/正式 URL/检查结果）和后续观察窗口。退款、付款、收入和客户记录只存私有处；发布/导出/注册事件不当作营收。
7. 不自动恢复其他暂停任务或变更它们职责，不绕过明确的 PR hold，不改密钥/额度/支付权限，不发送外联消息。低信号时更新证据或停止该方向，不凑页面。

## 验证与公开发布范围

`python3 tools/fleet/test_evolution.py` 与 `python3 tools/fleet/test_pain_radar.py` 在既有只读 PR 检查中执行，包含缺失/过期/未来/重复来源、错站路径、状态接续、每站限一项、字段投影以及两个消费者的临时目录集成。该变更只更新舰队后台研究输入与队列，没有新增网站页面，因此本次没有网站 GA4/SEO/GEO/IndexNow 提交；后续站点实际改动必须遵守各站既有发布检查。
