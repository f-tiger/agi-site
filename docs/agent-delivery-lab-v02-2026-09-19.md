# Agent Delivery Lab v0.2：完成任务与重复使用

日期：2026-09-19。Owner 请求：“继续扩展完善”。沿用先优化目标、执行、验证、部署的授权。

## 本轮优化后的执行目标

在已发布的免费 beta 上，减少准备输入与验收规则的阻力；允许开发者复核一批实际付费调用与失败重试的成本；把规则与报告带回自己的 CI；补一个任务相关的主站入口。保持支付、事实正确性、商业需求与匿名行为的计量边界。验收以算法/CLI/边缘路由测试、真实部署文件与接口检查、可行的页面交互检查为准。

## 为什么选这些改动

首版可以检查单条记录，但验收规则全靠手写 JSON，切换工具会覆盖正在处理的输入，多次失败和重试也无法一起核对。这些是代码与工作流中直接可观察的产品阻力，并非虚构的用户访谈。当前没有足够证据证明托管历史或监控订阅有人买，因此本轮不扩收费、支付与自动托管任务。

## 实现

- 规则生成表单：输入 JSON Pointer、条件和值，将经过同一引擎验证的规则加入可见 contract。支持导出 contract；不把示例输出自动推定为正确答案。
- 本地文件导入：JSON/text 文件在当前 tab 读取，不上传；大小限制与计算入口一致。各工具输入保留在当前 tab 内存，刷新清空，报告在输入变化后立即失效。
- 批量验收：1–100 次调用，共用一份明确的 contract。每次尝试有唯一 id；重复 id、缺成本、未知字段、混用 response/error 等错误直接拒绝整批，不静默遗漏收费失败。
- 合格输出成本：按 provider + currency 分组；所有录入的尝试成本（包括失败与重试）/ 规则通过的输出数。BigInt 固定 8 位精度累计，除法明确向上舍入至 8 位；没有合格输出时 null。分别显示合格输出数与不同任务数；币种不换算。
- 这是成本核算基线，不宣称新的数学算法、服务商信誉系统或自动采购路由。输入来自使用者；规则通过不证明事实、来源、链上支付或账单真实。
- 本地 CLI 支持 batch attempts.json contract.json。案例下载由相同示例常量生成，避免页面与测试样例漂移。
- 新增 /batch-checks.html 方法与虚构案例页、中文说明、sitemap/llms 入口；主站 /for-agents 的相关段落链接到 batch 工作台，并沿用已有 tool_click 事件。流量尚未得到证明，不把一个入口当作获客成功。
- 生产 smoke 从固定九个文件扩为构建目录全部文件的 SHA-256 校验，并检查 HTML/JS MIME 类型；匿名反馈读数明确剔除 QA。
