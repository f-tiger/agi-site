# Jarvis v11：可编辑的下一步接续

日期：2026-10-06  
范围：`/jarvis`、`/zh/jarvis`；不改变模型、额度、调度、会员产品或首页定位。

## 观察与约束

- 正式 API 基线仍为 `jarvis-20261005-10`：Workers AI 已绑定，快版 Llama 3.1 8B；全站 12 次/24 小时窗口、每 IP 3 次、新任务 1 次综合、旧检查点最多 2 次；一次访客任务后免费注册，不要求付费会员。
- 最近一次有权查看的两小时维护回执为 `processed: 0`，只说明该次扫描没有处理到期任务，不能推出没有用户或没有任务。
- 2026-10-03 至 2026-10-06 的 GA4 `/jarvis` 路径聚合查询返回空结果。数据延迟、过滤与曝光均未知，不能写成“0 用户”，更不能推断留存或收入。
- 客户任务正文、记忆、密钥和私有报表均未读取。公开仓库只记录合成案例与非敏感工程结论。

## 三轮任务优化

1. 把目标从“增加代理能力”缩小为“报告能否自然进入下一次真实尝试”；现有按钮只复制旧目标，丢失所选动作、完成标准和用户实际结果。
2. 比较确定性模板、小模型、现有 8B 与更强模型。字段已经存在，确定性代码可零模型调用、零推断误差地组合；模型候选没有额外价值证据。
3. 冻结验收为最终草稿内容、重新同意、无提前服务端写入、无额外模型调用、跨语言与恶意文本边界；页面点击和夹具通过不等于客户价值。

## 两轮对抗自检

1. 权限与隐私：访客试用用完后不能借“接着做这一步”创建第二项任务；接续草稿不继承已勾选记忆、公开搜索或云端同意；工作区所有权仍由服务端私钥/账号校验，不从客户端草稿推断。
2. 注入与配额：模型生成的动作只作为纯文本进入可见、可编辑草稿；双向控制字符被移除，总长限制 1,200；点击不调用 API、不预占 nonce、不执行工具，重复提交仍走原有幂等和全局/IP 配额。

## 实现与实验

- 每条报告动作新增“Use as follow-up / 接着做这一步”。草稿带入原目标、该动作、完成标准及空白的实际观察字段。
- 通用“继续这个目标”也使用同一安全草稿，但不虚构动作。
- 固定 GA4 动作 `jarvis_followup_prepare` 与 `jarvis_followup_start` 不带目标、任务 ID、记忆或其他客户数据。前者与后者的聚合比值只能描述界面路径，不能证明独立用户、留存或任务成功。
- 冻结浏览器回归会确认准备草稿时 SQLite 任务数不变，安全默认已复位，重新同意后才产生新任务。模型响应使用本地夹具；本轮不消耗正式 AI 额度。

## 当前验收状态

- 67 项 Jarvis 单元、SQLite、会员和安全测试通过，包括新的草稿边界与固定事件白名单。
- 本地 Playwright Chromium 不存在，浏览器回归留给现有部署流水线下载的固定浏览器执行；在该门禁通过前不声称浏览器验收完成。
- 真实客户采用、引用事实准确率、任务完成率、生产延迟与 token 用量仍未知。本改动不证明 AGI，也不证明用户会复用。
