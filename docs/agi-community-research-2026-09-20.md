# AGI 首页讨论区：调研、实现与增长实验

日期：2026-09-20。状态：实现与验收记录见文末。目标是本站注册、有效参与、回访及可归因引荐，不以发帖量或停留时长代替价值。

## 优化后的任务指令

第一轮：研究 Reddit 等 AI 社区的参与动机、讨论形式和分发规则，判断 AGI 首页是否值得增加讨论区；完成中英双语实现，以注册和流量提升为目标。

第二轮修订：保留本站“带来源、日期与翻转条件的 AGI 判断”定位；区分免费社区身份、邮件订阅和付费工作区；比较原生讨论、GitHub 评论与外部聊天群的成本；正视冷启动与审核；提供独立可索引话题、分享、来源归因和回访路径。禁止伪造用户、回复、热度、节省时间或营收。外部社区不自动发帖，不绕过社区对推广或 AI 文案的规则。上线前验证权限、UGC 隔离、会员权益隔离、多语言和移动端。

## 判断与证据

**可以上线一个有边界的原生讨论区。** 先采用三个主题和六个编辑开场话题，用现有主站访问量检验参与需求。无需开新域名或新增 SaaS。对增长的信心中等偏低：外部讨论证明主题有人关心，并不证明用户愿意离开既有社区来这里注册。

一手站内基线：2026-09-20 01:21:57 UTC，公开 `/api/pulse` 报告近 28 天 `human_pv=36013`，AI 引荐页面浏览 `ai_ref=22`。这是现有分类器下的页面浏览，不是独立用户、论坛受众或付费客户；不拿它直接计算社区注册率。历史手册中的 17 人/日和邮件 0/246 是旧窗口，也不能套在当前流量上。

研究采用可直接核对的社区首页、规则和官方产品文档。搜索结果出现大量不相关页面，已排除；以下为实际读取的来源。未进行批量爬取、客户访谈或统计抽样，不把首页观察解释为市场规模。

## SEO、GEO 与外链结论

- [Google 论坛结构化数据](https://developers.google.com/search/docs/appearance/structured-data/discussion-forum)适用于真实用户生成的讨论，不能用来包装站方文章。本次编辑开场话题不标记 `DiscussionForumPosting`；审核通过的用户主题才有该类型，字段匹配可见内容。SSR 正文、规范链接、中英界面和独立动态 sitemap 帮助抓取，但不保证索引、排名或 AI 引用。
- [Google UGC 防垃圾建议](https://developers.google.com/search/docs/monitor-debug/prevent-abuse)支持对不可信投稿采用审核及索引控制。本次所有投稿先私有审核，公开页和 sitemap 不暴露未通过内容。来源链接使用 [`rel=ugc nofollow`](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links)，不提供出售排名链接的机制。
- [Reddit spam policy](https://support.reddithelp.com/hc/en-us/articles/360043504051-Spam)限制重复、无关或自动推广。LocalLLaMA 的自荐比例是该社区的指导而非全 Reddit 的通行证；还要求披露关联并限制 AI 生成文案。Singularity 明确反对推广。分享功能提供链接与系统分享面板，用户自行选择目的地。
- 外链与引荐分别衡量。`share_intent` 是分享意图，不是完成分享、更不是获链；来源参数可以被用户更改，仅作低置信度归因。高质量的原始实测更可能值得被引用，这是待验证假设。
- 中英界面各有可抓取入口。编辑主题提供人工编写的双语版本；用户内容保持原文，不伪称已经翻译。GEO 的主要资产仍是有来源与日期的本站判断，讨论补充第一手证据，不替代原有判断台账。

## 本次产品范围

入口 `/discuss` 和 `/zh/discuss`，英文主页 `/`、中文主页 `/cn` 增加可见模块和导航。三个主题：工具实测、AI 未来、AI 与工作。六个开场主题均明确标注编辑来源，不显示假热度。

免费注册使用 AGI 已有的 256 位访问密钥身份：昵称 + 下载密钥 + 同意规则，不依赖尚未开通的邮箱服务。已有 AGI 会员可导入同一密钥。服务器只保存哈希；免费账号 `ends_at=0`，没有付费工作区权限。其他三个站点不受影响。登录密钥备份比常规邮箱流程陌生，这是明确的转化风险，需观察真实流失后再决定是否配置认证供应商，不能假称无摩擦。

支持发起主题、回复、关注、账号内新回复计数、草稿保留、审核状态、自己的内容删除、关闭社区资料、举报、原生分享和复制带来源参数的链接。关注是站内列表，不承诺邮件或 Telegram 通知。编辑主题跨语言共享讨论，回复保留作者语言；用户主题按原文语言归类。

界面采用既有的浅色中文设计：白色、浅灰、克莱因蓝，清晰的主题行与正文，不新增头像墙、积分、虚构成员数或无限滚动。免费参与和付费工作区的价值说明分开。

## 审核与运营

所有用户投稿先进入私有队列。`/discuss/moderate`（中文 `/zh/discuss/moderate`）可通过、拒绝及处理举报。凭据由 AGI 的独立运维密钥派生，不能用普通会员密钥进入。审核凭据只授予社区权限，不直接接受收款/会员管理员凭据；不写入链接或日志。

受信任本地环境持有现有部署 secrets 时，运行 `node sites/agiscorecard/tools/community/ops.mjs credential-file /PRIVATE/PATH` 生成仅用户可读凭据文件，再在审核页使用。不要在公开 Actions 中生成或输出该文件。也可由已有权限的运营者在 Cloudflare D1 控制台核对队列。代码不读取 GitHub secret 明文给用户。

建议每天两次查看审核队列和未回复话题，优先处理隐私举报；第一批贡献出现后，应由真人提供实质回复，不能用机器人伪造社区人气。没有专职审核投入的情况下，增长能力受限。已有每日部署工作流输出**聚合**注册、参与和积压数据，不新增 cron、不发送外部消息。已有舰队判定台账记录 2026-10-20 复盘，不能因本次上线忘记评估。

风控：同源 JSON 写入、请求体上限、账号与每日哈希网络标识限流、投稿总量阀值、未审核内容不公开、纯文本转义、HTTPS 来源约束、无第三方脚本、CSP、no-store 私有响应。无邮件找回；密钥丢失无法恢复。全部登录与参与测试使用临时 SQLite，生产验收不创建伪用户或评论。

## 30 天实验与分发操作

先站内验证：主站首页可见讨论模块 → 选择具体主题 → 阅读 → 免费注册 → 首次投稿 → 审核通过 → 关注后回访。每周依据真实主题补一篇有来源的编辑总结，链接到实际讨论；没有贡献时明确记录零，不编造“用户都在讨论”。此建议不代表已经设置自动内容发布。

外部分发准备的是**素材清单**：实际问题、可复现输入、结果/失败、原始来源、与网站的关系、真实讨论链接。通用分享文案假设：介绍一个具体测试结果并邀请纠错；不可声称已经节省时间、已有活跃社区或收益。HN 及限制 AI 文案的社区由作者本人从事实重新撰写。发布前逐个核对当前规则；本次没有外部发帖、私信、购买链接或广告支出。

| 指标 | 定义与边界 |
|---|---|
| 首页模块曝光 / 点击 | 现有 first-party `events` 的 `discussion_home_view` / `discussion_click`；客户端事件，不是独立用户 |
| 讨论访问 | 讨论区匿名 tab-session-days，去重同标签页同日；不是跨设备人数 |
| 注册 | 成功写入的免费社区 profile，分来源；不包括下载密钥和邮件点击 |
| 激活 | 注册后 7 天内提交且最终审核通过内容的账号；需区分尚未成熟的 7 天窗口 |
| 回访 | 注册日期之后另一天调用账号状态的账号；不包含匿名回访，也不等同 D7 retention |
| 内容供给 | 待审核数量、超过一天无其他用户回复的公开主题；编辑话题不充当用户主题 |
| 分享 | 分享意图事件和后续标记来源访问分开，不声称实际 backlink 数量 |

操作判定线：到 2026-10-20，先要求至少 100 个讨论 session-days 才讨论转化；目标至少 10 个注册、3 个非站长贡献者、3 个跨日回访账号，且没有持续超过 48 小时的审核积压。非站长需人工核对，当前自动指标仅统计账号。低于触达线 = 证据不足；触达足够但没人参与 = 收窄到少量编辑主题，停止板块扩张。这是预算控制线，不是效果承诺或统计显著性标准。

## 实现与验收
