# Jarvis v20：同标签页未提交目标恢复

日期：2026-10-12

## 真实缺口与本轮边界

v19 已能持久保存已提交任务、工具检查点、用户自报进展和受阻后的可编辑草稿，但纠错、解除阻塞、接续任务或手动输入的目标在提交前刷新页面会全部丢失。源码审计确认这些目标只存在于 `#goal`，没有恢复路径。聚合真实访客数、注册转化、二次任务、完成率、反馈与收入仍无本轮可安全读取的快照，因此保持未知；工程夹具和页面事件不计作客户、留存或收入。本轮没有读取客户任务正文、记忆、密钥或私有报表。

正式站公开页面与最近一次 AGI 部署可用；当前 Workers AI 配置仍为 `@cf/meta/llama-3.1-8b-instruct-fast`。本轮缺口是确定性浏览器状态恢复，不需要模型，也不改变全站 12 次/24 小时、每 IP 3 次、每任务最多 2 次模型调用的额度。没有执行真实模型验收。

## 新增一手证据与反证

- [W3C Web Storage](https://www.w3.org/TR/webstorage/) 把 `sessionStorage` 定义为顶层浏览上下文和来源隔离的存储；同一窗口内新文档可继续访问，浏览上下文销毁后可以丢弃。这与“刷新后恢复、另一个标签页不共享长期草稿”的目标一致。
- [OWASP HTML5 Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html) 建议在不需要跨会话持久化时优先使用 `sessionStorage`，同时明确不要在浏览器存储中放敏感信息或会话标识，XSS 可读取或污染同源存储。
- [OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) 进一步说明 Web Storage 不保证静态加密，且内容可被同源脚本读取。

反证：`sessionStorage` 不是保密存储，浏览器也可能因清理、空间或安全策略删除它；某些浏览器还会恢复上次会话。因而本实现只提供尽力恢复，不宣称可靠长期记忆；只保存可见目标文本，不保存密钥、授权、搜索词、记忆选择、任务 ID、引用或反馈；页面和 FAQ 明确要求不要填写敏感信息。

## 三轮任务优化

1. **结果轮**：把目标从“增加记忆”收敛为“意外刷新后，用户能找回尚未提交的目标文字，并明确知道它仍是草稿”。成功不等于任务创建、模型调用或现实工作完成。
2. **约束轮**：限定同一标签页、同一服务端核验工作区、同一语言、最多 1,200 字符、最多两小时。恢复只填目标；云端同意、公开搜索、关键词、周期和记忆选择全部保持安全默认。提交、丢弃、退出和切换工作区清除草稿。
3. **验收轮**：先冻结 12 个合法/非法记录，再实现纯函数和 UI。要求恢复或拒绝可逐例判断；刷新前后 D1 任务数和模型调用数不变；未经用户再次同意绝不提交。SEO/GEO 通过双语 FAQ、结构化 FAQ 和 Markdown 镜像同步；sitemap 日期更新。IndexNow 继续沿用既有周更/手动流程，不增加 push 提交。

## 候选比较

| 候选 | 调用/写入 | 可保持原文 | 风险 | 决定 |
|---|---:|---:|---|---|
| 确定性 `sessionStorage` 记录 | 0 模型、0 D1 | 是 | 同源脚本可读；浏览器可清理 | 采用，严格缩小字段与寿命 |
| 小模型重建草稿 | 至少 1 次模型 | 否 | 改写、幻觉、延迟、额度 | 不采用 |
| 当前 8B / 更强模型重建 | 至少 1 次模型 | 否 | 相同语义风险且成本更高 | 不采用 |
| 扩大长期记忆/上下文 | 未必有调用，但隐私面扩大 | 不保证 | 把更多数据当能力提升 | 不采用 |

这不是模型质量对照。对于已知文本的恢复，模型没有需要解决的推理问题。

## 可证伪实验

冻结 12 个案例：英文合法 JSON、中文合法对象、过期、未来时间、错误工作区、错误语言、额外字段、超长、双向控制字符、控制字符、畸形 JSON、错误版本。v19 对该产品流程没有恢复能力，特定基线为 0/12；v20 纯函数为 12/12。

浏览器验收定义：合成草稿带着记忆、搜索、关键词和授权选择刷新后，只恢复目标；安全选项归零；D1 任务数和旧报告模型调用数不变；显式丢弃、成功提交和退出后记录消失。浏览器测试代码已加入中英文旅程。本地环境缺少 Chromium 可执行文件，测试在启动前失败，未伪称通过；发布工作流仍须运行完整浏览器门禁。

## 两轮对抗自检

### 1. 隐私、污染与跨工作区

- 解析端把存储当不可信输入：只接受精确的 `version/scope/lang/goal/at` 字段，拒绝额外字段、畸形值、控制字符和双向文本控制符。
- 只有服务端返回并核验的 64 位工作区摘要可匹配；跨工作区或跨语言即删除，不展示。
- 不保存凭证、搜索词、授权、记忆选择、上下文回执、来源或反馈；最多两小时，并提供可见的“丢弃草稿”。
- 内容使用 textarea 的 `value` 恢复，不经过 HTML 渲染；现有 CSP/XSS 边界不变。

剩余风险：站点若发生同源 XSS，攻击脚本仍可能读取目标草稿；因此这不是敏感数据保险箱。限制字段和寿命只能降低暴露，不消除同源脚本风险。

### 2. 语义与副作用

- 恢复提示明确写“未提交草稿”，不计作任务、报告、模型成果或完成状态。
- 恢复函数没有 fetch、D1 或模型路径；只有用户再次勾选云端同意并点击开始才进入现有创建接口。
- 搜索、关键词、周期、记忆选择和同意都不恢复，避免旧授权被重放。
- 不新增 GA4 事件，不把恢复当活跃用户、留存或客户价值；真实价值仍要由自愿任务和二次使用验证。
