## 实际攻击与修正

| 攻击/失败点 | 结果或修正 |
|---|---|
| 相同交易多次通知、队列重复投递 | 付款幂等、任务租约、已接受行不重复调用；租约占用时重新投递而不是静默丢弃 |
| 仅回跳成功页、未付费、币种/金额/产品错误 | 不授予执行资格；产品价格由服务端确定，客户端传入低价不生效 |
| 伪造签名、修改 raw body、过期签名 | 签名验证拒绝 |
| 缺模型/支付/队列配置 | 后端收费路径关闭，免费检查仍可用 |
| 超预算和模型持续失败 | 调用前保留预算，每行最多两次；失败和中断的预留成本不退回 |
| 模型没有返回 usage cost | 增加未知成本尝试计数，不能把 observed_usd=0 当免费 |
| 译文丢数字、品牌、变量，添加数字或 HTML | 检查失败，不写入导入文件 |
| 长数字 ID、CSV 引号/换行、重复键 | ID 保持字符串，正确转义，重复翻译键拒绝 |
| 电子表格公式注入与 Shopify 标识损坏的冲突 | 区分原样导入 CSV 与公式转义的审阅 CSV；不为安全审阅修改正式标识 |
| 一个请求创建最多500字段 | 改成 `json_each` 批量插入，避免逐行501条创建语句 |
| 请求过大 | 按流读取并限制字节数；同源校验及按日盐化的上传限制 |
| 退款重试 | 固定幂等键，返回真实 pending/succeeded/failed 状态；退款请求后停止新调用 |
| 过期数据 | 访问拒绝，计划任务删除任务、行和限流桶 |

完整模拟链路：上传一个 CSV → 保存哈希恢复密钥 → 创建专用 Checkout → 服务端核验付款 → 排入处理队列 → 检查并保存输出 → 凭密钥读取 → 请求退款 → 重复请求不再创建第二笔退款。
